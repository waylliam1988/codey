Design Review · Based on DESIGN.md & frontend/src Audit

让 Codey 更精致、更顺手，同时守住“安静的本地 IDE”灵魂

本方案基于对当前 frontend/ 实际代码与 DESIGN.md 规范的全面梳理，针对视觉层次偏平、右侧工作区入口隐蔽且三层头冗余、过程流与审批辨识度不足、Settings 嵌套过深等 6 类高频痛点提出系统化升级。完整交互效果可随时点击右上角进入可操作原型体验。

保留 100% 品牌气质 纯暗黑单色体系 + 唯一鼠尾草绿族、英文 UI Chrome、字符涟漪空首页、零花哨徽章。
空间层次立体化 4 级深灰明度阶梯 + 半透明发丝描边，告别“灰块贴灰块”的扁平观感。
高频面板一键直达 消除右侧面板双层标题冗余，Files / Changes / Research 顶栏直达且保留改动计数。
安全与配置更清晰 Shell 审批聚焦边界、Restore 内联二次确认、Settings 双栏平铺告别套娃。

一、相对 DESIGN.md：哪些坚定保留，哪些适度突破

Alignment

坚定保留 Codey 的识别基因

  • 克制单色 + 唯一鼠尾草绿：绝不引入蓝/紫主按钮、渐变卡片、彩色状态胶囊或 Emoji。
  • De-bubbled AI 回答：AI 正文无外框直接落于画布，保障长技术内容和代码块的阅读流。
  • 字符涟漪空首页（Character Pond）：空对话页保持零营销文案，鼠标划过泛起鼠尾草绿字符波纹，发送首条消息时输入框丝滑沉底。
  • 绿色在线圆点 & 知识图谱：模型选择器的在线圆点、Research Graph 绿节点与悬浮高亮连线、波浪刻度导航（Tick Rail）全部保留并精细化。
  • 安全边界与英文 Chrome：Shell 审批、右键引用、只读事实收据（Run Details）全部沿用原语义。

适度突破 提升颜值与易用性的关键调整

  • 半透明发丝线替代死灰实线：用 rgba(255,255,255,0.085) 与微弱顶部高光替代 #2a2a2a，显著提升暗色精致度。
  • 用户消息收敛为右对齐自适应卡片：避免满宽 760px 灰条把提问和回答混成一团，一眼分清对话角色。
  • 顶栏增加 3 个静默快捷入口：把最高频的 Files / Changes / Research 放到顶栏右侧微胶囊组，不再藏在单一图标里。
  • Composer 上下文微态反馈：Choose folder 和 Research 增加细微 hover 底色与状态点，让新手一眼看出可点、是否开启。
  • Settings 改双栏平铺：拆解原版 <details> 嵌套地狱，把 Models / Connections / Appearance / Saved permissions 清晰分 tab，杜绝双 Save 按钮冲突。

三、6 大核心 UI/UX 改造详述（Before vs After）

Core Redesign
01三栏表面层次 & 对话视觉节拍
P0 · 纯 CSS 可落地
现状问题 (Before)

侧栏 #1c1c1c、主画布 #181818、卡片 #202020 亮度差距微弱，且用户消息占满整行 760px 宽度，快速滚动长对话时很难用余光定位“我上一句问了什么”。

  • 全宽灰底用户气泡在单句短提问时显得笨重空旷。
  • 多轮对话间缺少明确的视觉锚点，阅读容易疲劳。
优化方案 (After)

确立 Rail (#141416) → Canvas (#18181b) → Panel (#212125) 三级纵深；用户消息改为右对齐、自适应内容宽度（max 86%）的克制圆角卡片，带微弱发丝描边和顶部 1px 高光。

  • 操作行（Copy / Edit / Fork）保留在卡片外下方，共享连续 hover 热区，移入不闪烁。
  • AI 回复继续无气泡落于画布，长文、代码块与文件链接（柔和绿底）层次清晰。
02右侧工作区：直达入口、去冗余头与 Restore 防误触
P0 · 高频易用性提升
现状问题 (Before)

顶栏只有一个通用“侧栏开关”图标，用户不知道当前有几个改动文件，也得反复点 + 菜单找 Research / Changes / Review。同时右侧打开后出现“Tab 栏 + 抽屉头 + 子标签”三层叠罗汉，挤占代码 diff 高度。

优化方案 (After)

顶栏右侧增加安静的单色快捷组（Files / Changes 2 / Research），其余次高频面板（Review / Local context / History）留在 + 菜单和 Ctrl+K；右侧面板内部将标题与操作合并为单行 36px 紧凑子栏；点击 Snapshot Restore 展开内联二次确认条，防止误点覆盖代码。

03过程流 Timeline、Shell 审批焦点与 Steering 纠偏
P0 · 核心闭环体验
现状问题 (Before)
  • 展开后的 .process-block 工具行全部是等宽灰字，很难一眼分辨 read / edit / shell。
  • Shell 审批卡片和普通代码块外观太接近，任务暂停等批准时不够醒目；Split Button 下拉菜单层级较弱。
  • 运行中追加的消息队列（.pending-inputs）缺乏“正在纠偏当前运行”的语义提示。
优化方案 (After)
  • 结构化时间轴：摘要行增加耗时（如 Worked · read 3 · edited 2 · 14s），展开后按动词左对齐，编辑行直接带红绿 +18 −4 且点击直达右侧 Diff。
  • 聚焦式审批卡：左侧加 2px 鼠尾草绿语义边界 + 终端图标 + 深色 $ cmd 独立区，右下方明确区分 Deny 与高对比 Allow once ▾。
  • Steering 队列条：运行中在输入框上方显示带 STEERING 标识的轻量条，支持即时删除/编辑。

04Composer 上下文可发现性 & 拖拽附件体验
P1 · 新手友好度
现状问题 (Before)

输入框上方的 Choose folder · Research 只是两段无底色无图标的小号灰字，新手容易误以为是静态面包屑而非可切换按钮；同时移除了附件按钮后，用户不知道支持直接拖文件或粘贴截图。

优化方案 (After)

保留零冗余按钮的极简理念，但给 Choose folder 加上极细目录图标、给 Research 加上 6px 状态点（激活时柔和鼠尾草绿微亮）；右侧以极低存在感的 11px 提示语告知 Drop files or paste images（运行中自动切换为 Sending steers the active run），拖入时整个输入框亮起绿边反馈。

05Settings 弹窗：拆解多层嵌套，清晰分离“选模型”与“配连接”
P1 · 信息架构重构
现状问题 (Before)

当前 Settings 全部塞在单列弹窗中：Appearance、Models、Local 里的 Connection 再嵌套 Advanced（三层折叠套娃），且页面底部同时存在 Save connection 和 Save changes 两个保存按钮，用户极易点错或丢失未保存配置。

优化方案 (After)

升级为 680px 紧凑左导右内容双栏弹窗，明确拆为 4 个扁平分区：

  • Models：只管勾选日常下拉菜单里显示哪些网站/本地模型。
  • Connections：专心配置本地地址、API Key、上下文上限和 Tool calling，独立测试与保存。
  • Appearance：字体缩放实时预览。
  • Saved permissions：集中查看与撤销已记住的精确 Shell 授权规则（审批菜单仍可直达此页）。
06Research Handoff、长对话波浪刻度与键盘流闭环
P2 · 深度体验打磨
现状问题 (Before)

Research 面板里的 Use in Project 按钮与普通灰字按钮无视觉区分，用户做完研究后容易忽略核心的 Research Brief → Project Writer 交接路径；长对话中快速定位旧提问也不够直觉。

优化方案 (After)
  • 给 Use in Project 赋予克制的柔和绿底（--green-soft），成为 Research 面板唯一的高优先级出口；报告中的引用编号 [1] 可点击直接定位到右侧 Evidence/Sources。
  • 保留并微调左侧 Tick Rail 波浪刻度条，悬浮展开柔和波浪 + 延迟显示 Q&A 摘要卡片，点击平滑跳转。
  • 保留右键选中文本 Quote in reply（直接引用为 Markdown 进入输入框）与 Ctrl+K 命令面板。
