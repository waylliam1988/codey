Codey — 顶栏菜单与操作入口整合方案

分析右上角 ⋯ 菜单、侧栏操作按钮、Workspace chooser、命令面板 (Ctrl+K) 四个操作面之间的重复和分散问题，提出整合方案。

发现的问题：
1. ⋯ 菜单中 "Commands" 是多余的 — 点击 ⋯ 再点 Commands 打开命令面板，但用户可以直接 Ctrl+K。这个菜单项的唯一目的是暴露 Ctrl+K 的存在，但放在 ⋯ 里太深了。

5. "Local context" 只能从 ⋯ 菜单进入 — 作为重要功能，入口太深，需要两次点击。

3. 整合方案 — 设计原则

核心思路：每个操作最多有 2 个入口：一个主入口（最自然的位置）和命令面板作为万能备用入口。消除三处或更多的重复。

操作归属重组：
高频会话操作： 顶栏直出图标 ← Search conversation、Local context
低频/危险操作： 顶栏 ⋯ 菜单 ← Clear messages、Manage permissions
Workspace 面板： 顶栏 Workspace 按钮 ← 保留不变，合并到 ⋯ 菜单中也可选
被移除的项： ⋯ → Commands 用户知道 Ctrl+K 后不需要菜单入口
命令面板角色： 万能备用入口 ← 所有操作都可通过此到达，但不是主入口
变更汇总：
1. 把 "Search this conversation" 和 "Local context" 从 ⋯ 菜单提升为顶栏独立图标按钮 — 一次点击即达
2. 从 ⋯ 菜单中移除 "Commands" — 在 Ctrl+K 快捷键提示中展示，不占菜单位置
3. ⋯ 菜单只保留低频/危险操作（Clear messages、Manage permissions），并可选加入 Workspace 面板列表作为分组
4. 命令面板增加图标和快捷键提示，作为统一的 power-user 入口
5. 侧栏不变 — 侧栏的 New chat / Add project / Search / Settings 是全局导航，不与会话级操作重复

4. 新顶栏设计

核心改动：将 "Search this conversation" 和 "Local context" 提升为顶栏独立图标按钮。 顶栏右侧按钮顺序：状态指示 → 搜索 → Local context → Workspace → ⋯ 菜单。

Before — 当前顶栏

2 个按钮。"Search conversation" 和 "Local context" 藏在 ⋯ 菜单中（需 2 次点击）。
After — 改进顶栏
Research: scaling laws survey
5 个按钮。搜索和 Local context 一次点击即达。分隔线区分会话操作和面板操作。
设计说明：
• 状态 dot 保持最左侧（靠近标题），视觉上是标题的附属
• 搜索图标 (🔍) 和 Local context 图标 (👤) 紧随其后，作为会话级常用操作
• topbar-sep (1px 分隔线) 将会话操作和面板操作在视觉上分组
• Workspace 按钮在分隔线右侧，表示它打开的是独立面板而非修改当前会话
• ⋯ 菜单在最右侧，只承载低频操作
• 在侧栏隐藏状态下，hamburger 按钮出现在标题左侧（行为不变）

5. 精简后的 ⋯ 菜单

⋯ 菜单只保留无法或不适合放在顶栏图标的操作，按类型分组。 移除 "Commands"（由 Ctrl+K 提示替代）。移除 "Search this conversation" 和 "Local context"（已提升为图标）。

4 项，其中 Commands 自引用，Search 和 Local context 是常用操作藏得太深。
After — 精简 ⋯ 菜单

分为 Workspace 和 Session 两组。带图标、按类型分隔。
设计说明：
"Commands" 被移除 — 它的作用（暴露 Ctrl+K 的存在）可以通过在 ⋯ 菜单底部加一行提示文字完成（见下方命令面板部分），不需要占一个菜单项。

"Search this conversation" 被移除 — 已在顶栏有搜索图标 (🔍)，不需要在菜单重复。

"Local context" 被移除 — 已在顶栏有图标 (👤)，不需要在菜单重复。

新增 Workspace 分组 — 将 Workspace chooser 下拉菜单合并进来。用户点 ⋯ 可以看到所有面板选项。原有的 Workspace 顶栏图标按钮仍然保留，它只打开/关闭面板而不选择具体项。如果觉得 ⋯ 菜单太长，Workspace 分组也可以不合并进来——这取决于你们觉得 Workspace 按钮的下拉本身够不够用。

新增 "Rename chat" — 目前重命名只能从侧栏右键菜单，但用户在聊天中想重命名时不应该需要去侧栏操作。

"Manage permissions" 合并进来 — 原来只在命令面板，现在在 ⋯ 菜单也可到达。

分组用 label 标识 — "Workspace" / "Session" 两个小标签，10px 灰色大写字母，低调但清晰。

7. 侧栏 — 保持不变

侧栏的 New chat / Add project / Search / Settings 四个操作属于全局导航，它们操作的对象（聊天列表、项目、全局设置）与顶栏的会话级操作不重叠。 因此侧栏操作不需要精简。

操作 归属 理由
New chat 侧栏（主）+ 命令面板 全局操作，自然放在导航区
Add project 仅侧栏 低频全局操作
Search chats 仅侧栏 搜索跨会话，属于全局
Settings 侧栏（主）+ 命令面板 全局设置，自然放在底部
唯一需要注意的：
• 命令面板中保留 "New chat" 和 "Settings" 作为备用入口是合理的 — 侧栏可能被隐藏
• 不建议在 ⋯ 菜单或其他位置再重复这些 — 侧栏隐藏时用 Ctrl+K 或 Ctrl+N 足够

总结——整合带来的改善：

减少点击：Search conversation 和 Local context 从 2 次点击（⋯ → 选项）降为 1 次（顶栏图标）

消除困惑："Commands" 菜单项不再自引用；用户不会疑惑 "Commands 是什么"

减少重复：Search conversation 从 3 处减为 2 处；Workspace panels 通过合并 chooser 和 ⋯ 菜单统一入口

分层清晰：
  • 侧栏 = 全局导航（跨会话操作）
  • 顶栏图标 = 高频会话操作（一次点击）
  • ⋯ 菜单 = 低频/危险/枚举型操作（需要浏览选项）
  • 命令面板 = Power user 万能入口（键盘驱动）
