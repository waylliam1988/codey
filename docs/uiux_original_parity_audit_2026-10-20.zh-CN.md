# Codey 原版交互保留核对 · 2026-10-20

本文保留实施前核对结果；后续真实产品改造、回归证据与剩余能力边界见[实施记录](uiux_implementation_2026-10-20.zh-CN.md)，不以本文的历史测试数量代表当前验收范围。

本次结论：Research 关系图的拖节点、拖画布、滚轮缩放、点击详情和双击打开资料，在早期 JS、迁移前最后一版 JS、当前 TS 中都存在，浏览器检查也通过。没有发现这组手势在 JS → TS 迁移中丢失。

此前交互对照稿仍有不少未覆盖的原版功能，不能把它当成完整的替换实现。本清单把这些功能列为后续 UI/UX 改造的保留要求，并区分原版已有、对照稿遗漏和新增功能待接入。项目/会话导航侧栏及 Settings 的现有布局、入口与内容继续保持原样。

**颜色按用户确认的目标保留。** 早期和当前真实源码的静止节点主要是灰/白，悬停才使用绿色；用户明确要求静止节点也为原绿色 `#78a58b`，对照稿已这样处理。不得以“恢复原版”为理由把这个已确认目标改回去。默认连线仍为灰色，悬停关联边绿色。

原版没有提供“永久固定节点 / 保存手动布局”、完整的 Canvas 键盘漫游或双指捏合操作。它们可以另行完善，但不能误写成迁移丢失。当前 pointercancel 复用释放处理；取消拖动、失焦、多指输入与触屏应在真实产品验收时补覆盖，不能由鼠标夹具测试推定全部通过。

### 用户手感反馈后追加：拖动期间的布局休眠问题

初次检查确认了“节点能跟随鼠标”和“松手不误选”，但没有覆盖“图已经静止后，按住拖动时其他节点是否持续联动”。用户反馈后补测，确认早期/当前共用逻辑存在这个问题：布局静止后停止动画，拖动节点只修改坐标与重绘，直到松手才调用 wake。因此原版有 `0.86` 速度衰减，也可能表现为拖动时只拉长连线、松手后其他节点才突然运动。不能因为旧新代码一致，就认为手感已正确。

本轮已在**交互稿适配器**修复：按下节点及移动时唤醒布局，按住节点期间不进入静止休眠；抓取节点时清零旧速度。弹簧、排斥、原有速度衰减和视角保持原实现，空白拖动仍是画布平移。拖动时力会沿连线传播，松手后平滑收敛，并在稳定后停止动画。没有把所有节点改为僵硬的整体平移。

真实前端 `frontend/src/research_graph.ts` 与保留的参考快照本轮未改；后续产品落地必须同步这一已确认的修正，并运行相同的静止后拖动检查。

- [修复前记录](../artifacts/uiux-preview/2026-10-20/audit/graph-motion-before.json)：拖动期间其他 6 个节点位移全部为 0，持续联动检查失败。
- [修复后记录](../artifacts/uiux-preview/2026-10-20/audit/graph-motion-audit.json)：8 个检查通过，覆盖按住时联动、长按后继续拖、鼠标位置一致、释放后衰减、稳定后休眠及不误选。
- 复查脚本：`artifacts/uiux-preview/2026-10-20/audit_graph_motion.py`。`--baseline` 仅用于保存修复前观测；普通模式对修复要求做断言。

## 补充复核：项目箭头、键盘、焦点与隐藏状态

本轮继续核对迁移前 JS 的 `provider_ui.js`、`settings.js` 及当前源码，并补查之前未执行的审批、问题草稿、图片、富文本、历史请求、保存和 SSE 测试。重点是状态变化，不把“按钮可见”当作完整行为。

### 已直接修正到对照稿

| 遗漏 | 原版依据 / 本轮修正 |
|---|---|
| 项目箭头一直朝下 | 当前原版根据展开状态设置方向；对照稿改为折叠朝右、展开朝下，复用 Worked 摘要的同一个 chevron 和 0.15s 旋转动画，支持减少动画偏好 |
| 搜索与箭头状态分离 | 搜索临时展开匹配项目时同步箭头；清空或 Escape 退出后恢复搜索前的折叠状态 |
| 模型菜单没有键盘导航 | 旧 JS 和当前 TS 都有方向键、Home/End、选中项焦点；对照稿已补回，Escape 关闭并返回触发按钮 |
| 推理强度点击直接轮换 | 旧 JS 和当前 TS 都是可选菜单；对照稿恢复 Low/Medium/High 菜单，打开不改变值，选择后才更新 |
| 菜单失焦或再次点击不关闭 | 对照稿补回失焦关闭、同一按钮再次点击关闭，保持触发按钮的 aria-expanded 状态 |
| 从菜单进入窗口后焦点丢失 | 保留最外层仍可见的入口；例如 More → Commands → Settings → 关闭，回到 More，而不是隐藏或已删除的菜单项 |
| Settings 快捷键不切换关闭 | 旧 JS 与当前 `settings.ts` 的 Ctrl/Cmd+, 是开/关切换；对照稿已恢复 |
| Settings 打开时 Ctrl+N 改动背后的会话 | 按原版阻止背景 New chat；Settings 内容和分组不变 |
| 图拖动取消可能误选或卡住 | 对照稿将正常释放与 pointercancel 分开，补 lostpointercapture 和窗口失焦清理，释放临时固定，随后仍能再次拖动 |
| 非主指针或右键干扰图拖动 | 对照稿仅接受主按钮开始拖动，按 pointerId 区分操作；其他指针不能接管或取消当前拖动 |

这里的项目箭头修正不改变侧栏布局、项目内容和菜单。原版项目行还有独立的箭头、项目名、More 和 New chat 命中区域；对照稿的一行样例不能替代真实侧栏实现，正式产品仍直接保留现有侧栏。

## 空白首页与导航预览补充

按用户最新确认，交互稿默认首页与重置现在都是空白新会话：移除 What are we building、说明、终端装饰和两个建议按钮。输入框保留原外观，位于中间偏下；第一次真实发送后，同一个输入框以 360ms 下移至底部，保留焦点。开启减少动态效果时直接到位，新建会话恢复空白。

## 已确认的设计约束

- 项目/会话导航侧栏整体保持目前 Codey 原样，包括菜单、Settings、尺寸与操作。不新增 Compare editor layouts、底部 Add project、品牌栏或伪造项目历史。
- 项目文件夹行按用户补充要求与侧栏背景一致，选中、点击展开及悬停均不增加整行底色；当前对话仍保留原选中底色。箭头方向与动画独立于背景状态。
- Settings 的内容和分组保持原样；可以修复真实错误，不能借重构更换内容。
- 输入框继续原风格、模型旁原绿色点、原发送图标；没有附件加号，图片粘贴、文件拖拽。输入框上方显示所选项目名，未选项目显示 Choose folder。
- 所有 input/textarea/select 不添加额外高亮框、外圈或光晕；键盘按钮焦点仍需可辨认。
- 消息操作位于气泡外下方，悬停所属消息才显示，离开自动隐藏；键盘与触屏仍可访问。复制反馈短时保留是反馈状态，不是永久工具条。
- 编辑消息与重命名均原位进行。历史上下文派生是独立能力，不能把新建分支弹窗强塞到普通编辑入口。
- 绿色对话导航与 Research 点线图均保留；图节点按用户要求静止也为绿色。

## 本轮直接修复的对照稿问题

1. 回答 Copy 原先复制预设短摘要，现读取完整可见回答正文，排除操作按钮与验证摘要等界面附属内容。
2. 复制增加 pending 防重复、成功图标、失败提示与重试；鼠标移开后成功反馈保留 1.2 秒，失败反馈保留 4 秒。
3. 使用反馈 token 防止较早的超时任务提前清掉较新的重试状态。
4. Clipboard API 不可用时的回退复制保留原草稿、光标与选区，避免恢复窗口选区时覆盖输入框选区。

这些修复只作用于交互对照稿；原产品的复制模块已有更完整的答案读取与反馈机制，应继续沿用。文件标签、Local context、完整研究数据等没有在本轮伪装成已实现。
