# Codey 整体 UI/UX 补全与参考复现规格

日期：2026-10-20。状态：代码盘点与实施规格，尚未实施界面改造。

## 目标与依据

用户希望一次覆盖整体 UI/UX，包括工具展示、对话分支、插话、排队消息、左右侧栏，以及已有后端但尚未接入的能力。外观与交互尽可能贴近 deepseek-harness 和指定版本的 Codex；业务状态、执行、权限、历史与恢复仍由 Codey 实现。

本次结论来自当前工作区源文件、路由与前端调用对照，以及参考项目源码。没有启动三套界面进行逐屏视觉验收。工作区已有其他后端修改；本文件不把这些修改视为本次工作成果。旧路线图和历史测试数字不作为当前实现存在的证明。

## 参考如何统一

deepseek-harness 是主要交互参考，重点复现过程分组、工具详情、插话与队列、右栏标签和会话状态隔离。Codex 用于对照阅读排版、输入框、导航、审阅与面板操作的视觉细节。

用户明确保留的区域优先于参考项目：放置 Settings 的项目/会话导航侧栏、Settings 内容和输入框原风格维持 Codey 原版。导航顶部不加 Codey / Local workspace 品牌标题；New chat / Add project / Search 保持原有顶部顺序，底部只有 Settings，不另加 Add project 或 Commands。新增交互在对话与工作区内承载。

再次确认：整个项目/会话导航侧栏均不属于改造范围，布局、图标、条目与交互以当前 Codey 为准，不能只保留底部后继续调整其他区域。项目和会话来自真实状态，不自动加入比较布局、设计笔记等示例条目。独立对照稿已去除额外示例项目和历史会话，仅保留当前演示会话以定位中栏。

实施前给每个组件确定一个主参考，保存对应版本、视口、参考截图、交互状态和验收截图。不能在同一个组件中随意拼接两套间距、图标与键盘规则。所谓“尽可能照抄”需要可比较的画面与行为，不以大致相似替代验收。

先复现用户可见行为，再映射 Codey 状态；不直接移植 Cordis、React 插件层或编译后的 Codex 模块。不为界面相似而重写已工作的持久化与执行链路。若将来确需更换前端框架，应单独给出迁移依据与可回退切换方案。

## A. 已确认的接口与交互缺口

| 编号 | 当前证据 | 交付要求 |
|---|---|---|
| A01 对话分支 | 持久层已有 branch/fork；当前 history_page 返回当前上下文路径；前端没有完整分支导航 | 分支元数据读取、浏览其他分支、切换当前路径、消息级分支入口、祖先路径展示；保留原分支 |
| A02 编辑历史消息 | composer.editMessage 已支持原位编辑后普通发送，没有携带原消息位置 | 按用户确认保留原位编辑、Cancel / Send、Escape 取消和 Ctrl/Cmd+Enter 发送，不弹窗、不要求分支名；若另做“从此处派生”，须独立补原消息位置与上下文契约，保留原消息和旧回答 |
| A03 插话 | 持久层已有 steer/follow_up；输入 HTTP 白名单不传 input_mode，QueuedRequest 也未声明它 | 贯通输入模式、接收回执和消费状态；区分“引导当前任务”与“排队下一轮”；在真实执行边界消费 |
| A04 历史工作流 | 已有 GET /api/workflows、POST /api/workflows/fork；未找到产品前端调用 | 提供历史节点查看与从节点继续的入口；处理不允许分叉的节点；将新会话纳入侧栏和历史 |
| A05 结构化审阅 | 已有 GET /api/run_review，返回保存的 findings、scope、summary；前端未调用 | 展示已记录的审阅结果、范围、定位与空状态；该 GET 读取不等于触发新的 review |
| A06 会话搜索 | 后端返回 entry_id、ordinal、excerpt；界面只展示匹配条数 | 可读结果列表、摘要高亮、上一条/下一条、跳到历史原文、退出后恢复阅读位置；必要时补目标消息附近读取接口 |
| A07 工具调用树 | CodeMode 内核有父子执行身份；常规展示事件主要使用 turn 与 tool_index | 在实时与历史中提供稳定 callId/parentCallId 关系；去重、乱序合并、错误归属和深度限制；不能靠 DOM 缩进猜关系 |
| A08 统一右栏 | DocumentPane 有会话独立内存标签，Changes/Research/Local context 各用抽屉 | 文件、改动、研究证据、审阅采用同一面板容器与导航；Local context 仍由更多菜单按需进入 |
| A09 布局恢复 | DocumentPane 的标签保存在内存 Map；调整宽度写 CSS 属性 | 逐会话保存标签身份、选择、宽度和阅读位置；刷新恢复；损坏与保存失败有明确退路；不保存活动连接 |
| A10 长输出访问 | 工具事件可携带 output_handle、字节数和摘要；现有执行输出接口支持运行输出快照 | 统一长输出提示、保留范围与复制语义；如开放下载，补作用域受控接口；不能把句柄当任意路径 |

“分树”分成三个不同对象：历史回答分支、工具父子调用、子代理任务谱系。它们可以共享树控件，但必须分别建模，不能用 fork 冒充子代理，也不能用执行步骤冒充历史分支。

对话与工作流 fork 不会自动回滚文件系统。界面必须分别说明继承的会话位置与当前工作区状态；需要文件隔离或快照恢复时使用真实后端能力。

## C. 需要新增能力或进一步核实的参考功能

在当前 Codey HTTP 路由中没有发现下列能力的完整用户操作契约。它们可以纳入目标，但不能标为“后端已经有，只补按钮”。实施前核实内部模块及权限、持久化和可用性。

| 功能 | 应补齐的能力边界 |
|---|---|
| 交互式终端 | 创建/输入/调整大小/停止/重连/退出、会话与进程归属；现有命令输出快照不等于 PTY 终端 |
| 项目文件树与文件编辑 | 目录分页/懒加载、读取范围、监听、路径校验；若提供编辑，补版本冲突、保存与撤销语义 |
| 文件/图片附件与 @ 引用 | 上传、存储、删除、预算、模型能力判断、引用解析；“图片能预览”不等于“图片能发给模型” |
| 内嵌网页与应用预览 | 预览宿主、允许的地址与导航、失败回退、生命周期；模型网页连接不等于工作区浏览器 |
| 子代理谱系与控制 | 真实父子任务目录、历史、独立状态、续接和停止路由；owner_task_id 字段不等于完整子代理产品 |
| 计划与待办审批 | 持久计划、更新与审批状态、执行入口；不能从模型普通 Markdown 推断出已批准计划 |
| 任意分栏与浮窗 | 面板布局约束、键盘操作、恢复与焦点；浏览器内浮层与真正系统窗口分开定义 |
| 调度、插件、远程连接、账户管理 | 逐项另立业务契约；参考项目有入口不证明 Codey 已具备服务能力 |
| token/成本/上下文仪表 | 只有可靠数据时展示；网页模型未知用量不可凭输出长度估算成真实账单或上下文占用 |
| 对话导出与共享 | 当前分支/全树范围、附件与输出保留规则、导出格式；现有 Ghost 导出不等于对话导出，公开共享另需服务能力 |

已有内部审计、能力注册、凭据和调度字段不必全部变成常驻控件。用户任务所需功能有自然入口；诊断信息按需展开，保持产品安静。

## D. 先统一状态，再实现画面

1. 会话与分支：conversationId、entryId、parentEntryId、branch/head 身份及当前查看路径；区分浏览路径与改变后续执行路径。
2. 用户输入：requestId、submissionId、mode、revision、提交/排队/接收/消费/取消状态；保持幂等与草稿归属。
3. 执行与工具：runId、turnId、callId、parentCallId、executionId、阶段及权威结算；子调用与输出身份不可因折叠或刷新改变。
4. 内容与面板：统一 openDocument/openChanges/openReview/openEvidence 等用户动作；面板状态属于会话，内容读取与授权仍由后端负责。
5. 事件与历史：实时展示与冷历史从相同事实还原；前端只保存视图状态与本地待确认身份，不建立第二套会话真相。
6. 可用动作：前端明确区分后端已支持、当前不可用、等待状态和未知状态；不能以按钮外观承诺未实现的执行能力。

这些批次属于一次完整改造范围，批次之间分别保持应用可用，不以第一批画面完成宣称整体完成。

|---|---|---|

| 1 框架与会话 | 三栏、统一视觉与基础控件、工具/过程展示、输入框、右栏容器 | 常规任务的实时与历史展示一致；核心发送与审批闭环保持可用 |
| 2 已有能力接通 | 插话、队列、分支、编辑/重新生成、历史节点继续、搜索跳转、结构化审阅 | 对应真实后端调用、持久状态与跨刷新恢复均通过 |
| 3 工作区闭环 | 文件/diff/Research/审阅联动、布局持久化、模型连接与设置、快捷键与导航 | 从聊天结果到证据、文件、差异、恢复均有完整路径 |

| 5 总体验收 | 异常、恢复、长会话、键盘、窄窗口和视觉对照 | 满足下列完成标准，并更新设计文档与功能说明 |

## F. 完成标准

- 覆盖新会话、项目任务、Research、工具成功/失败/取消、等待问题、等待审批、插话、排队、分支、历史编辑、审阅、搜索和恢复的真实路径。
- 插话后，正在进行的任务在已定义边界读到新指令；排队消息不提前混入当前指令。界面显示的消费状态与持久事实一致。
- 新建分支不改变旧回答；历史节点继续具有明确上下文范围；切分支不假装恢复文件；刷新后能访问同一分支。
- 同时运行多个会话时，草稿、Stop、问题、审批、输出、审阅、右栏标签及错误均指向正确会话。
- 在发送前后、工具执行中、问题与审批等待、队列等待、停止中和完成后刷新；断开 SSE 后恢复；均不丢失已确认输入、不重复执行副作用、不显示假完成。
- 搜索结果可以打开并定位到实际消息，包含尚未加载的历史；长会话加载和定位不要求一次挂载全部 DOM。
- 改动后能查看逐文件事实、验证和审阅；restore 只针对后端确实支持的范围；过期或不存在的恢复目标明确报出。
- 空态、加载、错误、无权限、能力不支持、保存失败均可理解，并有适用的下一步。
- 1280×800、1440×900、1920×1080 和窄窗口进行关键画面对照；另外检查 125%/150% 缩放、长中英文、输入法及键盘导航。视口是验收建议，不是本次已经测试的结果。
- 验证前端类型、格式与构建；运行受影响的前后端测试；使用真实 Codey HTTP 和浏览器做工作流回归，不能仅注入模拟事件验证外观。
- 确定性模型服务可用于自动化验收，但网页模型插话、原生工具与各连接能力应单独记录真实联调范围，不把模拟结果写成全模型可用。
- 交付实现、截图、已完成矩阵与剩余限制；C 表的新能力若未交付，必须明确标为未完成或另期，不能笼统写“全部 UI/UX 已补齐”。

### “读取文件后只看到第一行”的已确认原因

工具执行产生的 run_event_ui_payload 已包含有界多行 detail、detail_truncated 和 preview。前端也优先读取 detail。但 server._sse 在实时与事件重放出口调用 machine_event_payload，该精简机器投影只保留 result 摘要，丢掉正文、展示 kind 和结构化 preview。未显式设置摘要的工具，result 可以仅为首行。

本轮新增 browser_event_payload，由 SSE 两个出口使用；它保留有界正文、读取范围和 diff，验证数字与字段并显示截断事实，机器日志仍使用原精简投影。回归覆盖实际 SSE handler 的实时和重放路径，并加强真实模型测试服务 → 工具读取 → HTTP/SSE → 浏览器展开的多行断言。

这解释的是 read 工具展开内容丢失。独立 DocumentPane 经 /api/documents/read 读取文本，当前返回最多 2 MiB 的完整内容或明确失败，没有在这里找到“固定只返回第一行”的代码。不能把两条链路混为一谈，也不能恢复旧记录中从未保留的正文。

### 文件与工具展示的细节验收清单

以下除已注明修复项外均为待实现或待浏览器验证，不代表都已确认故障：

1. 区分工具实际读到的历史片段与当前磁盘文件。展开工具查看当时结果；Open file 查看当前文件，二者不能悄悄替换。
2. 读取行号范围、实际保留长度、截断和下一页含义可见；不把一行摘要或有界页面叫“完整文件”。
3. 文件链接定位到真实行，保留前后文；处理空文件、越界行号、CRLF、多字节字符与无结尾换行。现有越界定位可能构造空高亮行，需要明确定义回退。
4. 行号引用应使用源码坐标；JSON 格式化与 Markdown 预览不能改变定位语义。明确切换预览/源码后的阅读位置。
5. 打开同一文件另一行时跳转；仅切回原标签或刷新文件时保留阅读位置。异步旧请求不能覆盖新文件。
6. 代码视图补行号、语法高亮、查找、跳转行、换行开关；超长行允许横向浏览，复制保留原始空白。
7. 工具只读片段可滚动、可复制；Open file、Copy result、Copy document 和 Copy diff 的范围清楚。
8. 文件已变化时显示版本关系或重新加载入口；历史读取不得假装仍是当前文件。
9. 多个同名文件有可选择的消歧路径；路径完整信息可访问，长文件名不挤掉关闭与面板操作。
10. 当前文本接口拒绝超大文件、二进制与非 UTF-8。为这些情况提供清楚文案与支持的下一步；分页读取和新增解码需要后端契约。
11. Markdown 内图片可展示，不代表图片作为独立标签也已接入专用查看器；统一图片标签、缩放、实际大小和失败重载需要单独补齐。
12. PDF/Office/表格预览须有真实渲染能力与空/错态，不能当纯文本或只显示一个文件图标就算支持。
13. 文档标签补 tab/tabpanel 关联、方向键、关闭后的焦点和选中标签滚入视区；关闭背景标签不意外切换当前文档。
14. 右栏缩放处理 pointercancel、窗口失焦、最小空间、键盘边界与 aria 数值；窄屏不暴露不可用的桌面拖拽行为。
15. 页面、文档、代码块、工具结果和命令输出的滚动各有归属；查找、定位、晚加载和展开不强制抢走用户阅读位置。
16. Copy 的成功/失败/重试、菜单键盘操作、禁用原因、保存失败、过期审批与链接失败均使用统一行为。
