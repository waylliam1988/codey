# 任务授权、无 ID 表格与结构化编辑恢复

基线为 `915d1172` 的结构化入口。两臂在同一任务、夹具、模型和真实 Chromium 上运行。A 从旧夹具的期望字段构造 schema，使用真实 DOM ID，采集后保持编辑阶段。B 实验实现以下三个变化：

1. 从任务里一行明确的授权声明读取 URL、文件、字段及类型。生产写入仍经过现有版本工具。候选接口未接收验收期望值，模型也不能传入转换类型。缺授权或授权多义时拒绝建立写入任务。
2. 固定采集由运行时选择页面中实际存在的单一受支持格式，给表格生成此次观察内有效的引用，返回标题、列名与最多三行预览。只有一个可用来源时由运行时绑定，有多个时开放真实候选。重复键仍拒绝；行列选择错误时，文件读取之前返回实际列名或行键。
3. 文件版本冲突继续开放编辑，固定程序重读文件并保留网页回执。浏览器文档变更且绑定被拒绝时重新开放观察，下一次编辑必须使用新文档回执。行列失败留在编辑阶段并提供真实候选。

无 ID 表格有两个标题、同一业务键和不同金额。JSON 夹具有相似字段和保留前导零的值。两组常规场景在第一次完整文件读取后注入真实外部修改，验收必须触发一次真实版本冲突。过期场景在第一次编辑验证前用真实 Chromium 重载同一 URL，验收旧回执拒绝后重新观察和写入。此处首次文件读取已注入外部修改，旧来源在写入前被拒绝，重读后允许无版本冲突完成。该场景单独计数。

## 回归与生产范围

定向用例验证了单表自动绑定、多表选择、行键及列名错误后的候选反馈、冲突后再遇到选择错误时反馈最近的问题、重复键及混合格式拒绝、任务范围和类型约束，以及同 URL 重载后的恢复。首轮注入暴露出行列失败时先读文件会提前触发外部修改，候选将可判定的选择错误提前到文件读取之前。

39 项 pytest 通过，退出时有 RAM disk 清理告警。Ruff、限定范围的 strict mypy 和 `git diff --check` 通过。

结果支持实现一条面向「明确目标字段的原值复制」的生产默认路径。当前实验从一行明确的授权声明构造范围，正常任务入口如何生成可信的授权字段与类型仍需验证。恢复信号在实验日志和 provider 接线中传递，生产需要用正式运行时状态承接。当前只验证整文档重载，未覆盖同文档动态换数据的过期语义。对重复业务键，验证的是拒绝歧义的提案；生产还应确保后续恢复不会改用任务未指定的业务键。
