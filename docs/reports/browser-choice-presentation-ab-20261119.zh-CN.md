# 浏览器现有操作选择展示 A/B（2026-11-19）

结论：**有局部帮助，尚未证明稳定收益，不据此修改生产代码。**
主分析 A 完成 5/16，B 完成 6/16；B 开始使用结构化目标，但仍大量自行编程。
最初关注的提前退出循环错误在两轮中都没有恢复，文件交付也没有成功。

## 范围

本轮只增加实验脚本、测试和记录，不修改 `codey/` 生产代码，也不创建 worktree。
测试的问题是：把已有合法操作清楚地展示给模型，能否减少自行编写查找循环、
保存控件编号和手工传递文件凭据的错误。

A 使用当前生产请求。B 在原请求末尾追加当前观察下的操作卡片，复用
`browser_task_handoff.handoff_call()` 和正式冻结的 `browser_references`。
模型仍然负责选择控件、填写值、决定下一步和回答；执行器、工具合同、权限、
回执以及生产完成判断保持相同。卡片列出当前选择，包括无关控件，不包含夹具答案。

这测试的是**现有机制的展示是否有收益**。它不是新的结构化接口实验，
也不能证明任意公网网站上的可靠性。所有任务限定 CodeMode，包含六个自然任务和两个
固定错误前缀后的恢复任务；恢复任务单列，不能混入首次自主成功率。

## 场景与判定

| 场景 | 要验证的差异 |

## 评分修正记录

首轮评分只识别 `[p…]` 正文片段引用，没有识别生产允许并渲染的 `[sN]` 来源引用，
也没有覆盖操作回执或快照已经展示结果正文的情况。这是实验评分缺口，
不是模型错误或生产错误。原始运行及评分全部保留；后续修正仅重评已有证据，
不重跑模型、不覆盖首次结果，并分别记录正式片段阅读与页面正文观察。

首轮 `slow`、`file_copy` 的中文表单初始正文少于生产采集器要求的 24 个字符，
`open_url` 按既有规则拒绝来源并释放页面。实验被动观察器只检查会话存在，
却继续读取已释放的页面，进一步触发 `controller_failure`。这 8 次都没有模型生成，
归为实验入口缺陷，不能记作模型能力失败。修正仅涉及测试：补充无答案的普通页面说明，
用 `BrowserSearchProvider.fetch()` 检查夹具初始采集，观察器在没有保留页面时返回空计数。
对应两个场景按相同 seed、顺序和请求展示方式另跑 8 次，位于 `entry-corrected/`。
主分析使用首轮其余 24 次和这 8 次修正后运行，首轮全部 32 次仍单独保留。

`live-first/audited-summary.json`、每项 `ab-audit.json` 保存旧运行的离线重评；
原 `summary.json`、`ab-summary.json` 均未覆盖。`aggregate.json` 保存最终合并与配对统计。
首轮冻结脚本与修正后的冻结脚本分别保存在各自证据目录。

首轮 `r1-duplicate-A` 与修正后 `r1-file_copy-B` 发生 90 秒生成超时。
客户端超时后本地模型仍在生成，已保留后台部分输出并中止本次遗留生成后续跑。
前者反复生成相近代码注释，后者反复生成 Unicode 正则片段；
它们没有得到可执行的完整回复。不能简单归为网站/浏览器环境错误，也不能断言若无限等待会成功。

### 原始回执说明的原因

1. **提前退出循环没有被展示提示救回。** A/B 两轮都在固定两次错误前缀之后，
   又真实生成三次同类错误循环。B 实际请求已经含有合法输入框、按钮的结构化选择，
   但模型没有采用。不是工具没开放，也不是卡片没送到。
2. **部分成功恢复没有重复交付。** `partial` 四次都沿已有填写回执续跑，
   后续实际只点击一次；页面总计均为填写一次、点击一次。A/B 都能做到，未证明 B 在此改善。
3. **翻页的局部收益有实际动作支持。** 第一轮 A 没点击下一页便回答未知；
   B 先把按钮名称当成编号，被拒绝后改用结构化目标，完成两次实际点击并读到记录。
   第二轮两组都成功，B 生成 3 次，A 生成 5 次。
4. **初始正文足够时，B 避免了一个提取错误。** 第二轮 A 自行写正则，
   把 `REC_2_6_Q7` 截成 `REC_2_6_Q`；B 根据已读正文直接回答正确。
5. **操作恢复与答案正确是两件事。** 第一轮 slow 的 B 已填写一次，
   失效按钮点击被拒绝且没有交付；重新观察后实际点击一次并看到目标正文。
   模型却在控件数组里找正文，把提取失败写成“未找到”，因此仍判失败。
   第二轮 A 能恢复并完成，B 只填写后重复错误请求，未完成点击。
6. **文件交付没有验证出新收益。** 四项都没有查出有效业务字段，未进入合法的固定字段复制阶段。
   其中模型尝试从“尚未加载记录”猜值、提交不合规编辑，或重复读取而没有查询。
   原有校验拒绝错误操作。不能说是固定复制机制失败，也不能靠自动补凭据变成正确交付。

逐项定位在各目录的 `provider.jsonl`、`presentation.jsonl`、`actions.json` 和 `receipts.json`。
未发现需要在本轮修改生产执行器的确定性错误；这不等于证明生产链所有情形都没有问题。

### 采用与成本

真实生成的程序 A 为 41 个，B 为 43 个。按字面结构检查，A 有 0 个、B 有 9 个程序
使用结构化目标；包含 `for`/`find` 类查找结构的程序分别为 24、23 个。
**没有程序原样采用展示中的固定单步 wrapper。** 这些是可复核的语法计数，
不是完整程序语义分类；说明 B 有一定选择方式变化，但没有消除自行编程负担。

两项超时没有完整用量回执，因此不报告全部 32 次的完整 token 总量。
对用量齐全的配对同时列出两个口径：

| 成本口径 | A 输入 / 输出 token | B 输入 / 输出 token | A/B 生成次数 |
| --- | ---: | ---: | ---: |
| 14 对均有完整用量（包含失败） | 360579 / 10994 | 447462 / 7984 | 42 / 48 |
| 4 对双方均成功 | 93418 / 1346 | 75916 / 980 | 11 / 8 |

全部完整配对中，B 输入增加 **24.1%**；双方成功的子集中，B 输入减少 **18.7%**。
不能只拿成功子集宣称普遍节省，也不能把失败提前停止当作成本优化。
墙钟时间保存在原记录；共享本地服务、首次部分并行回归、运行顺序与超时清理均会影响它，
不把该时间当作独立性能基准。

## 剩余边界与下一步

本实验只证明把已有快捷入口摆得更明显，有时能帮忙，整体仍不稳定。
B 仍允许自由 JS，还需要模型自己组织外层参数；并未测试真正限制为“选择目标、填写值”的输出合同。
因此既不能据此否定“程序做机械操作”，也不足以直接修改生产合同。

如果继续，下一项应仍是单独的测试实验：验证复用现有绑定/交接机制、
让单步浏览器动作只收目标和值，是否能减少程序错误；保持实际执行器与事实校验相同。
这需要独立比较，不能把本轮结果归因给尚未实施的接口。

本轮未覆盖登录、验证码、任意公网、恶意网页、iframe 或 canvas，也未证明严格 Research 或
全部浏览器能力都获得提升。B 的附加消息只是测试干预，不是准备发布的生产消息设计。
现有短正文采集限制仍在；本轮没有修改该规则，也没有把短表单的恢复能力测成通过。
生产源码起止摘要相同，没有生产代码差异。
