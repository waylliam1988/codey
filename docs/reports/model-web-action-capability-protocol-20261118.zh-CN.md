# 模型网页行动能力：实施前协议（2026-11-18）

目标：检验现有 Gemma 12B Q4 在工具明确可用、已有网页阅读指令的正常 Chat 入口，能否自主搜索、打开相关正文并利用观察继续。只增加实验脚本与报告，不修改生产代码、模型设置或完成检查。

## 冻结设计

- 本地 KoboldCpp `/v1/models` 核验身份；temperature=0、非流式、output8192、context262144、reserve32768、keep32000。每次物理请求最多1次，超时120秒；每个任务最多8轮，失败保留、不覆盖、不暗中重跑。
- 6个自然任务：知乎福州美食、小红书青岛游玩、陌生平台、混合来源、打开失败后另选来源、全部来源受限。另2个明确操作步骤的正对照，用于区分自主任务分解与听从具体步骤。
- 上述8个任务分别走 native 和原事故所属的 text 工具模式，16格。另2格 native 真实网站任务，合计18格。不是18种语义任务，也不是多次随机重复的稳定性统计。
- 每格独立 state，无旧助手回答与 Ghost 历史；使用生产 headless→task entry→provider→kernel→research tools。显式授予 web.read，保证工具可用；不授予项目写入，不设置必需来源、不强制打开、不切严格研究。
- 受控格仅替换 WebSourceProvider.search/fetch 数据。正文为合成材料，既不代表真实网站内容，也不算实际访问知乎或小红书。通过正文独有名称检查观察采用，搜索摘要不含答案。
- 真实格使用隔离的 headless 获取浏览器，真实搜索与获取；不接管用户浏览器，不登录、不发帖。

## 分开记录的指标

1. 工具可用性：实际出站请求中 web_search/open_url 定义或文本工具合同、网页阅读指令。
2. 搜索执行与主题保持：工具调用回执和实际查询。
3. 来源读取：指定来源相关页面的 fetch 成功，且正文进入后续模型请求。只调用 open、错误页、其他平台内容不计。
4. 观察采用：回答出现两项正文独有名称。与搜索/打开执行指标分别统计，不宣称穷尽事实准确性。
5. 恢复：实际失败后尝试另一相关来源并取得正文；全部受限时人工检查限制披露及是否假称读过。
6. 框架帮助：检查完成反馈是否在模型首次结束提案后强制补做。必须区分主动动作与被已有反馈推动的动作。
7. 环境、解析、超时、截断与模型提前结束分别归因；不能将所有缺失动作都算模型能力失败。

原始请求、响应、来源数据、durable state、工具事件、完成记录放在新的 D:/codey-local-evidence/model-web-action-20261118-* 目录。冻结 protocol.json 与脚本摘要先于首个模型请求保存。报告必须人工复核所有失败和代表性成功。

## 执行中的调度修订（保留首轮数据）

`controlled-recover_open-text` 在收到第一条来源登录失败后，第三次模型请求120秒超时；客户端结束后服务端仍在生成。首版调度器未检查每格之间的后端空闲，导致 `controlled-all_blocked-native` 排队并连带超时。这两格原始数据保留，不重跑；后一格不能用于能力判断。

剩余格开始前核验 idle=true、queue=0，每个请求增加唯一 genkey，仅在有匹配身份时清理本实验遗留的生成。不修改任务、来源数据、模型可见提示、工具定义、预算或评分。首版脚本和前后摘要、受影响格、修订时间记录于 evidence 根目录的 `runner-before-scheduling-amendment.py`、`scheduling-amendment.json`。

另更正入口描述：实验只显式请求 web.read，但正常 headless Chat 会创建隔离工作区，实际 runtime observation 中 can_modify_project=true；不能声称没有项目写权限。原有用户目录没有提供给测试，已完成格没有文件写入工具动作。最终按实际请求和动作报告。
