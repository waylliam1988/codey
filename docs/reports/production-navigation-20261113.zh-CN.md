## 真实点击与验收

用户问题不含网址。搜索组沿用鱼丸与博物馆两个问题，各含多个混淆结果。详情组先搜索并打开订单/库存列表，再按原生 snapshot 的元素 `ref` 点击：

- 普通链接：订单 A-173 配送详情，混有 A-174 配送和 A-173 发票链接。真正点击后导航到详情页，正确值是 `2026-11-18`、`0042091`。
- 事件链接：西仓 RX-08 库存详情，混有北仓 RX-08、西仓 RX-09。目标链接调用 `event.preventDefault()`，850 毫秒后更新当前页，正确值为 `37 件`、`WEST_0037`。直接导航该 `href` 只到静态降级页，读不到实时记录。

页面真实点击处理器在 sessionStorage 记录目标 ID 和 `event.isTrusted`，只读诊断收集它。验收同时核对：原 snapshot 中的 ref 与目标控件对应、生产 `browser_click` 成功且有可信事件、随后在正确 URL 完成指定文本等待、完整 `browser_read` 读到全部事实、最终回答交付正确事实。生产点击回执仍保持 `effect_verified: false`，没有把“点击已送达”改写成“业务完成”。

值判断要求日期、编号、版本、带单位的数量按记录出现，并排除已知其他记录值；不做一般自然语言等价判定。下面的错误日期是 20 日而非 18 日，属于实际错误，不是日期格式差异。浏览器子调用完成与父 CodeMode 返回成功单独说明，不把父调用的返回错误算成点击机制失败。

固定回归还覆盖了：正确 A/B 来源、错误 URL、伪造 `rN`、直接导航替代事件点击、同 URL 重载后的真实旧 ref 拒绝、漏等待、交付漏项、混入其他记录值及不可信事件。未给点击工具增加候选接口。

失败按实际阶段区分：

- A 六次失败均在打开目标来源前。鱼丸第二轮、博物馆第一轮反复使用 `unwrap(web_search_result).text`；订单与库存两轮使用不存在的 `.matches[0].path`，后来返回空串并重复搜索。生产声明的成功值是字符串。这些场景没有执行一次 `open_url`，不能记成 URL 抄错或点击失败。
- B 订单第二轮、库存第一轮把 `result_id` 写成 `id`，校验拒绝后仍重复。没有进入来源解析或点击。
- B 库存第二轮先修正了参数名，但实际选择 `r1`，程序按真实映射打开了北仓，而所需的西仓列表是 `r2`。这是选错候选；程序传的仍是所选候选原地址。随后模型对没有目标控件的页面使用自造 `details_link` 引用，真实调用被 `stale_ref` 拒绝，直到轮次用尽。这不是一次已经观察到的旧 ref 恢复实验。
- B 订单第一轮先把参数名写错，随后自行修正为 `result_id: r2`，完成真实 snapshot、点击、等待、读回与正确交付，共 8 次模型请求。

A 实际成功调用来源打开两次，地址均原样正确；B 实际进入来源解析六次，地址也均与当时所选搜索引用一致，其中一次选错候选。没有抓到 A 的实际地址抄错，因此本轮能证明生产引用入口可以使用，不能单独量化“省掉地址抄写”对可靠率的贡献。
