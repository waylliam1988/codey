# 浏览器确定性闭环验收（2026-11-22）

本轮严格研究模式首次完成真实动态按钮流程，原始回执为 `start → One → Two → Three`，共 4 次点击，没有重放点击。完成提示 `All Buttons Clicked` 出现在动作后的正式来源 `[e5]`，初始 `[e1]` 不包含该提示。普通模式首次仍陷入导航循环，程序在无进展预算达到 4 时以 `no_progress` 结束，没有完成网页任务。不能据此宣称所有模式均已跑通。

## 根因与本轮修改

| 问题 | 确认的缺口 | 生产行为 |
| --- | --- | --- |
| 重复点击 | 原 `purpose=controls` 立即快照，加载文字变化不能证明下一控件可操作 | 原快照回执提供基线；点击只执行一次，沿现有执行链等待新增、重命名或新启用控件，再取得新快照 |
| 导航循环 | 既有传输标识规范化和重复导航提示仍依赖模型纠正；效果动作豁免使循环继续 | 已见导航/快照循环消耗原有无进展预算，到限以未完成退出；显式导航仍实际执行 |
| 旧来源冒充当前结果 | 自然语言操作任务未进入显式等待/读取工作流；快照不是正式来源 | 整体研究作用域内，页面修改动作接正式 `browser_read`；提交检查当前文档最后动作之后的完整正式来源 |
| 错误引文 | 仅有来源标签和提交成功不能证明逐字引文存在 | 对交互结果报告中相邻双引号/中文引号与 `[eN]` 的明确引文核对原 passage，旧来源仍可作背景 |
| 操作统计失真 | 模型凭上下文重写次数和顺序 | 从原提交回执生成动作顺序、目标、交付状态、引用和计数；冻结进研究作用域并在报告编译时复核 |

复用原 CodeMode、ToolSpec 效果分类、durable 回执、后台工具任务与证据账本。控件基线比较使用启用控件的角色/名称计数，不依赖随重连变化的节点引用。后台等待从父任务原回执恢复基线，覆盖内存清空、托管大输出与 worker 重连；没有第二套运行时或双写快照事实。

控件等待超时保留失败等待回执，但继续取得当前快照；研究模式再读取正式页面来源。超时本身不宣称业务失败、完成，也不触发重放点击。取消、原文档丢失等其他失败仍中止后续链路。

`AnswerScope` 从版本 7 升至 8，携带冻结的执行摘要和原动作引用；继续解析历史 4–7 版本。报告编译以原提交之前的事实核对当前结果，之后的新动作不会重写已接受报告。

## 剩余限制与尚未闭合的边界

1. 普通模式的动作选择仍可能循环；程序已可靠退出，但不会替模型选择业务按钮。研究模式也仍出现一次冗余导航。没有静默吞掉显式重载，也没有禁止所有重复点击。
2. 控件等待比较当前既有 AX 支持角色（button/link/textbox/checkbox/combobox/menuitem）的启用数量变化。它是值得重新观察的信号，不是业务完成证明；其他角色、同名替换、值改变或没有新增控件的完成态可能等满 5 秒，再返回新快照。
3. 自动动作后正式读取接在整体研究的现有 CodeMode 执行链。需要问题参数的读取不会擅自猜参数；底层原子动作保持原子性，缺少动作后来源的 `answered` 提交会被拒绝，允许诚实报告 `partial/unresolved`。
4. 当前结果检查要求引用当前文档最后动作之后的正式来源，并机械核对有限格式的明确逐字引文。自然语言释义、表格推断、没有明确引号的转述，仍需语义审查。它不能证明所有引用句均受来源支持。
5. 程序摘要忠实记录已交付/已验证/不确定交付的页面动作，不把交付当业务成功。研究最终稿的程序统计由回执生成，普通模式自由文本和模型另写的解释仍可能出错。

以上边界不通过扩大为无关重构、追加另一事实来源或更改合同来掩盖。
