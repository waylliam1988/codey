# 来源定位与拒绝命令准入（2026-10-24）

本批基线为 `7bd778fb`。验收要求是本批有明确收益、没有发现新增回归；不运行全量 pytest，不进行性能对照。修复适用于共用内核，不含 Gemma、股票题目或 PowerShell 专用的重试分支。

## 来源定位

旧记录中模型曾调用 `open_hit`，但普通联网任务的快照没有声明这个工具，解析器将其拒绝。与此同时，来源搜索输出又无条件建议调用 `open_hit`。因此，不能把旧问题全部归因于模型忽略指令。

修改：

- `tool_spec.visible_tool_names_for_snapshot` 把三个引用工具纳入可见工具候选。
- `kernel_protocol.controller_allowed_for_session` 根据已观察到的 `search_results`、`source_ids`、`hit_targets` 收窄候选，同时保留原有能力授权和控制器否决。冻结后的同一个快照用于文本契约、原生 schema、解析和执行。
- 搜索正文、结果引用标题只说明观察和引用，不再无条件推荐下一步工具。
- 原有 `TaskPolicy.required_checks` 支持 `tool_succeeded:<工具名>`。完成门只消费已经提交的执行记录，不从回答文本、调用参数或“打开过任意来源”推断特定工具成功。
- 原 `_settle_slot` 中的执行记录投影移到 `kernel_facts.project_execution_record`，实时提交和恢复共用这一函数。没有新增持久状态、第二份成功日志或恢复执行器。

边界：这个通用检查证明指定工具有成功观察，不证明任意参数、调用顺序或所有自然语言步骤。任务入口必须明确声明要求；本批没有增加按题目关键词推测流程的解析器，也没有为普通解释、创作、固定 JSON 强制增加联网步骤。

先运行的来源测试有 4 项失败。修改后补测了真实 SQLite 提交和恢复：提交故障不发布成功记录、不满足完成要求；成功提交恢复后仍满足要求；重复恢复不累计记录。

本地 Gemma 实机使用原有生产内核、HTTP 模型连接、SQLite 和回执恢复，受控后端只提供测试来源。`artifacts/source-denial-locator-live-20261024-02/summary.json` 的 8 项全部通过：

| --- | --- | --- | --- |
| 来源内定位 | 通过 | 通过 | 实际执行 `open_url → source_search → open_hit`，得到 AMBER-913 |
| 搜索后读取重定向来源 | 通过 | 通过 | marker 和最终 URL 正确 |

## 拒绝命令再次申请

旧逻辑已经向模型发送拒绝结果及“不得重试”的提示，但准入只检查语法、路径和能力，没有消费原任务的拒绝决定。基线函数诊断确认：已有一条持久拒绝时，同一命令仍产生一张新审批卡。

修改：

- `operations.shell_authorization.denied_shell_message` 从原任务 checkpoint 中已有的 `approvals` 读取决定，用原有 managed artifact 的摘要和分析绑定校验命令。
- 同一任务中相同命令、实际工作目录和解释器被拒绝后，审批入口不创建新审批 ID；执行入口返回 `denied_before_execution` 的失败回执，并保留原调用身份。
- `run`、`shell` 及 CodeMode 子调用共用这条检查；已提交回执的恢复仍走原恢复路径。
- 记录或工件不能验证时拒绝执行，不回退到提示词或审计 JSONL。
- 不同命令、不同工作目录和新的人类请求任务继续走现有审批流程。解释器由会话确定，模型不能通过调用参数切换解释器。

边界：这是原任务内的精确调用约束，不是命令语义等价分析或跨任务永久黑名单。新任务重新询问权限，仍需原有授权流程；本批不把模型要求“重新授权”的文字当成人类授权。

9 项定向测试覆盖拒绝后的准入、执行、SQLite 重开、工件缺失以及正常放行边界。故意重复调用的 HTTP 测试覆盖 `run`/`shell` × Chat Completions/Responses，共 4 项通过；第二次调用得到拒绝回执，任务完成，没有第二次审批或命令执行。

PowerShell 7.5.3 实机拒绝探针连续两次通过，记录在 `artifacts/source-denial-shell-live-20261024-01` 和 `-02`：各一张 `shell_request`、一条拒绝结果、空 execution_id，没有执行或第二张审批卡。两次模型都直接说明拒绝；模型主动重复的分支由上述确定性 HTTP 测试验证。
