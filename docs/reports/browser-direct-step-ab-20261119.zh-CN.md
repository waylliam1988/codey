# 浏览器单步操作展示 A/B（2026-11-19）

结论：**本轮不支持采用隐藏自由 JS 的方案。** 主实验 A 成功 10/16、B 成功 6/16；
B 输入 token 减少 57.6%，但自然任务的完成率下降。两组都能从原错误前缀恢复，
不能把恢复成功归为 B 独有收益，也没有观察到 B 减少模型新写 JS 的错误。

## 实验问题与边界

本轮只增加测试、实机实验脚本和记录，生产代码不变，没有创建或复制 worktree。
要验证的是：普通任务保留现有单步填写、点击、读取等工具，只从模型的当前工具展示中
隐藏自由 JavaScript CodeMode，能否降低程序错误并提高完成率。

- A：当前生产请求，不附加操作卡片。
- B：仅投影当前系统工具合同与 JSON 采样 schema，移除自由 JS CodeMode 分支。
- 内部执行仍使用原生产快照、权限、解析器、执行器、回执、恢复与完成检查。
  单步填写、点击仍通过原生产 CodeMode lowering 执行。
- 显式要求 `Use codemode only.` 的任务以及正式绑定的文件复制入口保留。
  B 不是只允许浏览器工具的白名单，原有来源搜索、项目工具等仍在。
- 不重写模型回复；超出投影视图的回复算实验失败。展示投影本身不是执行权限屏障。
- 两组都去掉上一轮普通任务中的 `Use codemode only.`，所以不能直接与操作卡片实验
  比较成功率并把变化归因于 B。A 原本就能选择生产已有的单步工具。

这不是新的浏览器运行时，也不替模型判断该填什么、点哪个、何时读取。只有
来源证据和目标满足既有合同，才能进入原有固定字段复制，不能给任意编辑补凭据。

## 场景与成功条件

| 场景 | 要验证的行为 |
| --- | --- |
| early_break | 重放两次原提前退出循环的错误程序后，模型能否恢复 |
| partial | 重放已填写、随后错误取值的程序后，是否只继续缺失动作 |
| reordered | 控件顺序反转并更换名称，是否正确填写和查询 |
| duplicate | 同名控件分处不同区域，是否选对当前库存 |
| slow | 填写后替换节点、点击后延时更新，是否等待真实结果 |
| pagination | 翻页再打开目标记录，是否完成两次正确点击 |
| visible | 初始正文已经足够，是否避免无关操作 |
| file_copy | Hybrid 查询并依据正式来源修改文件 |

恢复场景有脚本错误前缀，只统计前缀之后的真实模型调用，不能当作首次自主成功。
成功须同时满足生产完成、正确事实、已观察正文支持的引用、正确文件、正确动作与次数、
生产源码未变和无超出投影视图的回复。正文可以来自正式读取，也可来自已观察的快照或
点击回执；正式 `browser_read` 另行计数。

字段 `no_repeated_actions` 实际检查期望填写/点击次数及错误动作数为零，失败也可能是
根本没有执行操作，不能一律描述成重复点击。固定 JS 内部执行也不能算模型自行编程。

## 主实验结果

| 场景 | A 两轮 | B 两轮 |
| --- | --- | --- |
| early_break（恢复） | 2/2 | 2/2 |
| partial（恢复） | 2/2 | 2/2 |
| reordered | 2/2 | 0/2 |
| duplicate | 0/2 | 0/2 |
| slow | 0/2 | 0/2 |
| pagination | 2/2 | 0/2 |
| visible | 2/2 | 2/2 |
| file_copy | 0/2 | 0/2 |
| 合计 | **10/16** | **6/16** |

恢复项各 4/4；自然任务 A 6/12、B 2/12。16 对中，两组都成功 6 对、都失败 6 对、
只有 A 成功 4 对、只有 B 成功 0 对。不是只对通过的任务统计。

| 全部 16 对，用量均完整 | A | B |
| --- | --- | --- |
| 真实模型调用次数 | 87 | 64 |
| 输入 token | 968,990 | 410,595 |
| 输出 token | 3,440 | 2,345 |
| 模型新提议自由 JS | 0 | 0 |
| 模型提议 `browser_*` | 59 | 14 |
| 至少一次正式 `browser_read` 的任务 | 6/16 | 2/16 |
| 动作及次数符合要求 | 14/16 | 6/16 |

B 输入减少 57.6%，调用减少 26.4%，但其中包含没有完成任务就停下的情况，不能称为
同等任务效果下的节约。共同成功的 6 对中，输入 181,705 → 81,995（减少 54.9%），
调用 16 → 12；恢复子集输入 164,754 → 72,652、调用 14 → 10。这些只说明局部成本变化，
不推翻整体完成率下降，也不能用成功子集替代全部任务结论。token 是接口报告的逻辑
用量，不等于现金费用、缓存成本或硬件性能。

主实验中 A 已经选择现有单步工具，没有真实模型新写自由 JS，因此不能声称本实验
证明“限制 JS 减少了原循环错误”。恢复项在没有强制 CodeMode 的当前条件下，两组都
绕开了原循环。这与上一轮强制 CodeMode 的展示卡片实验不是同一比较。

## 原始请求与回执核对

所有 32 项均保持生产摘要不变、没有投影视图违规、没有 runner 异常，完整用量 16 对。
核对范围包含每项实际请求、动作提议、生产子回执、页面计数和最终答案，不只看
`stop_reason`。生产 `done` 不自动等于实验成功；事实、来源或交付不符合要求仍失败。

| 失败场景 | 具体行为与证据 |
| --- | --- |
| reordered B 两轮 | 当前请求有填、点、读工具；模型反复 `source_search`/`open_url`，未填写或点击。首轮还把 offset 推到正文末尾，被明确拒绝。 |
| duplicate A 两轮 | 任务要求当前库存，模型却选“历史记录”区域。点击已经执行，正式读取保持结果未确认；之后重复读取，未恢复。第二轮页面记录错误点击 1 次。 |
| duplicate B 两轮 | 未操作表单，读取末尾 offset 被拒后却回答 `150g / 88291`；真实页面未提供这组答案。生产完成，实验按事实及来源失败。 |
| slow A 两轮 | 都找到表单并执行填写/点击，但填写值不是任务要求的福州，没拿到业务结果。首轮还编造数值；第二轮承认未加载，但任务仍未完成。 |
| slow B 两轮 | 都未填写或点击。首轮把 URL 中连字符改成下划线，受控站点按设计返回 404；第二轮在尚未查询时结束。 |
| pagination B 两轮 | 把网页第 2 页理解成 `open_url(pages="2")` 等文档读取，没有点击 Next 和目标记录，最终停滞。 |
| file_copy A 两轮 | 都未取得要求的真实业务字段。首轮先漏 `base_result_ref`，补凭据后仍被来源字段校验拒绝；第二轮填错城市后，结果一直未确认。 |
| file_copy B 两轮 | 重复读取或搜索尚未查询的页面，读了目标文件，但没有填写/点击，也没有正式业务字段。 |

具体可见对应任务目录的 `actions.json`、`provider.jsonl`、`raw-audit.json`。
例如 `r1-file_copy-A/raw-audit.json` 保留两次编辑拒绝：先缺文件凭据，后缺来源字段；
不能把它简化为“只差自动补参数”。全部文件任务的正式固定复制展示次数为零，
原因是来源前提未满足，不能判为固定复制执行器失效。脚本回归已经证明同一生产路径在
证据完整时可用。

成功恢复也保留过程中的错误：`r2-early_break-A` 曾使用失效编号，动作没有交付，
随后取新观察继续；`r2-pagination-A` 曾提交字面量 `<snapshot ref>`，被拒后重新选择。
最终页面计数与成功回执一致。`partial` 四项均只填写一次、点击一次；前缀已经完成
填写，真实模型只继续缺失操作，没有重复交付。

本轮未发现足以归为生产确定性 bug 的新证据。模型误选区域、错填城市、误用读取 offset
和把未查询页面当结果，属于已执行请求可见的模型错误。模型改错 URL 得到预期 404，
不能归为意外站点宕机。也不能从这些案例断言生产系统已无其他 bug。

## 显式 CodeMode 控制

额外运行 reordered、pagination 各 A/B 一次，共 4 次任务；两组任务都明确写有
`Use codemode only.`。全部投影记录 `changed=false`，不移除自由 JS，也不重写回复。
这是保留原入口的控制，不是另一组开启/关闭 JS 的成效比较。

| 场景 | A | B |
| --- | --- | --- |
| reordered | 失败，done，4 次模型调用 | 失败，no_progress，5 次模型调用 |
| pagination | 失败，no_progress，4 次模型调用 | 失败，no_progress，7 次模型调用 |

两组都 0/2，但 CodeMode 工具确实可以执行：共 19 次 JS 提议、20 次真实模型调用。
全部用量完整，无超时、runner 异常或生产源码变化。原始失败全部保留，不靠重跑变绿。

- reordered A 先访问未 unwrap 的返回值，再被注释中的字面量 `\n` 拒绝；修正后只填写、
  不点击便结束，没得到结果。
- reordered B 出现无明确 return、注释转义错误、恢复程序不匹配已执行工具序列等问题。
  后来意识到要点击，但未按原控制流恢复，未交付点击。
- pagination A 把网页翻页当作正文 offset，误读工具输出字段，并改错 URL，没有点击。
- pagination B 反复对未翻页正文编写正则提取，改变读取控件上限却没有点击 Next，
  最终仍返回空字段或“未找到”。

两组请求仍有运行时身份差异，少量样本出现不同程序不等于投影生效。不能把这 4 次
失败与主实验合并成 B 的收益，也不能据此证明单步操作在任意任务上优于 JS。
最终完整性核对在 `final-integrity-audit.json`；主实验成本子集在
`live-first/final-metrics.json`。36 次任务共 171 次真实模型调用，脚本前缀另计。

## 外推限制

单一量化模型、受控网页、两次 seed、温度 0，不是独立随机样本，不能证明任意公网
页面可靠。运行时引用身份、时间等会变化，seed 不代表请求字节完全相同。
本实验只检验现有单步操作的模型展示，不代表所有“模型选择、程序执行”的设计都无效。
较早停滞可能降低输入量，但不能算成功率收益；失败任务的用量也必须计入。
