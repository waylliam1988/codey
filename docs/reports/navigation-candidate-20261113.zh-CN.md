## 实验范围

这次使用真实本地模型和真实 Chromium，搜索结果与业务页面由受控 HTML 提供。搜索组由模型根据自然问题生成查询词，原生产 `BrowserSearchProvider.search` 真实打开受控 Bing 页面并解析多个结果；fixture 对不同查询返回同一组候选，因此不评价互联网搜索质量或查询词的召回能力。详情组由脚本先打开列表页，模型看到实际页面正文、链接文字、所在列表项和解析后的完整链接地址，再选链接。用户的问题都没有网址。

A、B 均使用实验性的 JSON 选择接口：共同返回 `candidate_id` 和选择理由，A 额外抄写完整 `url`，B 由程序按引用取 URL。A 的候选引用用来独立记录“选对但抄错”的情况；A 不是未经修改的生产代理。两组候选内容一致，详情页文档身份和由其派生的引用随浏览器实例变化。

生产已有 `open_result(result_id)`，搜索结果引用并非新能力；本实验没有与它比较，也没有把它替换掉。这里只比较候选选择后由谁传 URL。脚本固定安排“查询/观察 → 模型选择 → 程序导航与读取 → 模型回答”，每步一次，没有自动修复回复或挑成功样本；导航与读取使用原生产 `BrowserSession.navigate/capture`。原始浏览器观察以 JSON 留存，没有经过生产 Headless / CodeMode / durable receipt / done 完成链。因此结果说明这个受控选择入口可用，尚不证明完整生产代理会自主选择入口、安排导航时机或在一般网站上更可靠。

模型输出模式只限定字段类型，不枚举正确候选。目标答案只传给采样结束后的 `score`；导航解析只按模型选中的引用查表，选错对象也原样打开，不代选。候选 URL 来自实际搜索解析结果或当前可见 `a.href`，不从验收答案生成。详情候选还带 Chromium 文档身份，执行前重核文档和可见链接；同 URL 重载或链接替换会拒绝旧观察。相对链接以浏览器解析出的绝对 `href` 为基准，未测试服务端重定向或通用 DOM 变化策略。

## 问题与验收

| 组 | 自然问题 | 混淆候选 | 必须读到并交付 |

| 搜索 | 榕城检验站 2026 秋检福州鱼丸的净重与校验码 | 去年归档、泉州样本、食客论坛；正确结果在第 3 项 | 173 克、QUARTZ_851 |
| 搜索 | 澄川博物馆今年秋季周五夜场的闭馆、最后入场时间 | 日场、另一美术馆、去年公告；正确结果在第 1 项 | 21:40、20:55 |
| 详情 | 订单 A-173 的送达时间和追踪号 | A-174 同名配送链接、A-173 发票链接；正确链接在第 3 项 | 2026-11-18、0042091 |
| 详情 | 西仓 RX-08 的可用库存和记录版本 | 北仓同 SKU、西仓另一 SKU 的同名详情链接；正确链接在第 1 项 | 37 件、WEST_0037 |

每项单独记录：选中候选是否为目标、实际导航参数是否严格等于所选候选的原地址、目标是否真实 HTTP 200、完整读回是否属于该目标并包含全部事实、最终答案是否交付全部事实且未混入已知其他记录值。仅地址正确、仅 HTTP 200、或凭空写对答案都不算通过。追踪号保留前导零。

固定回复测试还故意让 A 在正确候选的 `autumn-2026` 地址里抄成 `autumn_2026`。A 选对但真实 404，即使受控最终回复写对事实也不通过；B 只按同一候选引用传原地址，读回后通过。另测错候选照常打开但验收失败、伪造/其他观察的引用拒绝、B 传额外 URL 拒绝、同 URL 重载拒绝、链接被替换拒绝、缺项及截断读回拒绝。

## 判分修正与正式重跑

开发采样发现脚本错误地给 `passed` 额外加上 `missing == ""` 条件，提示却只要求字符串，模型使用 `"none"` 表示无缺项。已查到且回答齐全的结果被误判失败。这个判定是实验代码的问题。

已先移除这个额外格式条件，让总判定依据上述用户验收事实；补入空串、`none`、“无”三种无缺项表达的测试，并确认真实漏事实、读错页面、前导零丢失仍失败。**20 项定向测试通过后，才用新目录完整重跑 16 项实机。** 未改模型提示、回复或候选选择逻辑；正式结果全部来自修正后的新运行，不是给开发采样重新判分。

包内 `development/scoring-v1/` 和原采样脚本保留错误版本的全部记录，明确排除出正式统计；`formal/` 保存重新运行的请求、回复、原始导航与读回。正式采样前保存的脚本与最终提交脚本逐字节一致。

模型为 `koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`，端点 `http://127.0.0.1:5001/v1`，temperature 0、thinking 关闭、JSON schema。两对 seed 为 `123456789`、`123456790`，问题间和 seed 间交替 A/B、B/A，每组每臂为两道题乘两个 seed。

两组合计 A、B 各 8/8，各 20 次模型请求。A prompt/completion token 为 11242/1267，B 为 11280/979；B 少输出 288 token（约 23%），累计模型回复耗时 A 47.220 秒、B 38.313 秒。输出量包含选择理由与最终回答的变化，不全是 URL 长度。阶段数由脚本固定，不能据此估计生产自主运行会节省多少请求。小样本也不能给出可靠率或稳定速度收益结论。

这一批没有出现 A 的实机地址抄错，因此只证明模型能在“用户没提供 URL”的两种观察中使用候选引用，固定对照中的地址传递机制成立；尚未观察到实机完成率优势。
