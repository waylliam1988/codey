# 小红书真实页面观察与人工登录接续方案

日期：2026-11-21（Asia/Taipei）。目标地址：https://www.xiaohongshu.com/explore 。

本轮使用单独的可见 Edge 和任务专用 profile；未发现可连接的现有 CDP 会话，因此不声称连接了用户截图中的标签页。通过 Playwright 操作页面，并在真实 DOM 上调用生产 `BrowserSession` 快照和内容校验方法。没有运行模型自主决策链，没有登录或注册，没有发送验证码、点赞、收藏、关注或发表评论。观察完成后已关闭本轮浏览器。

## 1. 真实观察

| 步骤 | 实际结果 | 对方案的影响 |
| --- | --- | --- |
| 独立 HTTP 获取 explore | 重定向至登录路径；HTTP 200，但为未填充应用壳；生产 HTTP 获取返回 `page_not_loaded` | 这次会触发既有浏览器 fallback；HTTP 200 本身不能说明正文可读 |
| 可见浏览器打开 explore | 主文档 HTTP 200；出现扫码、手机号和验证码登录弹窗；背后已有 30 个推荐卡片 | 登录入口、登录阻挡与可读内容必须分开判断 |
| 弹窗打开时正常点击搜索框 | 点击超时；Playwright 明确报告 `reds-mask` 拦截 pointer events | `is_visible()` 不代表当前可以点击 |
| 关闭首屏登录弹窗 | 弹窗消失；推荐卡片仍在，可点击搜索框 | 首屏弹窗可关闭，不能一见弹窗就要求用户登录 |
| 输入“福州美食”并回车 | 地址仍为 explore；出现“登录后查看搜索结果”；没有进入搜索结果页 | 这次已确认站内搜索被登录挡住，适合保留该页并请求用户登录 |
| 关闭搜索登录弹窗，打开一篇推荐笔记 | 笔记详情出现，并再次出现推荐登录弹窗 | 必须观察当前操作的结果，不能仅凭弹窗存在就判定笔记读取失败 |
| 关闭笔记上的登录弹窗 | 标题、正文、图片和部分评论可以阅读；页面另有“登录查看全部评论内容” | 公开正文可读与完整评论受限可以同时成立；不能声称已读全部评论 |

## 2. 在真实 DOM 上复核的实现缺口

1. **登录检测漏检。** 七次观察中 `_requires_login` 均返回 False，包括明确显示“登录后查看搜索结果”的页面。检测要求全文少于 1500 字符并存在密码输入框；首屏提取文本为 1979 字符，且使用扫码/短信登录。不能只补密码框的替代 selector，全文长度条件也需要调整。
2. **内容校验不能表达动作阻挡。** 七个节点 `_validate_page_observation` 均返回 None。列表内容确实存在，因此不能简单将整页改判为无内容；需要额外返回当前动作是否被弹窗挡住、哪些区域仍可读。
3. **关闭控件没有进入模型快照。** 登录关闭图标是无名称的 `div.icon-btn-wrapper.close-button`，不在当前交互元素选择器中。即使某图标改用 button，无名称按钮仍可能被过滤掉。本轮是观察脚本检查真实 DOM 后点击的，不能说生产模型已经会关闭它。
4. **背景控件被当作普通可用控件。** 搜索框和背景链接在遮罩下仍满足 `is_visible()`；快照没有阻挡和所属层信息。七次快照都达到 80 元素上限并标记截断，背景备案链接和卡片会占用预算。
5. **输入框名称损失语义。** 手机号框在生产快照中名为“+86”，验证码框名为“获取验证码”。需要保留 placeholder、input type 等独立字段，不能仅依赖当前拼接的 name。
6. **同文档发生任务状态变化。** 本轮首屏、关闭弹窗、搜索受限、打开笔记等节点的 targetId 和 loaderId 一直相同。即使 URL 或 loaderId 不变，弹窗、搜索状态和正文区域也会改变。恢复时必须重新观察 UI，不能只核对文档身份。

## 3. 建议的生产行为

以用户要完成的动作判断是否需要协助，不维护另一份持久化“已登录”真假表。

```text
打开并观察当前页
  ├─ 目标内容可读：读取对应区域，标明范围
  ├─ 可关闭的普通登录提示：关闭一次并重新观察
  │    ├─ 可以继续：继续原任务
  │    └─ 目标操作明确要求登录：保留该页，转人工协助
  ├─ 明确的登录/验证阻挡：保留并展示页面，ask_user
  └─ 仅有访问拒绝、无登录证据：如实说明限制，按页面证据决定协助方式

用户回答
  → 接回原浏览器和目标页
  → 刷新快照、控件引用和当前响应事实
  → 核实受阻动作是否已可执行
  → 必要时重做一次原查询
  → 打开实际结果并读取正文
```

在本轮小红书搜索中，询问可以表述为：“小红书显示‘登录后查看搜索结果’。请在已展示的浏览器页面完成登录，完成后选择继续，我会重新检查并搜索。”用户在网站中输入账号和验证码。

如果用户暂不登录：保留已经取得的公开信息，明确无法完成站内搜索或全部评论读取；只有用户允许替代来源时才改用替代来源，不能声称完成了原指定平台任务。

## 4. 分三批实施，每批有验收目标

### 第一批：让观察准确表达当前可操作页面

修改 `browser_observation.py`、`browser_session.py`、`browser_page.py`。

- 在现有观察中补充前景弹层、输入方式、提示文本、背景是否被遮挡等事实；区分“存在登录界面”与“当前动作明确要求登录”。具体字段随现有回执合同统一设计，不新增独立登录状态库。
- 首先使用 dialog、aria-modal 等语义；本次实页弹层只有 `role=presentation`，必须覆盖非标准弹层。几何、层级与命中测试属于辅助证据，不宣称一个通用 selector 能识别所有网站。
- 快照优先列出前景层与当前任务区域，再列背景；保留控件上限与截断标记，不以无限增大 DOM 输出解决排序问题。
- 对背景控件补充遮挡信息。不能直接删除所有命中测试失败的元素：离屏、可滚动区域与真正被遮罩阻挡需要区分。
- 对没有文本的图标控件保留实际 ref、可访问名称（如有）、位置与所属区域；无法可靠判断用途时提供进一步 DOM 观察或截图。截图辅助取决于模型视觉能力；无名称不能凭 class 猜成“关闭”。
- 保留 placeholder 和 type，避免把“+86”当成手机号框的全部语义。首版无需新增账号输入自动化。
- 登录判定基于弹层局部内容和实际操作后果，去除依赖整页短文本及密码框的必要条件。不能把有公开正文的整个网站判成不可读。

验收：重现本轮三种状态——首屏可关闭提示、搜索强制登录、正文可读但评论不完整。前景控件不能被背景 80 个控件预算挤掉。

### 第二批：完成人工接管的资源与恢复闭环

修改 `browser_search.py`、来源执行/审计绑定、资源清理和 `BrowserSession` 当前页读取。

- 对可继续人工处理的受限页面保留当前任务页；安全拒绝、取消和最终资源释放仍走既有生命周期。
- 在正文获取失败时也记录可恢复的浏览器绑定。把页面可接管事实和正文证据分开，失败页不产生已读正文证明。
- 复用现有 ask_user / DurableUserQuestionStore，不另建登录问答系统。浏览器资源在等待期间由任务持有，不能被 `run_entry_kernel` 的 finally 清理关掉；恢复、完成、取消和应用关闭必须有对应释放路径。
- 复用 BrowserBinding 中的 endpoint、browser UUID、context 和 targetId；不可用时明确失败，不能按域名任选一个标签页。
- 用户回答后先 snapshot，再 browser_read 或实际查询。不要默认重走 open_url 的独立 HTTP 路径，也不要把回答“已登录”直接写成成功。
- 修复同一 Page 上旧 HTTP 响应缓存与新文档不一致的问题。页面状态可能通过 SPA 变化，需刷新 UI 和控件引用；同一 URL、同一 loader 都不能代替当前观察。
- 窗口在请求协助时展示到前台，用户可以直接扫码；等待期间不反复刷新二维码、导航或抢焦点。
- 小红书搜索被阻挡后，用户登录可能不会自动重放原查询。保留查询意图，恢复后确认是否已有对应结果；没有则在同页重新搜索一次，不能把推荐 feed 当成搜索结果。

验收：等待任务时窗口不关闭；回答后连接原页；未登录、页关闭、浏览器重启、取消均有准确结果；取得正文后正常释放任务资源。

### 第三批：接入模型决策与有范围的正文读取

修改共享任务指导、结果交接及必要的正文范围选择；Chat 与严格 Research 使用同一浏览器事实。

- 发现弹窗后观察其当前用途。关闭一次可选提示后重新观察；明确登录阻挡时调用 ask_user，停止重复关闭和重复搜索。
- ask_user 保持独占控制回合，不与页面交互混发；继续使用现有持久化问题、用户回答和任务恢复机制。
- 导航完成、查询提交完成、搜索结果出现、正文读取成功分别核实。当前页“有很多字”不能证明搜索完成。
- 笔记详情阅读需要选中前景正文，避免把后面的推荐 feed、备案页脚与评论混成一篇笔记正文。保留标题、作者、正文和已观察评论的归属。
- “登录查看全部评论内容”应产生明确范围限制。可读正文可以入账，不能据部分评论声称完成全部评论分析。
- 若图文任务的信息只存在图片中，需验证视觉/OCR能力；本轮仅确认图片在浏览器中显示，未验证模型能读取图片文字。

验收：相同模型、相同自然请求，通过生产入口自主完成“观察→求助→等待→重新观察→继续”；不能在测试请求里预先教模型调用 ask_user。

## 5. 验证矩阵与实施顺序

先用受控真实 Chromium 页面验证确定性行为，再进行真实小红书人工登录验收。现有实验类 `ResumableBrowserSearchProvider` 可作为参考，但不能直接替换生产 provider；它覆盖保留当前页，不覆盖完整任务暂停、恢复和控件观察。

| 用例 | 必须验证的结果 |
| --- | --- |
| HTTP 200 + 长背景列表 + 扫码/短信弹层 | 识别登录 UI；保留背景可读事实；不误判已完成站内搜索 |
| 可选登录提示 | 一次关闭并继续；关闭操作来自当前观察 |
| 搜索后明确登录要求 | 保留阻挡证据并 ask_user；不循环搜索、关弹窗 |
| 无名关闭图标 / role=presentation 弹层 | 可以定位前景层；观察不足时明确进一步检查或请求协助 |
| 80 个以上背景控件 | 前景操作仍被保留，截断范围可见 |
| 原页登录、同 loader 的 SPA 状态变化 | 重新观察后恢复；旧 refs 不被直接复用 |
| 403 后人工导航到成功正文 | 不沿用旧响应状态；旧错误页也不被误当正文 |
| 用户表示完成但仍受限 | 不记成功，说明剩余限制 |
| 原页关闭或原浏览器被替换 | 不选择其他同域页面替代 |
| 暂不登录 / 取消 | 不编造内容；任务与资源按现有合同结束 |
| 公开正文 + 部分评论 | 正文范围正确；未读取全部评论的限制明确 |
| 用户回答后进程恢复 | 问题回答不丢失；可存活的原浏览器资源按身份恢复 |

首个可交付改动应包含第一批观察修复和对应真实浏览器夹具；随后完成第二批资源闭环；最后跑模型自然请求与真实网站。资源闭环未通过前，不宣称“登录后继续”已经可用。

本轮产出为观察材料与方案，未修改生产实现。上一轮 40 项基础测试通过不等于本轮真实登录链通过；本轮未进行账号登录，因此仍需后续人工登录验收。
