## 调度器 P1

旧实现可复现：队列拒收后第一次 `unclaim_task()` 抛 `OSError`，下一轮只看到 RUNNING，
任务脱离待处理集合并且没有执行者。新回归在修复前失败。

现在单独保留 task ID → 原 attempt token 的待释放动作，释放成功后再解释 checkpoint 并分发。
同 token 的提交冲突继续重试；后来者 token 和取消终态不会被旧清理释放。持续失败使用已有
reconcile 熔断预算（三次），公开 `unclaim_failed` 和禁用状态，显式恢复先做清理。
同样覆盖分发抛异常的清理路径，并修复关闭时跳过本轮清理的路径。
详见 [调度器运维说明](../durable_scheduler_operations.zh-CN.md)。
