# CodeMode 成功回执复用与具体错误反馈（2026-11-13）

本轮以 `34755066` 为基线，落实导航实验收尾的第一批：把已成功的网页读回交给下一轮，保留修复回放的首个具体错误，并显示真实来源与元素引用状态。三个只读工具直调、最终事实交付检查不在本轮范围。

## 生产修改

- `kernel_prompt.py` 从父调用引用的原始、已提交且归属匹配的子回执派生反馈。父程序失败后，成功的 `browser_read` 正文、回执引用、来源和完整性信息仍展示给下一轮；全部正文预览合计最多 8000 字符，优先保留较新的读回。未满足现有要求时仍须完成缺失步骤，历史读回不代表当前页面状态。
- 允许回执读取时，省略的正文附精确 `read_tool_result` 参数。直接保存在回执里的文本按实际展示字符数继续；另存的完整输出可能与展示窗口不同，因此从原输出 offset 0 开始，由已有回执读取工具继续分页和验证摘要。没有开放该工具或缺少 control 权限时，不附这个调用。截断或归属不明的读回不能获得完整读取标记。
- `replay.py` 保留本次修复的首个工具/参数不匹配，指出从 1 起算的步骤、预期与实际工具或参数。即使模型捕获异常，首个拒绝也不会被清除。确实提前结束时才列出剩余步骤；编译失败等已有具体运行错误不会被“序列未消费完”覆盖。未知 token 仍被拒绝，正确回放使用原始回执。
- 来源反馈展示最近三次成功 `open_result` 的原始 `result_id`、页面标题、请求地址和实际打开地址，并明确这是历史观察。失效或未知元素引用提示重新 snapshot；仍无目标时，提示结合实际页面判断是否重选来源。程序不判断北仓一定错误，也不代选西仓。
- 清理 `replay.py` 原有的 `cast` 和动态无类型入口，用明确的只读协议及既有 `ReplayRecord` / `StateReference` 声明验证恢复数据。没有新增回执存储、运行时或持久化字段。
