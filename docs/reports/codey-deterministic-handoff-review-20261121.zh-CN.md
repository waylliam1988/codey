## 本轮接通的链路

- `open_url/source_search` 和浏览器导航复用冻结任务 URL，直接工具、CodeMode、序列化恢复使用同一解析；其他已授权来源仍可选择。历史请求按原版本解释，不能恢复时套用新合同。
- `run(command={check:project})` 选择本轮冻结的项目验证候选，由程序提供原命令和 cwd；不扩命令许可。修改后先刷新候选再捕获请求；刷新失败不暴露失效的便捷选择。普通命令和输出尾行数继续经过原检查。
- 所有带 `ref` 的浏览器操作复用当前观察的控件选择，包括 select/check/press/hover/inspect 和文件动作；执行仍校验原节点、文档和授权。
- 查询点击后重新验证的输入可重新提供当前查询候选，不重放历史动作。自然任务在重复观察且尚无已验证输入时，也可获得同一填写提示，不必由探针预声明固定工具序列。输入值始终由模型依据用户任务选择。
- 报告复用任务已声明字段的来源就绪判断。缺证据时不提供/接受 `answered`，可如实提交 `partial/unresolved`；文件尚未编辑不妨碍来源已充分的报告。新增冻结字段有版本，旧请求保持旧解释。
- 研究证据展示按合同和本轮固定上下文的剩余容量裁剪重复原文；不撤销原 passage、原读取范围和引用资格。

## 真实网页暴露的进一步根因

**重复计算采样 schema。** 原 diff 把 `response_format` 的 schema 序列化后作为提示正文计数。Python 文档站首测因此在真正发送下一请求前失败。对保留的原请求调用本地完整模板计数器，计数为 11,791；移除 `response_format` 仍为 11,791；将其作为正文单独计数为 7,264。现在预估只计算实际文本合同，provider 继续对真实完整 wire payload 准入；没有调大上下文配置或关闭检查。

**完整快照 revision 冒充进展。** worker 每次完整观察递增 revision，进度比较原来保留它，使同页同内容不断被认成新信息。现在仅在完整快照的进度投影中去除该计数；原回执不变，文档身份、文本、控件和任意业务计算值继续比较。直接 snapshot/read 也标记为观察，进入 CodeMode 已有的重复观察恢复分支。

**合法后继页被建议返回入口。** 共同交接原来只要当前 URL 不同就展示返回任务 URL 的建议，正常搜索结果和详情页也会收到。移除该建议；已有基于当前真实 404、空控件观察和原回执的导航恢复保留，并有负例覆盖成功页、重定向和不确定动作。

**过时测试提示。** 生产重复观察回归期待源码中已不存在的 `only observed control refs changed`。修复上述 revision 问题后，真实请求已有正确的重复提示和填写入口；测试改为核对当前提示，并继续检查整个生产流程、动作次数和实际结果，没有为了旧字符串改生产文案。

**连接存在不等于已有活动文档。** 自由顺序修复首测中，模型在导航前读取网页，worker 正确拒绝，却留下了已连接、无活动 target 的资源。后续内部 DOCUMENT 查询也抛出 `browser_not_bound`，使可恢复的工具错误升级为 controller_failure。现在未绑定活动目标时 DOCUMENT 返回 None；已绑定目标消失仍报错。真实 Chromium、空目标恢复和关闭原目标的负例均覆盖，没有捕获所有异常或自动换页。

**明确参考请求遗漏冻结来源。** 同一任务使用“请结合项目文件和 URL”，原解析器只识别打开、读取等动作，既未冻结来源也未提供原地址选择。补充明确的“请结合/参考/参照/对照/核对/依据/根据”及 consult/refer to/compare with 请求，沿用原否定、代码/引语排除和网络检查。裸背景标签“额外参考链接”不升级为必读来源；不强制使用浏览器或规定与本地检查的先后。任务文字不变后复测，未自动纠正错误 URL。

## 自然任务的顺序

先浏览再首次检查是合法工作方式。旧 `repair` 任务明确要求“先检查项目现有文件并运行项目已有检查”，所以其顺序判据只适用于这份明确指令；`repair_triggered_research` 也只能证明失败检查、正式读取、编辑的相对顺序，不能推出所有此前的浏览动作都不存在。

保留原任务和失败判据，另加 `repair-flexible`：要求真实来源、正确修复和既有项目检查，不规定浏览与首次检查的顺序。探针分别记录操作完成和明确顺序，不把基础浏览器 gate 的固定步骤覆盖当成自然任务目标。已有两次 `deterministic-handoff-natural-repair-*` 及第三次 composition 的成功记录已核对，未覆盖之前失败。

## 剩余边界

任务预声明字段的机械就绪检查已接入报告入口，但任意自然语言报告并不因此获得语义真实性认证。没有字段合同的任务仍可能引用实际读过但不足以证明结论的页面；书店首轮就是保留的例子。程序可以验证声明字段、原引用范围、版本、动作和检查回执，不能把有引用等同于所有推理正确。

模型仍可能空提交、选错入口、误写地址和过早结束。真实导航后的即时正文可能暂时为空；已有失败回执、观察与继续读取的路径有效，但没有用固定 sleep、站点特例或自动重复副作用掩盖。登录、验证和站点限制没有在本轮获得普遍保证。

自由顺序修复的真实检查通过，UI 完整性投影仍显示 `verification limited / monitoring incomplete`；不把一次项目配置的 unittest 成功说成完整环境监控。原有无关设计稿、报告和 README 改动未包含在本轮提交。
