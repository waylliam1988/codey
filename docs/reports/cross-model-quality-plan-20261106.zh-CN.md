# 跨模型最终代码质量复核：预注册与运行记录

## 用户目标与判断标准

只以最终交付的代码质量判断规划、前置 audit、consensus 和第二 advisor 的价值。
请求数量、token 和耗时仅作描述，不作为删除或不开启的理由。不运行全量 pytest。
任何失败先区分夹具/评估器、生产代码、模型行为和上游服务；修复后保留原失败证据。

## 本轮起点

- Git 起点：`97e4ea3d`，工作树干净。
- 原有相关回归：55 passed。
- 上轮自动规划的 `zero-inventory` 虽然 `no_progress`，最终独立质量 4/4、suite 通过；
  `cross-file-rename` 才是实际质量退步（2/4、漏改调用方）。不能将 3/5 完成率当作质量通过率。
- 连接预检：本地 Gemma4、Lightning、Solar 均真实返回 READY。Super 返回 HTTP 404；
  刷新 Cline 目录后仅有 Solar、Beam、Lightning，Super 已不在目录中。这是上游可用性变化，
  不是 Codey Review parser 的故障。用户已明确不要求固定某个在线模型。
- 固定本轮角色：本地 Gemma4 Writer、Lightning 第一 advisor、Solar 第二 advisor；
  Solar 作为各组统一的独立 Reviewer。Reviewer 独立于 Writer，但双 advisor 组中兼任 advisor，
  不将其宣称为第三个独立在线意见。Cline 是同一在线连接，不能把两种模型叫作两个独立服务商。

## 设计

- 10 个项目夹具：8 个新留出题与 rename/slug 两个旧回归题。
- 已有项目：跨文件改名、原子转账、递归配置隔离、事件版本去重、范围解析验证。
- 从零项目：slug、LRU、动态字典序依赖排序、假时钟过期缓存、闭区间合并。
- 每组保留生产项目地图与 coding current context；使用相同独立 Review、最多一次 Writer
  返修与二次 Review。Writer 总预算 32 turn，返修同时受剩余预算与生产 12 turn 上限约束。
- baseline 不加前置步骤；plan 加一个在线计划；audit 使用生产只读审计工具循环；
  consensus_one/two 使用生产 owner draft → 一/两个 advisor → aggregate。
- audit 仅已有项目，consensus 仅从零项目。已有项目 plan 是对旧失败的诊断性扩展，
  单独标记，不能冒充生产自动新项目规划的默认触发范围。
- 首批两轮，第二轮将每题 arm 顺序反转，共 70 行；题目顺序打乱，调度 seed 61106。
  seed 只控制执行顺序，未控制模型采样，不宣称模型输出确定性或统计性排名。
- 先做少量接线 pilot，不把 pilot 混入正式计数。扩大或复核的批次分别归档。

## 评估与证据

- 每题独立外部行为 oracle、生成/现有测试是否有效且通过、允许修改范围及必需交付文件。
- 最终 quality 与 `done/no_progress`、Review approved、实际 advisor 数量分别记录。
  保留所有失败、最终文件、工具事件、请求和原回复，不删除不利样本。
- 外部 oracle 不交给 Writer/Reviewer，也不作为自动返修反馈。参考实现仅验证夹具，
  不发送给模型。每个新题都有能被 oracle 拒绝的代表性错误实现。
- 先记录 Writer 初稿，再记录整个 Review/返修后的结果；主要比较后者，初稿作诊断。
- 检查需求遗漏、边界/原子性、调用方兼容、输入隔离、测试有效性与范围。当前没有经过
  盲评的可维护性分数，不用“测试全绿”声称架构、可读性和大项目质量均已验证。
- 保存真实模型身份、完整生产源码哈希、实验配置与顺序。配置/源码变化禁止混合 resume。
- 这是中小型受控项目实验，尚不覆盖真实大型仓库、长期任务或所有语言。

## 初始门禁

新夹具的参考实现/缺陷对照及调度、质量口径：首次 12 passed；Ruff 通过。
生产返修预算核对后新增上限回归，正式运行前补跑。

## 后续记录

运行结果、失败根因、修复、检查和提交记录在本文件及最终审计报告持续追加。

### Pilot 与合同预检

- Pilot 的 LRU 产品行为 6/6，但 Writer 生成测试把 `get(missing)` 的缺省值 `None`
  错写成字符串 `'default'`，然后连续提交无变化编辑并 `no_progress`。这是模型生成测试的
  真实交付缺陷；不是评估器期望过时，也不是生产编辑器丢了 patch。不手工改样本冒充成功。
- Pilot 的原子转账最终代码质量通过，但 Solar 连续返回缺少 `]}` 的 Review JSON。
  8192 输出预算实际只用了 209 token，不是客户端设置的长度上限；生产拒绝是正确行为。
- Solar 的独立流式/非流式诊断均能返回完整 JSON，说明不是必现的流式尾部丢失；
  其语义仍有误报，保留而不放宽 parser。
- Lightning 的默认 thinking 模式在正确参考候选的 Review 合同预检耗尽输出预算并
  `finish_reason=length`。目录声明它支持 thinking 开关，本轮正式实验将显式选择
  `thinking=false`，仅作用于临时实验连接，写入 metadata 与真实 wire，不修改用户设置。
  此后结论限定于该配置，不能外推默认 thinking=true 模式的表现。
- 原 21 项定向门禁、扩大 160 项回归均通过。Mypy 597 文件通过；Pyrefly 0 errors，
  35 suppressed / 81 warnings；ty 通过。不将警告描述成零。

### 生产问题与重启正式实验

- 第一批正式运行因真实 audit 待结算 effect 异常中断。已完成的行保留为诊断批次，
  不混入修复后的正式 70 行统计；中断时尚在执行的那一行不算已完成样本。
- 确定性复现确认：私有 audit 不应发起用户交互。收窄声明为四个只读执行器与 done，
  控制器同时拒绝 ask_user；提示明确当前需求属于 Writer，顾问只报告差距。未放宽结算守卫。
- 另修复跨连接 Reviewer 对禁用来源仍先读取目录的问题；筛选启用模型后才加载连接。
- 首次新增 TraceProvider 测试的 timeout 签名不匹配，先修复夹具，再确认与实机相同异常；
  新严格 gate 的重复终态负例还发现一个测试检查器 ValueError，改成拒绝重复终态。
  这些是测试代码问题，没有因此修改生产结算规则。
- 旧报告归档的 production smoke 实际 unavailable、无持久收据，撤回错误结论。
  新严格入口真实 headless 自动选择 Solar 并通过全部 11 项检查；它没有注入 Reviewer。
- 生产修复后的相关扩大组 119 passed，三种生产树类型检查通过，Ruff 通过。
- 修复后 audit 预检三题没有再出现待结算异常，但生产 4 turn 上限下两题仍未形成报告。
  为使质量实验真正得到可评估建议，正式重启批次明确使用 `--audit-turns 8`，总超时和
  只读权限不变；生产默认仍为 4，不把实验增配冒充现有默认效果。是否值得增配也按质量判断。
- 正式入口现在先写 metadata，支持在输出旁放同名 `.stop` 文件，在当前行完成后安全停止；
  未完成矩阵返回失败状态。首次因未提供该机制而中止的在途行不纳入证据计数。

### 用户进一步明确的收益口径

- 双模型合作的主要问题是：本地 Writer 单独生成的文件，与加入在线合作后的最终文件，
  哪个缺陷更少。统一 Review 的 stage A/B 继续用于区分规划/audit/consensus 的额外作用。
- Review 不追求找全 bug，也不要求最终 approved 才算有收益。独立检查证实修好一部分问题，
  且原先通过的行为、测试和范围没有退步，就记录该轮质量收益；还有漏检时如实列出。
- 完整交付通过率作为附加指标，不再用它掩盖部分真实修复。问题数和 oracle 检查数不同，
  不把恢复两条检查自动称为修复两个独立 bug。不以找全构造缺陷为由继续加长提示。
- 同一个 baseline 保存的 Writer 初稿和 Review 后最终文件提供严格的同候选比较。
  Writer 早期异常没有初稿记录时，其最终未审查文件仍纳入本地单模型对照，避免只统计幸存者。
- 二次 Review 只观察修复状态，仍最多一次 Writer 返修，不循环到 Reviewer 满意。
  收据/JSON 门禁衡量工程接线，独立行为检查衡量质量，两个维度分别记录。
- 已出现配置隔离样本从 4/7 到 6/7、已通过行为无回归；即使仍未全题通过，也应计为本轮
  Review 的真实收益。后续全部样本按同一规则重新汇总，而非只调整有利样本。
- 在线模型能力会影响合作结果；本轮结论限定到模型、模式和任务。弱模型的负结果不能
  直接证明协作机制普遍无效，单个正例也不能证明所有模型/任务默认开启均有收益。

### 额外校准

三个当前在线模型各审查相同正确/缺陷候选，分别记录协议、可信发现和误报。
初版配置 mutant 与初始代码相同，三个零 diff 观察只作夹具诊断；修正为正确参考实现基线后
再提交 mutant，重新得到真实 diff。新增四项回归验证参考与缺陷候选都确有 diff。
校准使用参考/构造候选，不冒充自然 Writer 缺陷或完整返修收益。

### 本地通信根因与第三批冻结配置

- 第二批保留 6 行后停止：范围解析的 Writer 在单次编辑中重复注释，32768 输出预算与
  实验 300 秒超时不匹配。超时后非流式后端继续运行，后续请求排队；用户关闭了后端，
  然后按原 `2.kcpps` 配置后台重启，另加 quiet 以控制日志量。这批不混入恢复后的对照。
- 真实控制探针对同一后端分别发送 2 秒超时请求：非流式客户端已退出，后端随后四次
  采样仍 busy，必须使用该请求独有 genkey 才能停止；流式断开后后端自动恢复 idle。
  空 body abort 在有队列时返回 false 是 KoboldCpp 1.117.1 的明确行为，不是成功取消。
- 生产接线问题：Gemma 原生工具规避措施将工具格式切换到文本时，也将已请求的流式传输
  关闭。现在保留原来的流式传输选择，工具仍走文本兼容；旧收据的 stream 不静默更改。
  真实生产 admission 复测 2 秒超时后恢复 idle、queue=0，没有额外 abort。
- 新增真实 HTTP 半帧回归：超时关闭连接，半截 edit 不进入历史，不重发请求。
  旧测试把 fallback 必须非流式当成要求，按已验证的传输合同更新断言；没有放宽工具解析。
- 第三批 70 行仍使用相同题目、角色、顺序、turn 预算和一次返修；仅将本地单次输出上限
  通过临时 ApiRunSelection 限为 4096，并记录 metadata。保留原有 context reserve/input
  边界，不修改用户持久配置。不用响应预算差异去混合比较旧批次的质量。
