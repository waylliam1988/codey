# 指定 CodeMode 子调用约束验收（2026-10-24）

基线：`dd08655f`。目标是修复“CodeMode 成功过、普通 edit 写过文件，就被当成通过 CodeMode 写入”的结构化验收缺口。验收沿用“本批有明确收益，且没有发现新增代码回归”；没有运行全量 pytest 或性能对照。

## 原因与约束表达

旧探针只登记 `tool_succeeded:codemode`。生产完成门准确检查了这个较弱条件，但它无法证明实际写入属于 CodeMode。以下两条路径都可以通过旧门：CodeMode 返回常量后普通 edit；普通 edit 后 CodeMode 读取。

本批把通用的工具成功谓词扩展为可选的参数选择和父调用绑定，仍保存在原有不可变 `TaskPolicy.required_checks`，例如：

```python
require_tool_success("edit", via="codemode", arguments={"path": "created.txt"})
```

其含义是：存在一条成功提交、参数 path 精确匹配的 edit 记录，并且这条执行的引用属于一条成功提交的 CodeMode 父调用。无父调用、父调用失败、子调用失败或目标不匹配都不能通过。

单工具成功观察和带父子关系的要求共用 `ToolSuccessRequirement` 的解析、匹配和说明，没有保留两套扫描器。结构化声明只有一个规范编码；畸形声明失败关闭。原有单工具成功观察仍保留自身语义，不自动升级为某种推测流程。

## 单一事实来源

- CodeMode 继续调用原来的 `execute_turn`。父调用只收集已经正式提交的子执行引用，将引用放在原有父结果回执的 `canonical.child_effect_ids`；不复制子结果、不新建关系表、不另写关系日志。
- 实时执行和恢复仍共用 `project_execution_record`。参数选择器比较从原回执参数派生的类型保真摘要；没有另外保存一份参数正文。恢复时工具名也通过同一个 canonical 名称投影，避免 live 的 read_file 与恢复 intent 的 read 被当成不同工具。
- 完成门只消费上述提交投影；不依赖调用 ID 的 `:child:` 外观、模型回答、console 输出、事件 metadata 或另一份工具结果缓存来补证据。
- 要求说明在 `prepare_kernel_turn` 从当轮冻结策略生成。初始说明和失败后的指导共用同一个 requirement.guidance；通用提示渲染器仍只渲染输入，不读取策略或新增 fallback。
- 结构化声明留在原策略中，proof 只使用从声明派生的固定长度 ID；400 字符正文选择器测试确认不会被 proof 的 80 字符标识符边界裁坏，也不会把正文参数带进 proof。

没有新执行循环、模型专用分支、自动代码改写、隐式普通写入替代、第二个运行时或第二份持久事实。

## 先复现与故障检查

基线通过 `git archive dd08655f` 独立展开，避免候选源文件影响原版运行。修正测试驱动遗漏的正式轮间交付后，`before-corrected-fixture.xml` 记录两条绕过路径在文本/原生入口的 4 项确定性断言失败；不是状态机异常。最早的 `before.xml` 混有测试驱动错误，不把其中的状态转换异常算作生产缺陷。

新增 22 项测试覆盖：两种协议的绕过路径、写错目标、子调用失败被程序吞掉、子写入成功但父程序失败、合法子写入、伪造 native call ID、程序返回伪造子引用、指导同源、长参数 proof、畸形声明、普通无约束写入、父提交边界及并行子读取。正常场景关闭并重开 SQLite，恢复原策略与已提交结果，重复恢复不重复累计。

父调用提交前中断不发布完成；涉及未知执行状态时，原有恢复流程返回阻断，不猜测成功或重做写入。父回执提交后、实时投影发布前中断，恢复可从原回执重建完成，文件不会重写。

## 并行投影竞态

实际 `Promise.all` 子读取测试暴露出一个已有竞态：两个工具都成功，但两个线程在提交前各自克隆旧投影，后发布的克隆覆盖先发布的读取。归档原版也复现：父结果包含 A、B 两份真实内容，live 执行索引只有一个 read_file。记录在 `artifacts/required-tool-lineage-parallel-baseline-20261024/result.json`。

修复为每个 TaskSession 共用一个进程内投影锁，仅串行保护“克隆、正式回执提交、发布”阶段；不覆盖工具 I/O。带双线程 rendezvous 的真实读取测试同时验证两次读取保持并行、两份回执都进入实时投影、冷启动后判断一致。锁不持久化，不产生新事实来源。纯渲染测试对锁使用 deepcopy memo，继续逐字段检查其余会话状态不变，没有为测试给生产增加复制兼容层。

## 验收与适用边界

最终相关 pytest：**223 passed、3 skipped**，记录在 `.e2e-artifacts/required-tool-lineage/acceptance-merged-candidate.xml`。3 项为原有旧 delivery fixture 跳过。Ruff、mypy（519 个源文件）、Pyrefly、ty、runtime 清单及 diff 检查通过；Pyrefly 原有 29 suppressed / 80 hidden warnings 保留。

本批提供的是**入口显式登记的完成要求**，不新增自然语言流程编译器。仅在任务文字里提到某工具，不会自动生成关系要求；未登记的任务仍按原有策略执行。参数选择是对提交调用参数的精确匹配，不额外实现另一套文件路径规范化。

父子关系检查约束完成判断，不撤销原有工具授权，也不保证此前完全没有普通 edit。它能证明指定子操作发生，不能单独证明任意程序的业务语义、输出转换、步骤顺序或最终文件内容；现有业务验收仍需分别验证。实机探针因此保留了独立的内容和真实调用检查。
