# 本地模型使用工作图：首轮实机对照（2026-11-19）

后续的[主动图查询试验与合入准备](agent-work-graph-query-20261119.zh-CN.md)已完成，另列可查询“研究约束 → 实现 → 验证反例”的实机结果及真实仓库规模限制。本文保留首轮背景检索实验的原始结论。

已用本地 **Gemma4-12B Q4_K_M** 跑完 3 个任务 × 3 个组的隔离实验。**本轮发现补充上下文能减少寻找资料和代码的请求，但没有证明图检索比普通文本检索更可靠。** 图组和文本组各用了 13 次模型请求；原流程用了 23 次。结果正确性分别为图组 1/3、文本组 2/3、原流程 1/3。

这不是“图无用”的结论：样本很小，当前图只是文件导入、文档引用和来源定位关系的初始检索。尚未测到完整的“证据条件 → 决策 → 实现 → 测试结果”工作图，更没有测到跨会话知识积累。可以继续实验，但目前不应据此把图接进生产。

实验新增[脚本](../../tools/agent_work_graph_probe.py)和[评分器及泄漏检查](../../tests/test_agent_work_graph_probe.py)。**未修改生产代码、全局模型配置或完成规则，也未复用两个参考项目的源码。** 运行所用的是当前工作区快照，包含用户原有修改；所有生产 Python 文件均保存了运行前后哈希，9 个单元之间也没有源码漂移。

## 实验方法

脚本先生成协议、模型预检、任务、资料、评分器和运行顺序，再发出模型请求。各单元有独立的项目、Git 初始提交、应用状态、知识空间和原始请求日志，模型自主选择工具和修改内容。使用真实 Codey headless 入口、生产 provider、kernel 及读写工具；仅在测试进程中替换网页搜索/获取结果，并通过既有背景上下文入口加入实验检索。

| 组别 | 新增上下文 |
|---|---|
| baseline | 不新增；保留当前生产流程的项目上下文与知识召回 |
| flat | 从可见文件和已观察来源节点做 BM25 文本检索 |
| graph | 相同 BM25 的前两个节点为种子，沿显式关系双向扩展，最多两跳 |

两种检索使用相同语料、最多 6 个节点、4,800 字符上限。实际上下文没有填满上限，文本组为 1,268–1,471 字符，图组为 1,591–1,845 字符。图组同时改变了检索结果和关系呈现，**没有做“完全相同片段，只去掉关系”的消融，因此不能把差异归因于关系文本本身。**

关系自动来自 Python AST 的模块导入、文件内的路径引用和 URL 引用。AST 导入关系不等于完整调用图。节点有内容哈希；未读 URL 仅为定位符。构图函数不接触任务评分答案、参考实现或未打开网页的 fixture 正文。它支持投影已提交来源和实际获取失败，但本轮原生工具连续对话中，背景入口每单元实际只被调用一次：**这轮只检验初始图检索，未验证运行中图刷新。** 网页正文随后通过正常工具结果传给模型。

模型为 `koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`，端点 `http://127.0.0.1:5001/v1`；temperature=0，原生工具，输出上限 4,096，单请求超时 180 秒，物理尝试 1 次，任务预算 8 轮，配置上下文 262,144。顺序按任务轮换为 baseline/flat/graph、flat/graph/baseline、graph/baseline/flat。仅每单元一次运行，没有重复采样和统计显著性结论。

网页是受控合成来源，任务是小型 Python fixture。**这是真实本地模型和工具执行实验，不是实际互联网检索、真实站点可访问性或浏览器 UI 自动化实验。**

## 结果与失败归因

编码任务由项目外的独立 Python 检查评分，保留原有测试，避免只看模型声称成功或可见 smoke test。研究任务先做关键词/来源获取检查，再人工核对回答的条件、引用与过时说明。表中编码分数是通过的行为检查类别，任务成功还要求未越界改文件，研究后编码任务还要求实际取得指定来源。

| 任务 | 原流程 | 文本检索 | 图检索 |
|---|---|---|---|
| checkout：跨文件修复渠道税额、Decimal 舍入 | 4/5；8 次请求；done | **5/5；6 次；done** | 4/5；5 次；stopped |
| relay：阅读 v2 资料后修改重试规则 | 2/5；8 次；max_turns | 4/5；5 次；done | 4/5；6 次；no_progress |
| cache：区分 v1/v2 和缓存适用条件 | **通过；7 次；done** | **通过；2 次；done** | **通过；2 次；done** |

`done` 是生产完成状态，不能替代产品正确性；文本组 relay 虽然 done，仍有边界错误。图组 checkout 的行为错误与后续 shell 拒绝也分别记录，不能把正确性失败都归因于执行环境。

**checkout：图把实现找到了，但没有让模型落实全部合同。** 文本组的初始检索包含合同、入口文档、预览及测试；图组沿引用补到了实现和调用入口，确实改善了结构上下文。但合同中 `ROUND_HALF_UP` 在两组的实际出站提示里都完整存在，图组仍使用 Python `round`，`Decimal('1.005')` 未得到 `1.01`。原流程也漏掉同一要求；文本组采用 `Decimal.quantize(..., ROUND_HALF_UP)` 后通过独立检查。文本组一次精确替换失败后自行恢复。

图组随后选择的 `pytest tests/test_smoke.py` 返回 2，改用 shell 命令时收到 headless 默认拒绝，任务 stopped。这是该轨迹的执行限制，没有为实验绕过权限或伪造成功。它在拒绝前已写入的实现仍可由项目外评分器检查，舍入错误独立成立。

**relay：找到来源和采用约束的差距更明显。** 三组都实际取得并收到了当前 v2 原文。原流程花完 8 轮，在未读目标文件的情况下尝试编辑，被正常读取前置要求拒绝，最后没有修改。文本组和图组都实现了状态/方法过滤和 2–17 秒截断，却没完全落实“仅 ASCII 数字字符串”这一条件。文本组用 `str.isdigit()`，允许了非 ASCII 数字；图组直接 `int(retry_after)`，还接受了整数对象和带正负号的字符串。

图组又重复执行不适合 fixture 测试形式的 `python -m unittest tests/test_smoke.py`，三次返回 5，最后 no_progress。因此本轮较短的总耗时不能解释成更高生产力，部分来自更少输出或提前结束。

**cache：检索收益成立，图的额外收益未出现。** 三组人工核对均正确：仅个人工作区、共享工作区禁止离线复用、最长 11 小时、凭据轮换立即失效、v1 的 72 小时全工作区规则已经被替代，并引用了实际读取的 v2 URL。文本组和图组都直接打开当前来源后回答，均为两次请求；原流程需要先遍历项目笔记，共七次。

Relay fixture 同时提供了一个不可访问的旧地址，但所有组都找到了当前地址，实际获取失败次数均为零。**本轮没有触发“失败后恢复”的路径，不能对图的恢复收益作结论。**

| 汇总 | 原流程 | 文本检索 | 图检索 |
|---|---:|---:|---:|
| 满足任务评分条件 | 1/3 | 2/3 | 1/3 |
| 模型请求 | 23 | 13 | 13 |
| 输入 tokens（服务端报告） | 182,779 | 109,868 | 112,423 |
| 输出 tokens | 1,273 | 1,799 | 881 |
| 单元耗时合计（秒） | 108.83 | 97.31 | 74.31 |

这些 token 是多次请求的累计输入，包含反复发送的历史，不等于唯一信息量或实际计算成本。表中“满足任务评分条件”也不等于完整端到端发布/审查成功，完整停止状态单列保留。

## 核查与证据

11 项离线检查通过，覆盖未读正文泄漏、提交来源入图、失败类型、编辑后内容哈希更新、结构邻居扩展、上下文上限、空输入、错误组名，以及评分器拒绝原始错误实现、接受参考实现并拒绝篡改测试。两个新增 Python 文件随后完成类型补齐、解除对未提交网页探针的依赖，Ruff、mypy、Pyrefly、ty 全部通过，类型检查目标为 Python 3.11。类型整理后的 11 项检查也全部通过；没有把类型整理误报为新增实机结果。首次实跑时的脚本与测试已保存为证据目录内的 `runner-original.py`、`checks-original.py`，旧协议哈希仍指向当时版本；后续复跑需使用新目录重新冻结协议。

对 9 个实跑单元的事后审计确认：生产源码无漂移、检索文本确实进入原始请求、首请求未泄漏未读正文标记、取得的研究正文实际进入后续模型请求、每任务各组的初始工具 schema 相同、没有 provider 错误、物理尝试均为 1，所有请求带本实验专用生成标识。研究回答也做了人工复核。

## 对后续方案的影响

继续保留[工作图设计](agent-work-graph-design-20261119.zh-CN.md)的方向，但把下一轮实验重点放在模型能操作的工作关系，而非只增加一份图形化文件目录。优先测试：agent 能有界查询某条研究约束依赖哪些来源、适用于哪些代码；修改后有哪些约束仍未被测试覆盖；来源更新后哪些旧结论需要重查。

这轮暴露的两个具体需求是“舍入方式约束 → settle → 舍入反例”和“ASCII 字符串条件 → retry_delay → 非 ASCII/非字符串反例”。这些关系必须从实际证据、模型声明和真实检查建立，不能由隐藏评分器预先提供。关系显示“声称采用”也不能冒充“测试已证明”。

下一轮可在测试进程中增加有界图查询接口，与同资料的普通检索工具比较；再加入完全相同片段的无关系消融、更多真实仓库任务及重复运行。另设明确会遇到获取失败和资料版本更新的任务，分别测浏览器恢复和知识沉淀。当前无需为了首轮结果改生产代码或实现完整图 UI。UI 后续应帮助检查来源、条件、受影响实现和验证空缺；是否能提高 agent 的编码与研究能力，仍由真实行为实验判断。
