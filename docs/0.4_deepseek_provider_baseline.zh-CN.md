# Codey 0.4 DeepSeek Provider Baseline

## 定位

这是 0.4 stabilization 的第一 provider baseline。它整理的是 DeepSeek 在
0.4.20 / 0.4.21 阶段已经落盘的 live smoke 证据，以及 0.4.21 后补跑的
`source_connector_ab.py --transcript-mode archive` 证据。

这不是统计意义上的大 A/B，也不是跨 provider 结论。它只回答三个问题：

```text
DeepSeek 作为第一个网页 provider，0.4 的 coding / research / ghost 闭环是否能走通？
已观察到的负信号有没有明确指向 Codey 生产 bug？
后续是否还需要继续烧 DeepSeek 全套？
```

结论：

```text
DeepSeek 第一 provider baseline 可以冻结。
不再重跑 DeepSeek 全套。
目前不需要因为这轮 Research/Ghost 结果修改 Codey 生产代码。
```

## Coding / Completion

DeepSeek core arms 已在 0.4.20 跑过：

```text
control_done
proof_only_block
repair_context
repair_context_minimal
```

实机证据显示：requested-verification 场景里，低层 agent loop 不应该一直要求模型把
测试跑到绿色；低层只需要保证最新编辑后至少观察过一次 run，最终 complete /
failed / blocked 交给 CompletionProof。这个问题已经修复并补了 deterministic
regression。

DeepSeek extended arms 已在 0.4.21 跑过：

| Probe | 结论 |
| --- | --- |
| `verification_review` | baseline 会批准合成 diff；current 能要求修改，并指出测试路径和 pytest。Verification Map 有正向信号。 |
| `read_before_edit` | baseline 和 guard 都成功；DeepSeek 本身已经先读后改，所以 guard 没有触发 block。 |
| `scoped_task_plan` | scoped arm 能命中路径/测试，但 prompt 更重；作为有用信号保留，不立即扩大默认 prompt。 |
| `impact_guard` | guard arm 少一轮、少一个 tool，并找到 refs；单样本正向，但不做夸大结论。 |

生产决策：

```text
CompletionProof / repair enforcement 保持现状。
不因为一个 extended smoke 扩大 prompt。
后续只在 transcript 指向明确 Codey bug 时小修。
```

## Research

| Probe | DeepSeek baseline 结论 |
| --- | --- |
| `bounded_research_planner` | planner arm 从 score `3` 到 `5`，且以 `no_new_material` 停止；这是 bounded planner 的正向 smoke。 |
| `research_comparison_benchmark` | deterministic comparison passed；只能说 OpenScience-style regression passed，不能说超过 OpenScience。 |
| `search_coverage` | baseline / coverage 都安全；coverage arm 更明确说明跳过了非 UTF-8 文件。 |
| `source_connector` | 初始 connector run 为 score `5` / `max_turns`，不能推广；随后 archive rerun 为 score `9` / `done`，打开两个 arXiv 来源并保存证据，说明 connector 可走通。 |
| `source_connector_done` | baseline score `9`，batch score `9`，但 batch 多一次 done 和 quality retry；batch/checklist 没净收益，不推广。 |

`source_connector` archive 补跑命令：

```powershell
python -B tests\manual\source_connector_ab.py --provider deepseek --case arxiv --arms connector --output tests\manual\results\0.4.21\deepseek\research\source_connector\connector_archive\result.json --max-turns 8 --send-timeout 180 --new-chat-timeout 90 --transcript-mode archive
# [deepseek arxiv connector] ok=True score=9 stop=done
```

复盘结论：

```text
connector 可用，但还不能证明优于 baseline。
source_connector_done 的 batch/checklist overlay 不推广。
proof review 仍严格报告 partial / claim-link gaps；这是严格 gate，不是本轮要放松的 bug。
Research 生产代码暂不改。
```

## Ghost

| Probe | DeepSeek baseline 结论 |
| --- | --- |
| `ghost_research_continuity` | continuity arm 证明 bounded continuity 能被 admission，旧 claim 带 stale/recheck 标记，且不作为 evidence；该 run 停在 max_turns，所以不声称完整 research completion。 |
| `ghost_continuity` | 当前用户请求能覆盖 continuity，Ghost 不扩大任务范围。 |
| `ghost_router` | plain-chat control 和 readonly-plan case 作为 no-regression control 通过。 |
| `ghost_signal_extractor` | extractor 能抽取 grounded style preference；baseline 不产生 signal。 |
| `ghost_work_queue_production` | no-queue control 和 research-item case 没有误触发 Research。 |

生产决策：

```text
Ghost 继续只作为 bounded hint / continuity。
不把 memory 当 evidence。
不让 work queue 自动触发 Research。
```

## 已证明与未证明

初步证明：

```text
DeepSeek 可以跑通 0.4 的 coding / research / ghost 核心闭环。
CompletionProof / quality gate 能拦住不完整完成。
Research connector 在 archive rerun 中能打开来源、保存证据并完成。
Ghost continuity 没有污染 evidence，也没有覆盖当前用户意图。
当前负信号没有指向必须修改生产代码的明确 bug。
```

没有证明：

```text
Codey 统计上优于所有 baseline。
connector arm 优于 baseline。
batch/checklist overlay 有收益。
DeepSeek 结果能代表 GLM / MiMo / Qwen / StepFun。
proof review 的 partial 结果应该放松。
```

## 后续规则

不再继续跑 DeepSeek 全套。只有下列情况才重新跑 DeepSeek 对应 arm：

```text
修复了该 arm 暴露的明确 Codey bug
改了该 arm 的模型可见 prompt / tool schema / harness schema
第二 provider 暴露的问题需要回到 DeepSeek 做交叉确认
```

下一步进入第二 provider，仍然保持：

```text
一个 provider
一个 arm
落盘 JSON / journal / transcript
先分析再继续
```

第二 provider 的目标不是“打败 DeepSeek”，而是确认 0.4 闭环不是 DeepSeek
特例，并尽早暴露 provider-specific 的 stall、UI、协议或 prompt 问题。
