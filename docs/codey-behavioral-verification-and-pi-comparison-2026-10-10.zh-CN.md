# Codey 行为验证与 Pi 实机比较

2026-10-10。原 20 个 Codey 场景完整验收 **20/20**，同轮 Pi **9/20**。
这轮实现了有限、明确的行为检查闭环，并补齐修复后的新观察、新测试和新 review。
最终全量 pytest **8295 passed、7 skipped、1503 subtests passed**。
用户重启 KoboldCpp 后，补充新文件/函数任务完整回放 **Codey 4/4、Pi 0/4**；旧超时记录保留。

这里的 20/20 是场景验收：包括修复、无需修改、正确报告只读阻塞、停止和恢复。
它不表示 20 次都完成了修复，也不证明任意未知任务或所有性能指标全面领先。

## 实现及证据归属

此前，“把标点替换为空格”的错误实现可能通过原测试，Local reviewer 也可能批准。
现在，对明确支持的 ASCII 删除要求，运行实际函数，比较连续字符中插入待删除标点前后的结果。
例如 `f("Qr7t") == f("Q.r7t")`：删除满足这个关系，替换为空格会产生不同结果。
所有 32 个 ASCII 标点共享一条聚合完成检查；原任务测试仍独立必需。
恒定返回值可能满足这个性质，不能据此替代原测试或宣称整个函数正确。

| 所有者 | 当前职责 |
| --- | --- |
| `completion/behavioral_checks.py` | 原始要求的有限准入，冻结任务/函数/输入身份，纯完成状态投影 |
| `operations/behavioral_verification.py` | AST 发现、实际权限、有界复制、进程执行、前后代码身份、归档 |
| `operations/behavioral_probe_worker.py` | 同步单参数调用，实际 JSON 值与异常，普通模块身份与 self-import |
| `project_review_phase.validate_candidate()` | 首次及修复后共同入口：当前观察 → 当前 review → 既有完成门 |
| 既有 ledger / ManagedOutputStore / completion contract | 定义、事实和详细结果各存一份，不增加数据库或第二套状态机 |
| `explicit_execution_requirements.py` | 从有限原始要求和真实回执投影执行顺序及已证实的只读阻塞 |

准入使用原文的明确操作与函数绑定，不接受模型选择规则、填写期望值或再次确认来代替依据。
已识别的条件、例外、错误对象、引用旧要求、疑问和歧义会被拒绝；未匹配形式不启用这个强检查。
当前覆盖是有限英文 ASCII 删除形式与根目录单参数同步 Python 函数，尚未完备解析任意自然语言
及后续修正句，也不是通用需求理解或完整参考实现系统。扩大范围必须先补准入与误拒绝测试。
未从“lowercases ASCII letters”推导非 ASCII 字符必须原样保留。

实际执行复用权限、取消、超时及进程管理。临时源码副本保护工作树，**不是主机沙箱**；
导入项目仍执行项目代码。函数异常、依赖缺失、绑定错误、超时和协议错误分别保留明确原因，
不可把未运行当成产品通过。结果读取限当前 session/run，验证 digest，不重新执行命令。

必需观察失败、缺失或过期时，其他通过项和 reviewer 批准都不能抵消。
完成门的有界修复获得实际反例；修复后重新核对原任务验证、执行行为检查并重新 review。
review 修改代码也使旧观察失效。未修改文件的验证任务同样能执行已准入检查。
原有 advisory review 语义未被改成第二套通用审批机制。

## TDD 与确定性修复

新增 10 个按行为命名的文件，共 89 项用例；完整索引见 [tests/README](../tests/README.md)。
首个闭环使用真实 Python 函数、真实 unittest 和脚本化 Writer/reviewer：错误实现通过原测试、
reviewer 返回 approved，实际性质仍失败并阻止完成；只有新补丁、新测试、新观察与新 review
才能放行。另有缺少修复后测试、恒定错误返回值、过期身份和权限反例。

确定性问题先红再修：

- 原文存在却绑定另一操作、条件/例外或旧引用：准入拒绝，不借模型确认放行。
- 行为观察未归档、过期或缺失：完成检查不通过；不掩盖原测试已经证明的产品失败。
- Windows 原子替换被临时共享锁打断：只对 WinError 32 重试，同一临时文件最多 8 次；
  重试期间目标改变则停止，其他权限和磁盘错误保留。永久锁仍可能阻止临时文件清理。
- 显式 once 的命令在相同工作区被重复执行：拒绝重复，并给出原结果引用；
  工作区修改后的新验证继续允许。
- 要求先读取保存结果却从预览猜值：真实关键词读取同时约束写入准入和完成门。
- 明确要求修复、写权限禁止、当前真实验证失败，但停滞只报告 no_progress：
  仍先触发原停滞停止，再按真实事实报告 blocked；取消、未知或过期结果不被改写。
- 固定 worker 的特殊模块名破坏标准 dataclass / self-import：保留正常模块身份，正确实现不被误拒绝。

早期只读测试夹具误把 ToolOutcome 直接交给要求 ToolResult 的内核；该失败不算有效测红。
修正夹具后，在禁用新终态投影时，真实失败进程仍错误停为 no_progress；启用后变绿。
缺浏览器、接线错误、语法错误、已经通过的保护用例均不冒充行为缺失的红证据。

## 实机条件与版本

原生 Codey 和原生 Pi agent 循环，全部使用 `http://127.0.0.1:5001` 的同一个 KoboldCpp。
模型为 `koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`，KoboldCpp 1.117.1。
Windows / Python 3.12.8 / Node 24.19.0；温度 0，配对种子 51/52，交替执行先后顺序。

- 窗口 32,768，输出 2,048，keep 12,000。
- 每 arm 180 秒，最多 24 次生成；Codey 的真实 Local reviewer 也计入预算。
- 不禁用完成门、review、no_progress、取消或子进程清理。
- 每次 arm 前后验证后端空闲；计时期间生产代码冻结，不并行跑重检查。
- 起始提交 `8faaa0f4bc702b0437c041b04c31bf06e11f521c` 加本轮工作树改动。
  最终生产 Python 字节哈希 `f180758c226fb70fb393848c22b7c88fbf4f257f0513cca56eb1e24938e979a7`。
- Pi 使用显式选择的既有 dist，CLI 1.0.0，dist 哈希
  `189b8f8868f437c28ebbbd6be6fa9e357b7047fd2aab484ff1e31abb34020eb3`。
  checkout 为 `a276dabe57911253350bffb93cb7d7aff6a73261`，**构建对应的源码提交未知**。

模型和种子相同有助于控制条件，但不能排除 prompt、工具 schema、可见历史及生成非确定性的影响。
Pi 能成功的一次不能单独证明差异全部来自 Codey 的确定性运行时。

20 个完整配对中，9 个双方通过，11 个仅 Codey 通过；两边本轮 false_completion 均为 0。
Pi 的 11 个失败中：8 个耗尽相同生成预算（实验代理随后返回合成 429），
2 个长输出补丁正确但没有完成指定中段读取，1 个续接产生错误补丁。
不能把这些失分统一解释成“模型语义能力不足”，也不能把补丁正确等同完整场景通过。

Codey 并非每个耗时指标都领先：

- 普通修复：种子 51 为 47.93s 对 85.17s，快 43.72%；种子 52 为 51.10s 对 30.69s，慢 66.54%。
- 503：38.65s 对 85.80s、72.99s 对 85.54s，分别快 54.95%、14.67%。
- 续接种子 51：55.18s 对 38.14s，慢 44.69%；种子 52 Codey 113.01s 通过，Pi 未通过，不作双方成功的速度排名。
- 改需求：Codey 31.11s、27.30s，Pi 16.14s、15.95s，Codey 更慢。
- 停止延迟：Codey 约 0.250s、0.234s，Pi 两次约 0.250s；整体任务墙钟仍含启动与生成。

Pi 流式 usage 不完整；原始已知小计保留，但不能把缺失当零，也不能公平排名累计 token。
本轮是 agent 稳定性比较，不重新宣称上下文压缩算法在所有维度领先。
