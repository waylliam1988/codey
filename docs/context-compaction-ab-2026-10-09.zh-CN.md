## 实现归属

| 位置 | 职责 |
| --- | --- |
| `providers/token_accounting.py`、`runtime/core/api_selection.py` | 有效输入上限取窗口扣除预留后的容量与已知独立输入限制的较小值；未知独立限制保持 None |
| `providers/context_ledger.py` | 分段保存已接纳协议事件、来源和检查点；哈希链、文件锁及原子 head；持久化失败不修改内存视图，过期写入拒绝提交 |
| `providers/context_checkpoint.py` | 按完整工具往返选范围；保护最新用户请求、最新工具交换和近期原文；仅缩减有可信结果引用的旧工具输出；重复行保留次数 |
| `providers/compaction.py` | 候选生成、来源校验、合法性检查、完整请求重计数与提交；追加尾部可以重定位并重计数，来源或代次变动则丢弃 |
| `providers/api_provider.py` | 80% 增长启发式触发后台维护；硬准入仍使用连接计数器；紧急摘要和回答一起提交；摘要失败不删除原历史 |
| `operations/kernel_prompt.py`、`tool_result_reader.py` | 每次实际请求前投影当前任务、文件和执行事实；只读当前任务已有回执，校验托管结果归属与 SHA-256，缺失不触发重跑 |
| `providers/zen/connection.py` | Zen 的辅助请求前缀、必需声明和内部闭合；计数包含实际请求外壳，核心不导入 Zen |
| `runs/trace.py` | 所有物理生成计入已知用量；摘要用途单独标识，不能覆盖正常请求的最后上下文计数 |

检查点使用自然的 `Current project state`，不插入固定的压缩提示前缀。原始事件与当前视图分开；运行时事实不由模型摘要改写。合并旧检查点时读取其原始来源，而不是反复摘要摘要。成功检查点的来源、计数和时间持久化；最近失败诊断保留在内存，不能宣称全部失败日志已持久化。

## 如何吸收参考项目

| 参考 | 吸收的原则 | Codey 的落点 |
| --- | --- | --- |
| DSH | 可追溯范围与提交事务 | 来源 digest、不可变段与原子 head、迟到候选校验 |
| Pi | 一个长用户任务内部切分 | Chat/Responses 完整工具单元，保留 reasoning 与 call ID 关系 |
| Wish | 计数与分段状态 | 完整请求计数、保留分段检查点、必要合并时展开原始来源 |
| Percho | 先做低成本输出缩减 | 可信回执引用下缩短旧输出；辅助输入对连续重复行编码，不改原始记录 |
| Codey 运行时 | 执行事实独立于模型历史 | 确切退出码、工作区验证新鲜度、结果只读工具，不靠摘要判断是否执行过 |

不引入厂商框架、迁移器、旧函数别名或失效后改用估算的路径。网页继续使用自己的估算 handoff；API 使用本连接准入和上下文视图维护。移除 Zen 的测试继续验证 Local 两种协议及规范化用量可用。

## 参考运行范围与限制

- 旧版 Codey：`8456c0c0870420d032be122b05afa4ca755bf729`。
- OpenCode：`ecc4916b5a9608c30e6dd58a67f2137b594407ca`，实际 `packages/core/src/session/compaction.ts` 选择/提示函数与 `util/token.ts`。

- Node 24 运行实际 TypeScript 纯函数，共用 Codey 的本地传输与输入准入；没有启动完整 OpenCode/Pi agent、扩展、分支会话或其全部自动恢复机制。容量失败只说明本回放边界，不能推导完整产品失败。
- `model-change` 是同一已加载模型重新连接；真正跨模型/协议仅做工作状态携带的确定性测试，没有跨模型质量实测。
- 验证了已完成 pytest 的回执与未闭合工具单元；没有新增异步命令监视器，也没有证明进程重启后仍运行的命令可被接管。
- 后台维护不持有前台发送锁，但单 GPU 摘要仍可能争用模型资源。回放各波次间等待维护，不能推断并发前台 P95 延迟。大规模长期归档的磁盘/启动性能也未标定。
- 一个本地模型、有限场景和 8K 逻辑压力窗口，不能证明全局最优或对所有模型全面优于参考项目。
