## 单模型验证后完成产品接入

一个实际使用的模型（当前本地 Gemma4，或后续实际使用的 API 模型）证明候选有净收益，且相关生产边界通过后，就完成正常消费者、正常入口和默认启用。无需第二模型，也无需把所有模型、预算和任务组合都测一遍才交付。

复用有效的历史证据，只补本次改动影响的验证。确定性的投递、删除、恢复或兼容性修复，以对应行为和回归验证收益，不要求额外创造模型 A/B。新学习、自动写回、排序或预测机制仍需证明所声称的收益；一次请求成功、格式正确或原型跑通，不单独构成这类收益证明。无收益的候选记录负结果并调整或终止。

验收通过后应在同一轮完成生产接线；不长期留在默认关闭、无人调用或只有实验开关的状态。只有已进入主分支、正常入口默认生效的功能，才标记 `PRODUCTION_MERGED`。

## 实验设置与生产条件分开记录

| 项目 | 实验证据应记录 | 生产规则 |
|---|---|---|
| 模型与服务 | 实际模型 ID、量化、endpoint、协议、版本 | 不因只测过 Gemma4 就只允许 Gemma4；本地状态随用户切换受支持的模型/API继续使用 |
| 输出与上下文 | 128、4096、8192等输出上限及窗口、reserve、keep设置 | 不按实验数值相等判定启用；遵守当前连接预算及正常admission |
| 流式 | 本次实测的stream值、回复和usage完整性 | 已验证的通用上下文默认供受支持的流式/非流式路径消费；只补新路径相关回归 |
| 消费者与scope | 实测入口、任务、用户/项目/会话范围 | 默认覆盖已接线且权限、来源、scope契约兼容的正常入口；用户偏好可跨项目，项目经历/目标仍限本项目 |
| 效果结论 | 样本、对照、指标、成本、限制和负结果 | 只声称证据支持的行为收益；未测其他模型不等于应关闭通用功能 |

默认启用依据功能、来源、scope、协议能力和当前可用预算，不依据精确模型名、API地址或实验输出上限白名单。新增的推断/学习消费者通过自身验收后，也按此规则接入；显式人工确认不会自动批准尚未验证的算法或整个family。

有界来源窗口、字符预算和上下文预算可以保留，并注明单位和用途。预算不足时按现有策略裁剪或拒绝来源；这不应变成“只有output=128或8192才开启”。API密钥、工具能力、权限和协议校验继续由各自生产边界负责。

## 限制必须有具体依据

只有已复现的不兼容或生产回归、明确依赖模型专有协议/能力，或当前预算确实无法容纳来源等情况，才对受影响路径限制、隔离或回退。生产回归可包括有对照证据的行为或成本明显退化；不能只以“该模型/数值/stream组合未单独跑过效果实验”为理由关闭通用能力。

每项例外必须记录：受影响能力和路径、复现或明确技术依赖、回退行为、解除限制的验证条件。优先按协议能力和实际边界判断；确需精确模型/版本例外时单独列明，修复后移除，不扩成所有未知模型默认禁用。

模型切换仍应验证payload、scope、当前指令覆盖和生命周期；可用离线HTTP/SSE fixture及相关正常入口回归完成兼容性验证。新provider需要其协议适配验收；本文不把尚未支持的API变成已支持。

## 保留的验收与交付要求

- 新实验前冻结目标、主要变量、模型配置、任务、对照、样本、指标和停止条件；不事后放宽scorer或把服务故障算阴性。缺失usage保持未知，不写成零或成本门通过。
- 验证本次涉及的真实发送、禁用、scope、过期、撤回、删除、重建、重启和故障恢复；不因全局大项仍为 `INCOMPLETE` 而重做已通过部分或扩大到无关矩阵。
- 当前明确指令优先；独立 `ContextSource` 和现有admission必经；Ghost/World Model不授予权限、不生成事实证据或完成proof。预测没有可靠判断依据时保持 `unjudged`。
- 保留用户关闭、故障隔离和回滚。产品不加载本地HF，不增加Ghost独立生成或第二遍最终回答。
- 按仓库要求完成受影响回归、静态检查及前端发布一致性检查；不运行全量pytest。每个可复查实验、负结果或生产接入及时单独commit。

每次交付分别填写：**实测证据范围、当前默认生产范围、确有依据的限制、消费者、关闭/回滚、检查结果、commit和剩余缺口**。不再用一个“支持的模型/配置”字段把证据范围直接变成产品白名单。

本文只修订后续工作规则，不新增生产实现，不重判历史实验，也不把未通过收益验收的World Model或自动学习候选标为已上线。当前已确认上下文的实现与边界见[通用生产入口记录](ghost_progress/portable-context-production-20261118.md)。
