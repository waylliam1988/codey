# 合同展示、定向纠错与本轮发现的边界

本轮以 `a1bba7865d4f523756f1a8872b6856af8c6a0080` 的独立源码归档为对照。
先落实合同展示与纠错交付两项，再按实测发现修复索引、终态和返回值诊断问题。
没有重跑 Pi、OpenCode 或 DSH，也没有放宽完成条件以换取通过率。

## 交付实现

- 文本合同按工具分组，用途只展示一次，参数签名从冻结 schema 生成，原示例保留。
  原生工具的说明、schema 和生成声明内容保持与对照一致。
- 协议错误通过原 ToolPlan 的工具身份选择同轮冻结合同。原生请求继续携带原 schema，
  不在错误提示中重复；文本模式提供当前工具的完整 schema。未知工具只列授权签名。
- CodeMode 的用途和生成目录属于同一冻结快照的不同展示字段。语法、输入和返回错误
  不再附整份子工具目录。返回错误仅展示本次已提交子调用的返回类型及原收据引用。
- Node 保留严格 JSON 返回验证，在原来的一次序列化中定位嵌套无效值，保留类型化错误码。
  不把 undefined 转 null，不删除字段，不修改源码，也不增加另一套验证执行器。
- 答案观察值不符时，短值直接展示 JSON 字面量，避免额外的 value 包装造成混淆。
  长值仍标记截断并引用原收据；完成门仍校验模型自己提交的答案。

## 发现并修复的边界

1. **目录时间戳不能证明成员未变。** 原索引在 Windows 快速创建文件时可能漏掉新文件。
   现复用原有界目录枚举，校验成员名称、类型、目录身份和枚举状态。没有监听器、
   全项目二次遍历或另一份文件事实账本。
2. **恰好触及条目上限的覆盖变化。** 从 N 个文件增加到 N+1，前 N 个成员可能完全相同，
   但完整性已经不同。目录摘要包含本次枚举的触顶和读取失败状态；原预算只消费同一
   目录枚举返回的记录。校验仍限于之前访问过的目录、原排除规则和条目上限。
3. **缓存格式也是身份的一部分。** schema 3 与策略共同确定当前缓存键。旧格式不读、
   不转换、不双写；当前键下损坏或不一致仍明确失败，不能吞错换路径继续。
4. **预算耗尽被外层记成完成。** 内核拒绝后，原持久化入口曾把 max_turns 归入 completed。
   现在直接使用已有统一终态判定，失败任务和 submission 不再被标为完成或已回答。
5. **返回字段不存在时缺少定位。** 实机曾成功写入文件，却返回 editResult.value.text，
   得到嵌套 undefined；通用 JSON 错误使模型重复原程序。现在报告无效值位置，并从冻结
   schema 提供实际调用工具的返回类型。成功子效果仍只保存于原收据。
6. **版本过期指引不够直接。** 两个原版本检查位置共用诊断，明确要求重新读取当前文件，
   不再让模型仅凭“使用最新收据”去重复提交旧版本引用。

目录校验不是文件系统原子快照，不能排除校验完成后的外部修改。成员校验也有实际 IO
成本；不能把缓存命中描述为完全不读取目录。
