# 借鉴 HyperResearch：Codey 研究获取流程的下一版候选

日期：2026-11-07。本文是可审阅的设计方案，没有修改生产行为或正在运行的 2A 实验，也没有新增模型调用。承接 [2A 等实验交接书](research-hyperresearch-ab-playbook-20261106.zh-CN.md)。

用户目标已明确：本地模型以研究质量为先，调用、tokens 和耗时记录为诊断，不再作为采用的一票否决条件。历史冻结合同与历史判定保留；新的质量优先决策单独说明。

## 目标与流程

把目前“连接器找到若干结果就可能停止扩展”的行为，逐步发展为：

```text
原问题
  → 从合适的渠道、不同角度寻找候选资料
  → 去重复，比较对象、版本、时间和相关性
  → 实际打开、核对材料身份，阅读关键内容
  → 对照原问题：还缺哪个事实、条件、比较项或原始来源？
      → 已有文章可能包含：文内定位、续读
      → 需要其他材料：定向补搜
      → 存在冲突：追原始出处、比较适用范围
  → 有依据的完整答案，或明确说明尚不能确定的部分
```

这些都是同一个 writer 可选择的动作，不要求每题按固定阶段执行。短问题找到充分原文后即可回答；复杂问题可反复获取和阅读。

## HyperResearch 实际提供了什么借鉴

完整档的 [width sweep](../reference-projects/hyperresearch/src/hyperresearch/skills/hyperresearch-2-width-sweep.md)要求多视角检索：基本事实、原始引用、限制/反例，以及按需的特定时期原始文件。学术查询之后仍执行网页查询，汇总链接后去重、筛选和分批读取，再按问题覆盖情况补资料。

[corpus critic](../reference-projects/hyperresearch/src/hyperresearch/skills/hyperresearch-8-corpus-critic.md)继续问什么材料可能改变当前判断；[写作资料选择](../reference-projects/hyperresearch/src/hyperresearch/skills/hyperresearch-10-triple-draft.md)按任务和写作角度选取材料。

其完整编排主要由宿主模型遵循 Markdown 步骤说明执行，Python 提供检索、抓取、存储、索引和检查。Python 语言相同便于理解和迁移窄功能，但研究方法不能靠直接 import 一个函数自动获得。不能把简易 `cli/research.py` 当成完整流程，也不需要复制 vault、manifest、三草稿和多 critic 才能借鉴获取方法。

## 五个最小改进点

### 1. 多渠道：让正确资料有机会出现

先保留当前 2A 的单因素定义：对适用的查询，专业连接器之外仍搜索网页，并合并去重。当前正式批次继续按冻结合同完成，不在里面加入新查询生成、排序或补搜。

后续扩展时，按题目选择渠道：论文可用学术渠道和作者/会议入口；工程版本问题侧重官方文档、仓库、发布记录；明确给定原文则直接读取。无需为了形式完整对每个问题查询全部数据库。

由现有 `search_factory`、connector/provider 和 `source_gateway` 负责获取。渠道失败保留其他真实结果，取消与网络策略沿用已有实现。

### 2. 多角度：不同查询分别服务不同疑问

由现有 writer 根据完整原问题选择下一条 query，复用 `web_search`，不增加必须先注册的计划工具。

例如研究某种长上下文方法：

- 原始论文：它提出了什么，实际测试了哪些模型与任务？
- 评估方法：测了什么，没有测什么？
- 限制和反例：什么情况下结论不成立？
- 对比：与另一方法是否使用相同设置？

不机械要求每题都搜“批评”；版本事实应定位版本规则，数字问题应找对应时间和口径。先前缺口提示候选未显示净收益，不能把换一种提示说法当成已经有效。任何新指导或调用安排仍是待验证处理。

### 3. 筛选：优先选能回答当前问题的材料

第一步做可解释的去重和身份展示：来源渠道、标题、URL、可取得的日期/版本及摘要身份。未知保持未知，不靠域名或模型评分授予事实正确性。

随后优先考察：是否是用户问的对象；是否对应版本与时间；是否能补当前缺口；是否为原始材料；是否与已读材料重复。

标题与搜索摘要只用于粗选，打开后还要核对。多个转述页面不能自动当成多份独立证据。筛选改进先用实验适配器验证，不立即引入庞大的综合质量评分系统。

搜索结果仍只是线索；只有真实阅读形成的准确片段才进入 eN 引用通道。

### 4. 阅读：围绕所问内容，而不是读开头就结束

沿用 `open_url`、`open_result`、`source_search`、`open_hit` 和续读能力。

问题要求方法、限制、是否继续某项操作时，摘要或引言往往不够。下一步应优先定位对应章节，而不是继续收集只重复概述的网页。只取得摘要时应保留摘要身份，不能假装全文已读。

当前精确版本、不可变阅读片段和原始回执继续作为依据。目录、模型摘要和覆盖提示都不能替代实际阅读事实。

### 5. 补搜：只追能改变答案的缺口

同一个 writer 在正式提交前，对照原任务判断当前缺口：

| 缺口 | 下一步动作 |
|---|---|
| 找到文章，但没有读到所问章节 | 在同一文章定位、续读 |
| 材料讲的是其他对象或版本 | 换准确对象/版本搜索 |
| 只有二手转述 | 沿引用找原始来源 |
| 两份材料冲突 | 比较对象、时间、条件和研究设置 |
| 比较问题只覆盖一边 | 针对另一边补搜、补读 |
| 允许渠道内仍无证据或新增动作持续无信息 | 明确交代未解决部分 |

没有搜索到反证不自动提高置信度；模型声明“已覆盖”也不是语义证明。避免原样反复搜索、重复读取开头来拖延交付。

## 代码职责保持收敛

| 当前所有者 | 保持的职责 |
|---|---|
| `search_factory` / `connector_search` / provider | 选择和执行获取渠道、合并结果、保留失败信息 |
| `ResearchSourceGateway` / `ResearchTools` | 实际搜索、打开、文内定位，形成回执 |
| `answer_context` / passages | 展示实际阅读材料与准确定位，预算内保留关键原文 |
| 共享 kernel / research writer | 决定下一动作、阅读和补搜、何时交付 |
| `answer_contract/report/archive` / publication | 原始完整提交、准确引用、显式知识更新、原子发布 |

保持一个研究执行循环和一个正式发布点。若确有必要记录覆盖信息，先从现有原任务与回执派生，不另建持久子任务状态机。外层的历史 proof/plan 诊断不重新取得执行或补搜权。

## 如何小步验证

不要把五个处理一次合进“升级版 2A”，否则无法解释哪个机制有效。

1. 完成现有 2A，单独评价搜索覆盖、正确原始材料实际读到、最终答案与控制题回退。成本按用户新偏好记录，不一票否决。
2. 冻结下一版基线后，分别研究多角度查询、资料筛选、关键章节阅读和定向补搜。复用同一个隔离实验框架，不建设新的研究运行时。
3. 每项先做小开发验证，确认实际改变了目标动作，再做新题比较。旧实验题可开发回放，不重新称未见题。
4. 区分获取、阅读和解释的改善：找到相关来源有独立能力价值，但不能据此声称整题已正确；writer 的固有理解错误也不能自动归因获取策略。
5. 最终采用判断优先看正确资料覆盖、必答项完成、重要断言支持和真实交付，保留全部新增回退并分析归因。信息更广、来源更相关可以支持最小获取改动，但不自动授权全套流程和未验证的评分器上线。

下一步最有价值的问题是：在允许多查的条件下，Codey 能否更稳定地找对材料、读到对应章节，并对剩余缺口继续采取有效动作。现有工具已经覆盖这些动作，工作的重点是获取策略和研究决策，不是重新建设一套架构。
