# Ghost 生产闭环、维护、恢复与研究分离

基于 `37dba3a5`。本轮按有限规模验证后默认交付的规则实现；不要求每个用户先填写实验报告，才能使用自己已经确认的记忆。旧六组试验保留在 [前次报告](memory-evolution-20261121.zh-CN.md)，不与本轮重复任务合并计分。

## 正常生产路径

1. 主调用在原有结构化 `done` 上提供可选 `memory_candidates`，不增加模型请求。原始回执保持原样。正文、执行参数和候选分别校验；候选错误不触发正文协议重试，整个 JSON 损坏仍按原合同失败。
2. Core 只从已接受、已交付的完成回答提取候选，绑定 submission 的原始用户输入。原话和 Unicode 字符区间必须逐字匹配；模型不能指定身份、scope、时间或来源。原生工具的关闭确认不替代原始完成回执。
3. 用户在抽屉、HTTP 或 CLI 确认具体版本。已确认的偏好、目标、假设及真实经历默认参加检索和正常发送，不需要额外类别晋级，也没有精确模型或配置白名单。
4. 请求冻结完整 item 摘要、来源、类别状态、选择理由、预算、冲突与挤出关系。物理发送复核当前来源、开关、生命周期和类别状态。独立 Core 工件记录实际 payload 摘要、JSON pointer 和字符位置；不修改冻结请求。
5. 曝光按请求引用、item 身份和版本区分。代码围栏语言是可观察特征，不是代码正确性。明确反馈可以绑定精确曝光与行为；run/item 的整体反馈保持 exposure-only，不能冒充因果证明。没有反馈不增加满意次数。
6. 确认代码语言偏好后自动建立有期限的行为预测；现有 Core 调度器到期复盘真实观察。矛盾只生成新的待确认假设，不覆盖用户确认。用户范围预测可匹配项目回答，但行为必须属于实际曝光的同一个请求。
7. 用户情境纠正仍经过候选、来源校验和确认。规范 slot/value 支持确定性关系；自由文本关系是 suspected_conflict，不自动撤回旧记忆。原内容、关系、双方来源和显式替代选择在抽屉展示。

类别管理支持 observed、shadow_candidate、production_candidate、enabled、demoted、quarantined、deleted。它管理正常消费者中的启用、降级与隔离，独立于单条确认。已确认声明的消费是 enabled 基线；显式降级后重新晋级可以引用小规模完整配对报告，不要求大样本或第二模型。隔离、删除和降级不能通过 shadow 预览绕过。实验报告是有来源引用的操作者声明，SHA 绑定内容，不构成第三方认证。

## 生产实现与研究脚本

| 方向 | 实际交付与消费者 | 限制 |
| --- | --- | --- |
| 同次提取 | 三种协议回归，正常 headless/API 接线，抽屉审阅 | 本地受测模型尚不能可靠产生合法候选，不能把回答里的“记住了”当作已保存 |
| 适应与纠正 | 确认记忆→真实曝光→行为→反馈→情境候选→确认→后续消费；统计按版本与情境限幅 | 反馈表示用户判断，曝光不单独证明因果；自由文本理解依赖模型候选 |
| 周期维护 | Core 原 scheduler 的中性 idle deadline；有界到期、预测复盘和终态补读；日志内维护/观察游标 | 忙碌期间让任务优先，维护不保证严格墙钟期限；start_scheduler=False 禁用自动执行 |
| 保留与恢复 | 版本化恢复基点、哈希链、原子安装与截断、secure_delete、VACUUM；SQL 有界普通维护查询 | 全局显式压缩与恢复基点仍可能随当前必要状态增长，不能宣称所有操作都是常量内存 |
| 类别与 Explain | 正常默认消费、独立状态机、完整冻结选择与实际物理尝试连接 | 发送前拒绝仍拒绝原请求，不重写原工件；不保证竞态下自动重新构建请求 |
| 修复经验 | Core 原始失败/action/check/版本/时间引用→显式 credit link→待确认经验→延迟回归隔离 | 缺少关联时只保存未归因事实；退出码零不证明修复；不是自动发现所有修复链 |
| World Model | feedback/behavior/verification 目标、版本与窗口匹配、到期 supported/contradicted/unjudged、样本与条件统计、复盘候选 | 可观察目标是有限集合；条件 Beta 统计不是模型 confidence，也不是通用世界预测或满意概率 |
| R0 | tools/memory_plasticity_mechanisms.py 与 probe 中 13 种离线算法，统一输入预算、重放、快照、删除和容量测试 | 研究代码不在 codey 生产包，不注册后端，不参与生产路由；合成数据结果不证明产品收益 |

生产依赖继续是 Core → Memory 合同 → Ghost 存储/算法。Ghost 不读任务库，不运行会话、任务、工具或第二套 scheduler。只有 app/memory_setup.py 装配具体后端。新候选校验、槽位注册、序列化和公开合同各有唯一来源。

## 存储承诺

所有持久业务更新均先追加 MemoryEvent，并在同一 SQLite 事务中更新投影。快照是日志派生的恢复基点，不是第二个独立写入权威；包括版本、覆盖序号/摘要、必要投影、删除水位、控制、游标和有界重试身份摘要。压缩先应用日志化保留策略，再校验并原子安装基点和截断前缀。事务失败回滚安装与截断；投影重建失败回滚原投影。

默认每 scope 保留最多 1000 条经历、180 天经历、30 天归档和 1000 个重试身份摘要；active 已确认条目保留。普通维护每批最多 100 个 item，公开请求上限 1000。每日或文件达到 64 MiB 时触发保留/压缩；64 MiB 是触发线，不是包含任意数量用户确认条目的硬容量上限。

压缩后承诺从保留基点和后续日志恢复当前状态。历史正文被物理清理后不再承诺完整历史重放；重试身份窗口之外的旧命令明确拒绝，旧观察受 intake cutoff 和删除水位约束。reset 是逻辑删除；需要物理清除 Ghost 历史时还需 compact。Core 对话、请求工件和用户自行备份由各自所有者处理，Ghost 不跨库删除。当前应用没有另一个 Ghost 备份写入器。

证据目录：`D:/codey-local-evidence/memory-adaptation-20261121-first`、`...-second`。每批 22 请求/22 回执，四个显式持久提取任务、两个临时任务，加八组配对示例任务。冻结协议、全部生产 Python 源码 SHA、scorer SHA、预算和任务；保留 wire、事件、状态和结果。两批是相同任务的工程复核，不能合算成 16 个独立留出对照。

| 批次 | 消费路径 | Rust 示例指标 | 提取结果 |
| --- | --- | --- | --- |
| first | 工具显式 shadow reader 试用已确认偏好，未持久晋级 | 记忆 5/8，对照 0/8 | 4 个显式持久要求均无合法候选；2 个临时要求均未保存候选，其中 1 个未完成 |
| second | 正常默认生产检索与发送，无 reader monkeypatch、无手工类别晋级 | 记忆 5/8，对照 0/8 | 4 个显式要求仍无合法候选：3 次缺失、1 次原话/位置错误被拒绝；临时要求仍未误写，其中 1 个未完成 |

三个记忆组未完成格均返回 edit，命中单轮预算停止条件；原始回执中使用 Rust 也不改成已完成通过。五份交付答案经人工检查符合对应简单任务；没有运行 Rust 编译器。对照的非 Rust 正常答案属于偏好指标未命中，不表示任务本身错误。临时要求的失败是 run 选择及预算结果，不是生成了持久偏好。

本地模型为 Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M，KoboldCpp /v1，temperature=0，输出 2048，上下文 262144/reserve32768/keep32000，非流式，每格最多一次生成。第二批平均 prompt tokens：对照 8756.125，记忆 8994；平均 completion tokens：90 与 127.125；工具记录的平均整格耗时约 7.11 与 8.43 秒。不声称节省 token、降低延迟或全面改善代码质量。

第二批只增强了可选字段说明和示例，没有放松原话/区间/执行合同；它未解决该模型提取不可靠的问题，保留负结果。最终工具还有一次纯类型注解修正，生产请求字节不变；协议中的 scorer SHA 仍标识实测版本，不伪称相同文件哈希。

离线机制证据：`D:/codey-local-evidence/memory-plasticity-20261121-first`、`...-second`。最终脚本为 13 机制 × 7 合成场景/9 查询，均完成快照和重放检查。频数基线 1/9，词法 0/9，Hebbian 3/9，temporal/eligibility/recurrent 各 2/9，decay/normalization/contextual/hierarchical 各 4/9，其余各 3/9。各算法覆盖、延迟、增长和操作代理数据保存在 results.json；这些是设计性合成题，不据此将任何机制装入生产。
