# 冷启动记忆的控制、重建、纠正和反馈

本轮扩展现行 `Core → Memory 协议 → Ghost`，不恢复退役的 Ghost runtime、daemon、队列或旧数据库兼容层。
Core 继续拥有执行、权限、Evidence、CompletionProof、最终发送与任务结算。实现边界见[说明](../memory-boundary.zh-CN.md)。

## 生产和测试修正

- 首次生命周期回归暴露空 journal head 的 JSON 键序与规范编码不一致；修正初始化，未放宽完整性校验。
- 删除水位只向前推进，乱序清空不能允许延迟旧事件复活；来源删除同步移除依赖的反馈、预测、曝光和判断投影。
- 提案/管理/清空重试复用 Core 已提交命令；已经过期但先前成功的同一提案重试不重新验证成新事件。
- 终态事件绑定原始 commit 时间及 submission 的最终答案，重复观察不会改变载荷或重复记账。
- 解释读取冻结请求，关闭当前检索后不会改写历史解释。所有 memory 管理记录在历史编辑前排除。
- 旧过期测试在到期时刻创建并确认提案，与新有效期合同矛盾；只将 fixture 的创建和确认移到前一天，没有允许生产接受过期提案。
- 类型清理覆盖本轮 Python 文件中的原有隐式 Any，使用明确类型和真实窄化，没有 cast、ignore 或关闭检查。
