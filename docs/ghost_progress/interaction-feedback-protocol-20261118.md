# 条件化讨论开头与用户反应预测：运行前冻结

日期2026-11-18。状态`DESIGN_FROZEN`；新实验，不重跑两个项目验证事实负结果。
前一消费者已在master提交`35fb56da`；本批不改它的模型/config边界。

## 用户可见目标与消费者

同样的方案问题，因为不同个人历史而先比较选项或先给推荐；明确纠正之后改变，
临时要求只在有效期内生效。真实消费者是shared kernel的单次native done回复，
测两种实际句子顺序，不以“提示已发送”代替模型行为。实验不宣称开放对话总体收益。

本地候选：保存明确人工偏好及绑定具体实际回复的反馈；按scope/情境/有效期选最近
合法依据；预测下一条可归因用户反馈会要求哪种开头；收到明确反馈后hit/miss review，
更新/维持有条件理解，再经独立有界来源影响下一次主调用。
这是一个简单的“最近明确反馈”规则及预测接口，不主张新增学习算法、Hebbian或神经机制收益。

World Model预测对象是**后续用户反馈要求的讨论开头**，不是已存在的项目验证状态。
字段含对象、情境、依据、创建时间、5个模拟时间单位的horizon及未校准confidence0.6。
预测不是用户事实、权限、evidence_refs或完成依据；不执行项目工具。

## 冻结矩阵与时间契约

20条独立合成个人经历流，不是20个真实用户。初始比较/推荐各10条，项目和来源独立。
10组当前方案题各配两条相反偏好历史；主要阶段配对题逐字相同，推荐选项不由个人偏好决定。
无开发集选参；全部20条为预定留出矩阵。确定性契约测试不计作独立用户或模型收益样本。
同一流三臂共享同一份当时已经保存的语义历史，不能读取之后的反馈：

1. `none`：没有个人历史或预测；共同缺省为先推荐。
2. `retrieval`：仅检索相同的已发生经历，含实际回复、明确用户原话、情境与有效期。
3. `forecast`：相同经历、位置及主调用出口，加独立用户反应预测投影。

每流5阶段×3臂，共**300次物理生成**。顺序按`(stream+phase)%3`轮换，
三臂全部完成后才写本阶段候选臂实际回复所收到的合成明确反馈；下一阶段三臂都可读取。
基线是共享候选交互轨迹的反事实对照，不冒充各自独立在线用户；统计单位始终为20条流。

| 阶段/模拟时间 | 回答时已知的个人历史 | 回答后才提供的反馈 |
|---|---|---|
| 0 / 10 | 人工明确初始architecture_plan开头偏好 | 绑定候选实际回复，明确改为相反开头，长期有效 |
| 1 / 20 | 已有上述永久纠正 | 临时改回初始开头，只到时间35 |
| 2 / 30 | 临时要求仍有效 | 明确维持临时要求，仍只到35 |
| 3 / 40 | 临时要求已到期，原永久纠正继续适用 | 明确维持永久要求 |
| 4 / 50 | 前四阶段的已发生经历 | 不提供反馈，review保持unjudged |

阶段0–3为主要个性化指标。阶段4是独立边界：10条换到无相关偏好的incident_status
情境，缺省先推荐；另10条当前明确要求与历史相反的开头。每组初始两偏好各5条。
当前请求优先和情境隔离不单独计作个人收益。

“永久纠正”与“临时改动”是预先锁定的合成反馈日程，不因模型表现生成有利用户。
预测评分比较后续明确要求的开头，不将预定偏好变化当成先前回答的任务错误。
实际回复必须可观测并绑定ref、scope、context和完整summary digest；无效回复、隐式反馈、
身份/时间不匹配或缺失反馈为unjudged，不应用状态更新。沉默、技术中断和日志缺失不算miss。

时间为冻结模拟钟，事件顺序与有效期由本地投影校验；真实wall-clock另用于调用延迟。
模拟TTL不是对产品任意日历时间、升级或并发恢复的生产验收。
JSONL每次冷读取并严格校验；由相同事件确定性重放。错误不靠猜测修复。

## 模型、通道与预算

`koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`，
`http://127.0.0.1:5001/v1`，OpenAI Completions/native tools，temperature0，非流式，
context/output/safety/keep_recent=262144/128/32640/32000，timeout120秒。
同一正常主调用，max_turns1，物理attempt1，仅control/done；不补发、不重试、不重启服务。
无HF、embedding、第二模型或第二遍正文。源经历预算2400字符、预测900字符；
截断或超过冻结预算直接INCOMPLETE，不偷偷改语义输入。相同当前问题明确列出两种完整
句子，仅句序不同；严格评分summary只strip外部空白后逐字相等，不剥围栏、不修回复。

候选直接使用既有KernelRunRequestBuilder、真实durable操作/managed outputs、
独立ContextSource与physical Attempt Gate；不修改生产profile，不将实验模块import到产品。
有收益后还要另补普通入口和本消费者生命周期边界，不能凭manual harness标记上线。

## 主指标、收益与停止条件

主统计为每流**四个主要阶段全部正确**的流数，另报告各阶段、初始两类、两边界组、
逐格正确及格式有效数；不把300请求当300个独立个人。

晋级门同时要求：

- forecast主要流≥18/20；比仅检索相同经历多≥4/20，比none多≥8/20。
- 初始两类的主要流各≥9/10；每个阶段≥18/20；两边界各≥9/10。
- 相对相同经历检索额外输入每格≤400tokens；forecast p95总延迟≤retrieval p95×2+1秒。
- 每流持久状态≤64KiB；完整配对、usage、全部预测/review记录齐全。

同时报告每格input/output tokens、物理请求、wire bytes、真实总延迟、可见回答时间、
准备耗时和状态增长。非流式可见时间为kernel返回，不冒充网络首token；流式未测不晋级。
没有因结果追加样本、更换主基线、放宽scorer或调整门槛的分支。
完整但格式错误的非空回复记错；空/截断、usage缺失、服务故障或不完整配对保存失败证据并停止，
记INCOMPLETE，不记模型阴性、不重试。开始/结束只读models核对不算生成。

如果相同经历检索已同样正确，则新预测接口没有增量收益，保留负结果并终止该候选；
不提交无人消费的生产模块，不将接口压缩收益说成新增学习机制。
如通过收益/成本门，再独立验收正常入口、用户关闭、真实来源撤回/删除/重建/恢复后接线，
仅受测模型/config默认启用。原中文、项目连续性、Hopfield及两World Model负结果均保持各自状态。
