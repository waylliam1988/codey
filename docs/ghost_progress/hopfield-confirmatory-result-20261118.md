## 能作出的决定

**目前没有用这个基础现代 Hopfield 实现替换 Ghost 的收益依据。** 它能改善相对普通向量检索的排序及部分模型行为，但没有超过开发集锁定的简单关联主基线；实际调用 Ghost 状态机制的适配组也没有落后于它。弱文本表示下，迭代还会拖慢第一次明确纠正的适应。

这是受测生成器、两种固定表示、有限参数网格和单一本地 Gemma 配置的结论。不能推广成“所有现代 Hopfield 不如 Ghost”，也不能推广成“Hebbian/关联图已被证明普遍更强”。这轮没有训练表示或投影，没有真实用户长期数据，没有 TB 训练；自动文本特征也不是预训练语义模型。

预注册的四个主比较均没有达到收益门。**实机只有 12 条独立经历流，不能把差一两题解释为稳定的总体劣势，也不能据此严格排除未观察到的罕见收益。** 按预定矩阵停止，未因结果追加质量试验、改题、换基线或调参。

## 比上一轮改进了什么

1. 开发集 24 条、测试集 96 条独立随机经历流；每流 14 查询。场景组合、事件数量、时间、少数例外、偏好与干扰均变化，不仅是置换动作标签。不完整线索在原概念层能唯一辨别目标；噪声题有唯一最高匹配目标。
2. 两种表示、三个种子；text 的 IDF 只拟合开发文本。参数与共同相关性门只在开发集选择，然后独立 SHA lock 锁定。
3. 所有组共享资格/情境/原始查询相似度门和空选。删除、过期有 before/after；不再让“只有规则能空选”决定网络比较。
4. 真正调用 Ghost SQLite、强化、明确替代、共激活、Affinity 与 directive 冲突处理/排序；每个新历史冷重开并 replay。输入结构化条件和回映经历的适配层明确单列，不伪称完整生产能力。
5. 模型同时给出 action/source。只有动作正确且依据 ID 真正相关才算 grounded 成功；碰巧选对偏好不通过。
6. 以经历流为统计簇，种子、快照和请求复用不当作独立用户；主比较使用 98.75% 配对 cluster bootstrap，另做保守敏感性核查，不把退化区间当确定性。

## 运行规模和参数

- 测试：96 × 14 × 3 seeds × 2 representations × 8 arms = **64,512 格**。
- 每种表示、每个 arm：4032 格；统计独立簇为 **96**，不是 4032 或 64,512。
- 开发集真实 Ghost 新历史存储/重开/replay：168 次；测试集 672 次；实机准备 36 次。另有真实 store 删除→冷重开→replay 为空的独立 probe。
- 主要简单基线由开发集在 cosine/linear/latest 中选择，两条表示均选择 **linear**，没有根据测试成绩重选。

| 表示 | 共同阈值 | cosine beta | linear beta/steps | Hopfield beta/steps | anchored beta/steps |
|---|---:|---:|---:|---:|---:|
| 提供的概念特征 | 0.60 | 2 | 8 / 3 | 2 / 3 | 2 / 3 |
| 自动字符 TF-IDF | 0.30 | 2 | 2 / 1 | 2 / 1 | 2 / 1 |

Hopfield 使用 `q_next=Xᵀsoftmax(beta Xq+prior)`，无迭代归一化；anchored 使用 `.25*q_original+.75*Hopfield(q)`，是单列变体。共同 `prior=-age/45`。线性关联为外积矩阵传播；不是把它冒充生产 Ghost 图。

## 离线：召回和排序分开看

主指标 hit@2：找回当前偏好的至少一条相关经历；无相关经历时必须空选。top1 是次要描述指标。下表百分比，包含共同生命周期控制题；不能据高总体成绩忽略困难线索子集。

| 方法 | 概念 hit@2 | 概念 top1 | 文本 hit@2 | 文本 top1 |
|---|---:|---:|---:|---:|
| 生产词汇评分参照 | 91.77 | 83.23 | 80.51 | 72.77 |
| 原始向量 | 99.95 | 94.59 | 87.85 | 83.95 |
| 简单线性关联 | 99.95 | 99.90 | 87.70 | 86.24 |
| 固定状态 | 64.24 | 58.88 | 52.13 | 48.24 |
| 最新反馈 | 99.95 | 94.59 | 87.67 | 84.03 |
| Ghost 状态适配组 | 99.95 | 99.95 | 88.29 | 87.33 |
| 现代 Hopfield | 99.95 | 99.16 | 86.78 | 84.85 |
| 保留原查询的 Hopfield | 99.95 | 98.51 | 87.45 | 86.48 |

概念轨的 hit@2 几乎满分，对不同排序的区分能力不足；不能把相同 hit@2 写成所有方面等价。Hopfield 相对普通向量的 top1 有改善，但简单线性关联改善得更多。此处 top1/precision 属于次要诊断，没有改成新的主要成功门。

文本轨的主比较（相对开发集选定的 linear，百分点）：

| 候选 | hit@2 差值 | 预注册 98.75% cluster bootstrap 区间 |
|---|---:|---:|
| Hopfield | -0.92 | [-1.56, -0.35] |
| anchored | -0.25 | [-0.60, +0.07] |

常规重采样分析没有正向收益信号；不能由 anchored 的区间跨零就写“证明等价”。Hopfield 文本轨平均下降约 0.92pp 是对该生成器/表示的观测，不是所有网络或真实用户总体定理。

困难线索子集尤其说明表示的重要性：Hopfield 的概念 cue hit@2 为 **99.65%**，字符文本 cue hit@2 只有 **13.37%**。这一巨大差距不能靠更换吸引子更新自动消除。text 轨仍只是词面特征，不能从它推断使用强语义表示时一定失败。

## 适应：新纠正有时被旧经历拉回

概念轨除固定状态和词汇评分参照外，全部组第一次明确纠正后就持续正确；没有 Hopfield 更快适应的证据。

文本轨，第一次纠正后的相关经历命中：

- cosine / linear / latest / Ghost 适配：**288/288**。
- Hopfield：**254/288（88.19%）**；第二次起 288/288。
- anchored：**282/288（97.92%）**；第二次起 288/288。
- 固定状态：0/288，之后也不更新。

288 是 96 流 × 3 seeds，不是 288 个用户。事后逐格核查 Hopfield 的 34 个首次纠正失败，涉及 16 条流：全部只取回校准期旧值；同样原始候选池中 cosine 能取回新纠正。anchored 恢复其中 28 格。两种文本 Hopfield 变体均为 beta2/step1，因此此处保留查询的差异没有混入迭代次数或 beta 的变化。

这与检索状态向旧模式聚集的解释一致；它也可能受到弱文本表示和反馈模板的影响，不能直接归因为所有现代 Hopfield 的固有缺陷。

## 实机：动作必须有相关记忆依据

固定 12 条测试流 × 每流 8 查询 × 两种表示 × 九组（含 off）= **1728 逻辑格**。实际 **340 次**物理生成，**1388 格**复用字节完全相同的请求。单次 temperature0、最多96 token；无重试、无截断、无格式错误，无第二次改写或模型裁判；**Ghost 额外生成请求 0**。

模型：`koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`。
端点：`http://127.0.0.1:5001/v1`。服务报告 max_context_length=262144；调用前后模型标识一致。

| 方法 | 概念 grounded 正确 /96 | 文本 grounded 正确 /96 |
|---|---:|---:|
| 词汇 | 78 | 59 |
| 原始向量 | 82 | 68 |
| 简单线性关联（锁定主基线） | 94 | 73 |
| 固定状态 | 59 | 45 |
| 最新反馈 | 83 | 68 |
| Ghost 状态适配组 | 96 | 73 |
| Hopfield | 93 | 72 |
| anchored | 92 | 72 |
| 无历史 off | 24 | 24 |

无历史组只在应该询问用户偏好的生命周期题正确，其余题不能无依据选对就过门。文本轨中 Hopfield 另有 6 格“动作碰巧正确、依据不相关”，本轮全部拒绝计为 grounded 成功。

Hopfield 相对原始向量的概念行为有 **+11/96** 改善，应该保留这个正向结果；它是次要比较，不允许把主基线从 linear 换成 cosine 以宣布过门。相对主基线两条表示各 **-1/96**；anchored 分别 -2/96 和 -1/96，未达到预定 +5pp 收益门。

实机只验证主模型选择响应方式及记忆依据，未执行真实编码/研究任务，也未经过生产 runtime/builder/admission/provider-send。source 正确是可检查的依据约束，不是对模型内部推理过程的证明。两种表示还会共享相同实机请求的观察，不能当独立复制实验。

## 统计上需要保留的不确定性

冻结程序在概念主比较上返回 [0,0] bootstrap 区间，因为每条流的平均差都为零。**这不是零不确定性。** 事后增加只读敏感性核查，不改冻结结果或成功门：若 96 条独立流均无非零差值，利用差值位于 [-1,1]，对未观察到的非零流概率给精确保守上界，98.75% 范围为 **[-4.46,+4.46]pp**。它仍只针对固定生成器、固定开发选择与 iid 流假设。

同时核查稀少正向流的最坏情况：总体平均收益不超过“流上收益为正”的概率上界。这个核查故意忽略已观察到的负向结果及小幅收益，因此很保守。文本两候选均有 7/96 条平均正向流，其上界约 **+15.55pp**；它说明常规 bootstrap 不能被宣传成不依赖分布假设的普遍排除。

实机 12 条流没有候选相对主基线获胜的流，但零正向观察仍对应约 **+30.59pp** 的最坏情况上界。它不是预测会有这么大收益，而是提示小样本无法排除罕见大收益。故实机冻结报告中的 `EXCLUDES_FIVE_POINT_GAIN_ON_THIS_GENERATOR` 只按预注册重采样解释；不作为有限样本、无分布假设的总体证明。

所以可靠的工程决策是“**未展示足以替换的收益**”，而不是“已经严格证明 Hopfield 没有潜力”。上述保守核查是明确标注的事后分析；没有拿它改参数、换主要终点或追加实机样本。

## 生命周期和成本

所有组无效原文暴露为 **0**。当前项目/明示情境、删除与到期过滤在共同入口完成；除固定状态未学习后来新增情境的 before 快照外，生命周期恢复/空选均正确。实机两条表示所有组的过期/删除查询均 24/24 正确。这解决了上一轮空选不对称问题，也说明不能把该成绩归功于网络参数遗忘。

340 个物理请求的模型延迟 p50 **1067.64ms**、p95 **1189.27ms**；服务 usage 共输入 **99,705 token**、输出 **9,406 token**。历史字符上限900，实耗最多183。模型延迟受服务缓存及本机环境影响；复用格没有再次计时，不作严格 arm 间排名。

原始微基准的 threshold0 过滤了负相似度，实际候选数是 **46/296/1108/4726**，不是名义64/512/2048/8192；原始结果保留未覆盖。发现后新增成本补测，**只对成本夹具禁用相关性门并断言实际数量**，在全部实机结束后运行，不改任何质量输入、选参或评分。

补测的 concept 已选配置（每 arm 冷建编码缓存，预热一次，再25次查询；含排序/渲染）：

| 8192 个实际候选 | 查询 p50 / p95 ms | 索引数组 MiB | 编码缓存数组 MiB |
|---|---:|---:|---:|
| cosine | 6.107 / 8.605 | 16.064 | 4.855 |
| linear | 6.336 / 8.385 | 16.564 | 4.855 |
| Hopfield | 11.524 / 12.559 | 16.064 | 4.855 |
| anchored | 11.194 / 11.571 | 16.064 | 4.855 |

Hopfield 基础实现没有减少 key 存储，保留 N×256 个 float64 值。tracemalloc 冷建峰值约37.7MiB；数组、编码缓存、进程 RSS 不混用。这是生成历史的实现开销，不是独立记忆容量、最优 kernel 性能或 TB 训练证据。
