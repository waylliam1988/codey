# 旧知识修订、长文章阅读：这次改了什么（2026-11-04）

**最终只保留“放得下就直接读完整篇网页”。修订方案发现新增回退，已从生产撤回，实验和失败证据保留。**

| 问题 | 旧办法 | 采用的局部改法 | 仍然没解决的事 |
|---|---|---|---|
| 修改旧知识 | 模型抄完整旧对象，再填要修改的版本 | 试过程序代填版本、只填修改字段，但没有保留生产改动 | 有时改了没答完；实机出现额外替代条目，补救又误伤正常新建 |
| 长文没读完就回答 | 每次默认只显示一段，靠模型判断是否继续读 | 已取到的网页全文连同其他原文放得下，就直接显示，不再让模型翻页 | 看到了仍可能理解错；超预算长文的阅读选择仍不稳定 |

这里的“改对”会查实际数据库，不只看模型说“我已修改”。“答对”还会逐题看正文，不只看保存是否成功。

## 1. 为什么这样改

### 旧知识：程序已经知道版本，就不让模型再抄

版本检查不能取消。否则别人已经改过的知识，可能被过时内容覆盖。

但模型成功读过一条知识后，程序已经保存了它的准确版本。实验原型因此不再要求模型复制版本号、全文、条件、来源和所有引用关系，只需这样的修改：

```json
{"commit_id":"edit-1","changes":[{"id":"准确的旧ID","title":"新标题"}]}
```

原型从那次读到的不可变版本补齐未修改的字段，然后仍走原来的权限、版本冲突和原子保存检查。**不是偷偷改用最新版本，也不是放宽版本检查。上述 JSON 是实验接口，不是当前生产接口。**

保存回执会留在下一轮输入里，明确告诉模型已经保存。重复读到新版本后再提交完全相同的内容，不会制造额外版本。

原型只改变严格整篇 Research 的模型接口，未增加任务分类器或“先展开工具”的步骤。后面实机出现回退，因此字段合并函数、新工具协议和追加保存回执均已从生产撤回，当前修订接口保持原版。

### 长文：能一次看完，就不增加翻页选择

网页已经取到了全文，默认显示 6,000 字符不代表模型真的看到了后面。旧样本读完开头就交答案，因此漏掉 checkpoint 和只读条件所在的章节。

现在先用同一套上下文展示函数和实际 tokenizer 预估：**当前全部已读原文，加这篇网页的剩余全文，能否放进工作视图预算。** 放得下才展开；不会先挤走另一篇原文，再假装全文放得下。

工作视图使用已有的半窗口预算，并受实际输入上限约束。明确指定读取长度、PDF 页码和知识库原文读取仍保持原行为。放不下或计数失败，就保留原来的读取窗口和继续阅读能力。引用和重启恢复使用的真实阅读记录也同步保留。

实现复用现有的原文窗口、上下文展示和回执恢复函数；把原有 tokenizer/预算选择抽成共用函数，供展示与读取共用。生产没有增加新工具或新的恢复阶段，但确实增加了预算预览代码，不能说源代码行数减少了。

## 2. 接入前的实机 A/B

同一题、同一 seed 对比。固定资料、固定知识库种子，使用后台 Gemma4 12B。先试的无收益方案也保留记录。

### 修订：有真实修改收益，但结束作答还不可靠

| 实验 | 观察到什么 | 处理 |
|---|---|---|
| 保留 `value` 嵌套，只由程序代填版本 | 三个有效配对都没有完成修订；模型仍套错参数层级 | 不采用 |
| 改成平铺字段，并保留保存回执 | 三个有效配对中，正确修改旧对象从 0/3 到 3/3；其中一份完成答案。另一个候选样本重复写出无变化的新版本 | 不能直接采用，补防重复检查 |
| 平铺字段，加拒绝无变化修改 | 两份追加别名候选都只改旧 ID 一次并完成答案；其中只有一个完整基线配对，另一个基线后端中断 | 曾试接生产；后续发现回退，最终撤回。不把中断样本拿来算收益 |
| 真正修正错误正文，两 seed | 旧版 2/2 答案文字正确，却没改旧 ID，还新建替代 claim；新版 2/2 正确修改旧 ID、保留其他字段，但 0/2 交付最终答案 | 如实保留“旧版答了没改，新版改了没答完”的限制 |
| 在回执里额外重复展示修改字段 | 两组都改对旧 ID，但各 0/2 交付；成本有增有减 | 无稳定收益，不再加这一层显示 |

最后那个正文修订对照，旧版请求 6 次、输入 25,124 token；新版请求 15 次、输入 62,511 token。**这一题的新版更贵，而且没有最终答案，不能只宣传数据库修改成功。** 修改动作的局部收益是真实的，但仍需验证其他环节有没有新增损失。

别名最终候选的有效配对是 seed 706：旧版未改完、未交付；新版改对且交付，请求 9→7，输入 33,160→26,416。只有这一对，不能外推为普遍节省约 20%。seed 705 的候选独立成功，基线中断，不算配对成本。

### 长文：关键章节的收益明确，代价是更多输入

两道长文题、两个 seed，共四个配对：

| 检查项 | 旧版 | 全文候选 |
|---|---:|---:|
| 关键全文曾同时出现在模型输入中 | 0/4 | 4/4 |
| checkpoint 的停止、进度、继续说明正确 | 0/4 | 4/4 |
| 整题严格合格 | 0/4 | 1/4 |
| 请求数 | 8 | 8 |
| 总输入 token | 34,438 | 48,708 |

**输入增加约 41.44%，收益是少漏读，不是省 token。**

仍判失败的正文包括：没有直接区分部分 checkpoint 与回绕、漏答“能否证明整页没测量”、把 only when 改成“当且仅当”。后一份还把 local 的“7 写者额度”称为“7 写者限制”，措辞不准确。全文可见解决不了这些理解错误。

### 普通查资料和新增积累的保护检查

首次积累两 seed、两组共四份答案，都正确保存新候选知识并保持准确原文引用。历史复用的四份正文正确，但都跳过了要求核对的旧主张/旧答案引用链，不能算完整任务通过；候选还多用了请求。因此没有全局省成本结论。

## 3. 试接修订方案后，为什么又撤回

第一次试接后，用新 seed 711、712 跑了 **14 次**不加候选补丁的实际生产代码：

- 六次修订的**目标旧对象都正确修改一次**，但完整交付只有 **1/6**。
- 其中一次追加别名，在改对旧 ID 后，又把连字符抄成下划线，**另建了替代 claim**。因此“只改目标、没有替代条目”的检查是 **5/6**，不能写成六次全过。
- 四次长文都看到了全文、checkpoint 要点都正确；整题严格合格 **3/4**。一个 SQLite 样本仍把只读的替代条件误解为替代回滚日志。
- 新增积累 **2/2**；历史复用正文 **2/2** 正确，但严格步骤只有 **1/2**，另一份跳过了旧主张的实际引用链核查。

其中一份长文经过多次引用格式修复才交付，消耗 7 个请求、75,895 输入 token。成功不能只统计最后一次请求。

另在隔离目录检出原始 `3393bc10`，补跑同一道别名题、同 seed 712：原版未改成、未交付，**但没有多建替代条目**。这是发现失败后追加的诊断，不能冒充预先登记的确认实验。

随后又做 **8 次 A/B**，尝试不再把“ID 不存在”自动当成新建；只有显式 `create=true` 才能创建。对照是临时的平铺修订版，不是最初原版：

| 检查 | 临时平铺版 | 显式新建候选 |
|---|---:|---:|
| 两次别名题正确修改目标、且没有替代条目 | 2/2 | 1/2 |
| 两次别名题完整交付 | 1/2 | 0/2 |
| 两次真正新建 entity 的数据库结果正确 | 2/2 | 0/2 |
| 新建题交付了正确的阅读答案 | 2/2 | 2/2 |

**补救版“答了，但没新建”。如果只看程序显示完成，就会把这两份误记成成功。** 因为这次出现具体回退，最后撤回整组修订改动。没有取消正常新建能力，也没有放宽身份或版本校验。

同 seed 的临时平铺版复跑也从失败变为成功，说明实际输出仍有波动；固定 seed 不保证不同运行的整份输入逐字相同。可确定的是具体保存行为和接口分支，不能把某个 seed 的全部差异都归因于一句提示。

## 6. 证据边界

每个场景只有两个 seed，是探索性实验，不是全面研究能力评测。

本轮共发起 **74 次实机运行**，其中 **71 次有完整后端记账**，另 **3 次后端中断**单独保留。这个数字包括未采用候选、试接后撤回、补充诊断和最终确认，不代表 74 次都成功。

原始运行保留在 `.e2e-artifacts/research-revision-*-20261104` 和 `.e2e-artifacts/research-longread-final-production-20261104`。可随仓库阅读的逐例正文、实际调用、数据库变化、token、源码身份及中断记录见[逐例证据](reports/research-revision-longread-20261104.json)。历史批次中 arm 名为 `production` 只表示当时没有实验补丁，不代表那套临时修订代码最终被保留。

前两批额外的修订/冲突知识库种子未纳入当批逐请求冻结清单；事后核对其数据库 SHA256 与来源实验已冻结的对应文件完全一致。后续批次已补入冻结清单。后端未完整返回的样本排除配对质量和成本统计，不按零成本失败或成功处理。

下一步应区分两件事：**让已经保存成功的修订顺利收尾**，以及**模型看过完整原文后仍然说错条件**。不能再把它们都归因于“没读到资料”，也不应为这两个问题继续堆重复提示。
