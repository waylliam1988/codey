# 0.5.11 发布验收：公共事件与真实恢复

日期：2026-10-03；本轮起点 `42f528a1`，工作区起初干净，源码版本已为 `0.5.10`。
通过门槛后按最新指示将源码版本改为 `0.5.11`；本次 commit、push、创建 `v0.5.11` tag 与 GitHub Release，不制作安装包。
[早期版本提交验收](release_0.5.10.zh-CN.md)作为历史保留。

## 实现范围

1. `AppContext.emit` 在公共出口补全运行身份、模式与精确状态；SSE 与
   headless 消费同一发布事件。机器事件与有界收据的纯投影移入
   `app/event_payloads.py`，CLI 使用规范工具名，不再复制 headless 运行补字段。
2. 恢复保留原任务提示并追加已结算结果。项目适配器明确传递是否打开新
   provider 窗口；新窗通过文本 handoff 接收事实，同窗原生结果仍按旧 ID 配对。
   原 call ID 留在持久收据中，不向新窗伪造孤立的旧 tool result。
3. `recovery` 发布场景由两个独立进程通过正式任务入口执行：编辑结算后
   `os._exit(75)`，第二进程从正式日志恢复、交付原结果、验证并完成。
   独立校验原授权、进程身份、精确文件内容、原测试未修改、编辑只执行一次
   和结果交付。Ghost 的存储 roundtrip 单独保留，不冒充任务恢复。
4. `tools/machine_contract_gate.py` 为 CI/本地唯一必跑清单；缺失、失败或
   skip 都不能通过。认证、授权、异常、原生 ID、来源状态、SSE 和请求诊断
   使用确定性故障注入。实机脚本仍使用生产 provider 与隔离存储。

## 已复现的问题与测试卫生

回归先锁定运行身份遗漏、原任务提示被恢复结果覆盖、新 native 窗口收到旧
孤立结果、验证收据把非布尔真值显示为成功、权威退出码被 audit 兜底覆盖、
终态模式记录未释放，以及重启 exchange 编号混淆诊断。
恢复 oracle 还先用反例确认：测试通过和哈希相等不能代替请求的精确内容。

正确的取消/连接/交付失败行为也新增锁定；这些初测已绿，不称为新发现的 bug。
模块回归中的旧私有 patch/投影入口已迁移到正式所有者；worker 环境变量在测试
中隔离，保留原完成断言，不添加 skip/xfail 或放宽完成要求。

## 证明范围

有限状态枚举只证明所建模交付状态与权限子集的不变量；真实日志和双进程
恢复覆盖明确的崩溃点。它们不能证明全库无 bug、无死代码或任何模型都可靠。
实机一轮成功不能当作长期成功率，也不证明回答质量、延迟或 token 改善。

## 实际验收结果

- 最近全量（变更版本前）：**7011 通过、6 跳过、1497 子测试通过，485.38 秒**，
  含真实 Edge UI E2E。第一轮有 1 个旧私有导入遗漏，迁移并保留失败记录。
- 后续发现 gate 按默认编码读取 UTF-8 日志，以中文收据和非 UTF-8 默认编码
  复现后修复。此测试与版本更新按最新指示只做定向验证，不再全量 pytest。
- 最终必跑机器契约 **206 通过，无跳过**；12 个新测试文件共 48 例，47 例进入
  上述全量，后加的 UTF-8 一例进入定向门。Ruff、mypy（365 文件）、compileall、diff 通过。
- 变更版本和 UTF-8 前完整实机矩阵：JSON/native 各 **13/13**，各 6 个客观产物任务
  **6/6**；变更后实际恢复复测各 **1/1**。当前端点报告 Gemma4-12B 模型名称，
  不证明其他模型或长期成功率，也不把 Ghost 算作模型任务成功。
- 有限枚举：1 个安全批次、2 个 provider effect ID 的交付图 **44 状态、134 合法边**；
  **512 授权子集 × 2 拒绝模式**。这是具体有限模型的检查，不是全程序无 bug 证明。
- 六个全量 skip 均是 Windows 不适用的 POSIX/O_NOFOLLOW 条件；必跑门没有 skip。
