## 1. 协议可靠性：不能把解析器失败当作语义失败

在此前四类错误候选上，分别让模型用普通 JSON 文本和 `submit_probe_plan` 原生工具调用提交同一套签名导出的探针结构。

| 指标 | 普通文本 | 原生工具调用 |
|---|---:|---:|
| 按原始严格协议可用 | 0/8 | 5/8 |
| 仅事后去掉完整 Markdown 外层后可解析 | 6/8 | 不替换原生协议结果 |
| 事后确认的有效数值反例 | 6 | 原始可用提议中 3 |
| 已知 token | 6756 | 7753 |

普通文本 8 份都带 Markdown 外层；其中 6 份内部 JSON 和签名绑定合法，另外 2 份内部仍不合法。因此 `0/8` 主要暴露实验解析器过严，不能证明模型没有提出反例，也不能据此宣称原生格式胜出。事后审计只分析固定输入和返回值，**没有重新请求模型、修补内部 JSON 或替换原始结果**。

原生组 3 次未产生要求的单个工具调用，说明原生工具协议也不是可靠性的保证。数值反例成立也不意味着整段解释或修复建议正确：区间任务中，模型给出了成立的等端点输入，却仍误称 `range(5,5)` 返回 `[5]`。

## 2. 新任务共享提议：合法输入不等于正确期望

7 次已知提议均可绑定实际函数参数，共 14 个探针；14 个输入都满足本轮任务定义。事后评分得到 3 个有效反例、3 个错误预期。正确候选 seed 82 的重叠计数提议在 KoboldCpp 中超时，结果未知。

共享提议在最终审核之前生成并冻结。两个候选审核组使用同一份模型提议：

- `native-data`：提供提议，不执行探针。
- `native-observed`：提供同一提议，并执行固定 Python worker 获取实际值。

期望值一直标为未核实假设；没有由运行时把模型期望升级为 oracle。未知提议也不自动补生成：该配对的两个最终组都看到提议不可用，故它不能证明“观察”的收益。全样本结果保留，另明确其信息不足。

## 3. 首次审核结果

| 指标 | 当前 Codey Reviewer | 仅提议 | 提议 + 实际观察 |
|---|---:|---:|---:|
| 错误候选提出修改要求 | 4/4 | 4/4 | 4/4 |
| 正确候选误拒绝 | 0/4 | 0/4 | 1/4 |
| 审核不可用 | 0/8 | 0/8 | 0/8 |

不能把三个组的 `4/4` 当成同等证据质量。两个候选组在错误重叠计数上都复述了错误数字：`"abababa"` 中 `"aba"` 应有 3 次，不是 4 次。它们指出 `.count()` 不计重叠这一缺陷是对的，但引用的预期数字是错的。当前 Reviewer 在该任务使用 `"aaaa" / "aa"`，准确指出应为 3 次而 `.count()` 返回 2。

执行观察组还把正确实现返回的 3 判为错误，并提出改变扫描范围的建议。这是**真实观察被错误语义预期解释**，不是执行器造假：原始回执确实返回 3；模型却把自己的 4 当作可信依据，并把不完整的第 6 个位置误计成匹配。

## 4. 完整修复与完成流程

三个组保留同一生产生命周期。无审核组只关闭实际审核调用；候选组只替换实验子进程中的 Reviewer。没有扩大生产命令权限、跳过完成门或用隐藏验收补写完成证明。

“合格补丁”要求原测试、隐藏验收、修改范围及当前代码的新鲜验证全部满足；“完整完成”还要求正常终止和可信完成证明。

| 指标 | 无实际审核 | 当前 Reviewer | 提议 + 实际观察 |
|---|---:|---:|---:|
| 合格补丁 | 4/8 | 6/8 | 8/8 |
| 完整完成 | 4/8 | 4/8 | 3/8 |
| 错误初稿修复后完整完成 | 0/4 | 0/4 | 0/4 |
| 正确候选完整完成 | 4/4 | 4/4 | 3/4 |
| 首次审核误拒绝正确候选 | 无审核 | 0/4 | 1/4 |
| 误完成 | 4 | 0 | 0 |

所有审核组最终 `app.py` 都通过了本轮隐藏验收；但当前 Reviewer 组有两次修改了禁止修改的 `test_app.py`，且最终验证对当前文件集合不新鲜，故不算合格补丁。执行观察组没有出现这两次越界，其 8/8 是本轮值得保留的积极信号，尚不能证明广泛稳定的提升。

八个错误候选修复臂均在 `max_turns` 停止，没有修复后的新批准及完整完成证明。记录包含工具参数错误、精确编辑尝试失败、重复读取和额外验证等消耗。上限 12 是事前固定控制，不能事后加预算把这些臂补成成功。此限制会压低完整完成率，不能外推为更宽预算下生产任务必然失败。

额外的正确候选失败是另一条路径：执行观察组误拒绝正确重叠实现；Writer 读取并运行原任务测试后，又请求 `python -c "from app import select; print(select('abababa', 'aba'))"`。项目命令策略拒绝，随后 shell 审批被 headless 默认拒绝，最终 `stopped`。代码一直正确，不能把安全停止计成成功，也不应为改善分数取消权限边界。

共享提议不能因为实验缓存而当作免费能力。以下把首次提议成本加回候选方法的独立部署账本，修复过程中再生成的提议也已包含在最终臂用量中。

| 阶段 | 当前 Reviewer | 仅提议 | 提议 + 实际观察 |
|---|---:|---:|---:|
| 首次审核已知 token | 9560 | 至少 18290 | 至少 26259 |
| 完整修复已知 token | 102280 | 未设此修复组 | 至少 143175 |

候选组总成本不完整：未知生成不能记成零。完整修复的已知部分已比当前 Reviewer 多约 40%，尚未获得更高完整完成率。固定候选作者成本不计入各组；无审核的零模型增量只是固定作者不需再发模型请求，不能解读成自然 Writer 写代码零成本。

KoboldCpp 重启及第一请求冷启动影响耗时；报告保留原始耗时，不宣称公平的速度胜负。语义配对的任务、源码、共享提议相同，但临时项目路径和执行元数据不同，最终提示并非逐字相同；这也限制了单个差异的因果解释。

## 6. 问题归属

**实验脚本：**

- 严格 JSON 文本解析把 Markdown 外层当作不可用；已用事后只去外层审计说明影响，没有改写实机结论。
- 不执行组的评分器越界访问不存在的观察。新增测试先红（`IndexError`）后修绿，改为 `actual=null`、语义评分未知。仅更改事后评分；修正及前后 hash 已登记在续跑审计，原始 23 行保持一致。
- 第一次未知生成后，父进程在等待后端空闲时没保存该臂的精确结果。按真实子进程记录与 HTTP 日志补一行未知，保留缺失时间、退出码及证据为空，不伪造事实、不重跑。
- 轮次限制与固定作者是实验范围约束，不能据此判断 Reviewer 在所有真实任务上的净收益。

**模型：**

- 错误计算重叠次数，并在看到真实结果后仍坚持错误预期。
- 正确识别最后匹配缺陷，却混入“反转列表索引”这类不完整修复建议。
- 修复时使用错误工具参数、越界修改测试、重复读取或请求未授权临时命令。

**生产流程：**

- 本轮表明现有完成门没有把这些未完成修复冒充成功；审核确实阻止了无审核组的四次误完成。
- 当前通用 review 仍属于模型判断，没有确定性自然语言 oracle。真实执行只证明实际行为。
- 本轮没有建立“某一生产内核规则必然错误”的固定复现，也没有修改生产代码。预算耗尽或权限拒绝不能直接判为内核 bug；若要优化收尾，仍应单独建立确定性测试和真实任务证据。

## 7. 下一项值得验证的收缩方案

保留签名绑定、固定执行器、代码身份与原始要求，**让最终 Reviewer 看输入、实际结果和原始要求，不携带提议者的预期值及带结论的解释**。提议者负责找输入，最终判断者独立解释需求。只删除一个 `expected` 字段不够：本轮 `raw_plan` 和 `alternative` 也会泄露同一错误预期，必须一起隔离。

这仍只是一项待验证的候选方法，不能声称消除了小模型语义失误。下一轮应预先固定新任务、正确候选、正常输入对照及足够支撑后续 review 的相同预算，比较误拒绝、有效发现、范围保持、合格补丁、完整完成和全部增量成本。不要为此次重叠例子写生产特例。
