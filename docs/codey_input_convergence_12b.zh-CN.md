删除了 edit 的重复允许字段表，新参数沿原 schema 验证。未知字段仍拒绝，不静默删除
thought、justification 等字段来隐藏错误。

变更跟踪按任务隔离，Git 与非 Git 都保存原始基线，工作区写锁仍共用。全仓库 dirty
集合只用于工作区展示，不再证明“本任务修改过文件”。失败编辑预先捕获的基线不单独
声明文件归本任务所有；确认版本与当前内容不符时阻断。恢复 UI 只选择已绑定的作用域。

已有文件的整文件更新必须提供 content 和 base_result_ref；引用必须是同任务、同路径、
完整且未截断的读取收据。部分读取、跨文件引用、过期版本、删除的目标及越权均拒绝。
失败的 replacements 不自动变成覆盖操作。该检查是乐观版本保护，不是跨任意外部进程
的文件系统原子比较交换。

调用方可用 `--output-format json`，并可用 `--output-schema '<JSON schema>'` 声明已有验证器
支持的 schema 子集。HTTP、直接调用、headless、异步 admission 和冷启动 dispatch 传递同一输入。
普通文本默认没有 JSON 约束，不通过自然语言猜测器生成另一份输出策略。
完成门拒绝围栏、重复属性、非有限数字及 schema 不符，不自动改写答案。
格式正确不能普遍证明语义正确；观察值绑定仍由原显式 ToolSuccessRequirement 负责。

## 慢与反复报错的实际原因

此前每轮将变化的时钟放在消息开头，工作观察也由 Provider 可变状态插入并重排。
现在时钟和观察追加到当前轮，历史消息保持稳定。多文件任务前两次请求的 messages JSON
共同前缀从 89 字符变为 5,974 字符。这是请求侧指标，不等于后端模板的实际缓存 token 数。

原先的单变量探针已经记录在 `convergence-20261025/prefix-probe.json`：约 7,361 token 的
相同输入、输出上限 1 token，仅改变开头时间，首次/改秒约 5.6 秒，完全重复约 0.30 秒，
三对记录。它说明该后端对稳定前缀敏感，不能直接当作完整任务加速倍率。

工具声明去掉重复的完整参数 JSON，保留从原 schema 生成的必填参数和结果签名。
多文件任务首轮工具 JSON 从 10,164 降至 8,810 字符，约减少 13.3%。首轮 messages
从 6,401 到 6,446 字符，不能声称全部输入减半，也不能把字符数当成 token 数。

原生失败轨迹中的实际参数是 `{"args":{"query":"needle","path":"lines.txt"}}`。
原生函数需要参数对象本身；这不是 justification 白名单问题。旧代码虽生成完整修复提示，
却在原生错误回执路径只发送简短错误，导致模型收不到提示、继续重复错误。
现在原生入口明确参数层次，修复提示随同一批错误回执的末条 user_content 发送，原错误
内容和调用 ID 保持原样。不存在自动拆壳或把未知字段丢弃后执行的分支。

## 历史 Codey 与本轮实机

模型仍为 `koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`。
主轮通过原 headless/CLI、Provider、工具与完成门执行；temperature=0、seed=41，
上下文 32768、输出上限 2048、每任务最多 24 次生成请求、240 秒。
修改任务保留原任务内验证，并由独立 oracle 再检查两个模块与未改动的测试夹具。
只读任务不向运行时注入标准答案，只显式增加 JSON 输出要求。

| 同一任务 | 此前 Codey | 本轮 Codey | 本轮结果 |
| --- | --- | --- | --- |
| 含引号完整行 | 9.52s / 2 请求 | 7.35s / 2 请求 | 内容与裸 JSON 正确 |
| 范围、glob、排除目录 | 19.99s / 4 请求 | 10.48s / 3 请求 | 内容与裸 JSON 正确 |
| 第二处命中后的两行 | 18.05s / 4 请求 | 10.04s / 3 请求 | 内容与裸 JSON 正确 |
| 修改两个模块并验证 | 130.57s / 17 请求 | 46.79s / 12 请求 | 两模块正确、任务内测试与独立 oracle 通过 |

本轮主任务 4/4 严格通过；历史只读 glob/后文虽然内容正确，却带 Markdown 围栏。
多文件耗时本轮减少约 64.2%。生成 HTTP 总耗时从 118.25s 到 35.29s，累计首字节等待
从 76.05s 到 14.14s；首字节等待包含后端排队和生成首 token 等成本，不是纯 prefill 测量。
稳定前缀、声明体积、请求数和具体编辑轨迹均有变化，不能把全部收益归因于其中一项。

这是历史基线对照，不是控制冷缓存的多次配对统计。崩溃后测试与模型进程串行，TEMP/TMP
移到 E 盘；历史夹具在 C 盘，临时路径及缓存状态也不同。本轮数据证明这些样本改善，
不保证所有模型、仓库和任务都有同样倍率。

## 失败样本与边界

诊断轮全部保留，没有将失败样本换成后续成功样本：

- 过度删除 CodeMode 参数提示曾诱发缺参数；最终签名恢复必填信息，但仍只由原 schema 派生。
- 引号搜索示例诱发模型给无引号查询增加引号。删除该示例，改为原样保留参数的通用规则。
- 文本整文件更新曾把真实换行放进 JS 单引号字符串，编译阶段拒绝，未执行子工具。
- 模型曾使用 result.matches，实际结构是 result.value.matches；最终合同明确数据所在层次与空数组。
- 原生协议曾重复携带 args 外壳；回归确认修复提示丢在错误回执路径，已修正实际交付。

以上修复均通过合同、原消息交付或原 schema 完成，没有剥引号、重写参数、修补 JS
源码、自动切换编辑模式或放宽完成条件。

## 最终验证及仍然存在的模型边界

- 串行定向集合：401 项测试、472 个子测试通过。
- 最后原生提示/错误回执交付修改后：181 项测试、405 个子测试通过，包括原生/文本轮次、
  生命周期、协议关闭、任务范围、完成门和“拒绝 args 外壳后只执行一次正确读取”。
- 合同澄清及无绑定作用域的 UI 选择：79 项测试、64 个子测试通过。
- 上述集合有重叠，不能相加宣称覆盖了更多独立用例。架构上限没有调整。
- 最终 Ruff、完整生产代码 mypy（532 个文件）和 git diff --check 通过。
- 最后原生实机矩阵 9/10；同一最终文本路径的上一轮为 10/10。此前整轮 20/20 的样本
  也保留，但不能替代最后一次原生失败。
- 最新未跟踪 Git 仓库实机：6.38 秒、2 请求，完整带引号文本与裸 JSON 正确，正常退出。

矩阵包含读、创建文件、带读取版本的整文件更新、写停止、字面量/引号/正则/空结果/
上下文搜索和搜索停止，同时校验回执、恢复后的完成判断与重复恢复稳定性。
最后一次失败是原生两文件读取：模型反复 `console.log`，没有 `return` 数据，并搜索
本就不存在的 console 输出，最终达到轮次上限。子读取回执存在，父程序返回 null，
完成门没有放行；读取成功不能代替答案内容正确。没有将 console 接成另一份程序结果，
也没有将该失败当作成功或偷偷多跑一轮覆盖它。

工具合同改动会影响 12B 的采样轨迹；单次矩阵成功不保证下一次全部成功。原生参数
层次、错误反馈交付等程序问题已修复，模型生成 JS/参数/最终答案的失误仍需由现有
合同、回执及完成门拒绝。更普遍的语义正确性不由这轮修改保证。

崩溃前的广一点旧 server 探针另有四个 shell 相关失败，涉及被 mock 的 shell 版本探测和
审批接口返回 409；这部分没有纳入本轮修复，也没有据此断言它们与本次修改有关或无关。
本轮没有运行全量 pytest，完整仓库验证仍由用户安排。
