## 已观察的测试问题

- 首轮旧 HTTP 测试按完整字典相等断言，无法容纳新增获取链；更新测试契约，未删除失败断言。
- mypy 指出失败 canonical 推断为 `dict[str, dict[str,str]]`，不能放 JSON 获取链；改为明确 JsonObject，无 Any/ignore。
- 浏览器函数增加失败事件后触发复杂度门禁；将单次导航诊断与失败正文处理拆出，不新增运行时或状态库。
- 发布回归在本轮继续编辑生产文件期间触发 `REVISION_CONFLICT`，属于快照一致性检查按设计拒绝；冻结生产代码后重新验证，不能放宽生产检查。
- 比较脚本最初 HTTP 夹具缺 `geturl()`，旧版报接口错误。该样本 `.e2e-artifacts/spa-acquisition-20261108/old-site-spa` 作废；补接口后旧版获取预检已得到预期 `page_blank`，重跑使用 `old-site-spa-valid`。
- 真实网站原始问法首次：正文获取和模型交付均成功，但最终回答遇到 `GenerationUnknownError` 超时，不能算回答通过。KoboldCpp 性能端点显示 248 token 生成耗时约 194 秒，超过原来 180 秒预算；正式固定来源对照各版本统一 600 秒请求预算。

## 当前实现细节

- 现有 BrowserWorker 拥有全部 Playwright 操作；普通聊天懒加载独立 headless 上下文，关闭时释放，不使用用户浏览器状态。
- headless 使用 context route，包含脚本打开页面的首个请求；禁用 service worker 与下载。取消后迟到结果不提交，放弃的后台获取关闭所拥有浏览器。
- 不可用页面保留脚本异常或脚本/数据请求失败；无具体失败时区分持续加载、不可用正文；登录表单不会成为目标正文。
- `source_acquisition` 是原始 ToolResult 的附加 JSON 字段，不改变严格 research_observation 或 ledger 的历史契约。成功/失败都携带获取链；恢复只读取既有回执。
- 移除 HTML attrs 与浏览器 fetch 返回的 Any，Session/进程字节输出类型明确。未扩大到无关模块整体重构。

## 比较原则

工具能力与回答质量分别计分。固定页面实验通过生产 headless/kernel，唯一替换为受控来源，不代替真实联网；真实 SPA 另用实际浏览器验证。旧三批与新实现使用同一模型、参数、原始问法和页面内容；必要时增加本轮改动前版本以区分此前提示精简与此次渲染变动。历史未同条件测试的结果不用于宣称质量上升或下降。
