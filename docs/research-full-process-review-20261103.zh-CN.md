# Research 全链条删减审查与 A/B：2026-11-03

本轮只审查和实验，生产基线固定为 `7060f345`，不删除、不推广候选、不提交生产改动。

**不能把“某次研究成功”理解成“每个现有流程都有必要”，也不能把“去掉后仍有报告”理解成“研究收益没有损失”。** 研究至少有四种不同收益：本题答对、引用可核查、知识能正确积累和复用、出错及中断时不破坏数据。分别评估这些收益，才能决定哪些手续可以简化。

## 1. 审查方法

从用户要求的八步链条出发，拆成 42 项职责：找准任务、召回、发现及阅读、整篇回答、积累、检查、发布、下次复用，及贯穿其中的预算、取消和恢复。完整映射见本报告附录及机器记录 `coverage-catalog.json`。

对进入模型请求的机制，用真实 12B 逐项关闭，对照原入口；对程序事务、版本、访问边界等，用原代码的故障对照。没有通过另写一套执行器替代现有 kernel，也没有给候选新增一条发布通道。每次运行从同一初始库复制，随后独立执行。

**审查覆盖不等于删减实测覆盖。** 21 个模型侧删减方案安排了实机；42 项中的可选 Ghost/聊天交接、特殊来源适配等未在主矩阵触发，单列为代码审查和确定性回归，不能声称它们已经通过删除检验。原有逐题计划和同模型强制自审已经不属于普通整篇入口，不能再次“删除”后算成本轮收益。

## 2. 冻结的实机设计

- 模型：`koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`。
- 温度 0.3，top_p 0.9，关闭 thinking，输出上限 4096，上下文 32768。
- 两个 seed：74、75；每例最多 8 个真实推理请求、8 个逻辑轮次；固定模型可见时间。
- 11 类场景，88 次计划运行。每项只放在相关场景比较，不能拿不同题目的通过率直接排序。
- 记录实际发送的工具、消息、tool_choice 及后端 token 统计；记录数据库真实新版本、引用和事务。展示字符串变短不自动算真实输入变短。
- 内容由本次审查逐份阅读，依据预注册细则；不用被测 12B 自己给自己打分。

这里没有直接测量模型的“心智负担”；输入 token、实际请求、协议错误和具体漏项只是可观察指标。省 token 与答对更多必须分别报告。

| 场景 | 要区分的能力 |
|---|---|
| 普通只读 WAL | 版本、三个 OR 替代条件及限制 |
| asyncio 综合 | 12 项异常、取消、顺序与性能边界 |
| Queue 缺口 | 未完成计数机制、没有测量与整篇没有测量的区别 |
| 首次积累 | 答案之外真实写入候选主张与完整前提推论 |
| 历史复用 | 从真实前次积累读取原始证据，不能偷换成新版本 |
| 原对象修订 | 同一 claim 到 revision2，精确保留其余字段 |
| 资料发现 | URL 未直接给出，找到两个虚构版本并阅读原文 |
| 长篇 WAL | 真实续读、定位、checkpoint 和回绕边界 |
| 草稿修复 | 已写完整正文却未调用提交工具 |
| 错引修复 | 已读取 e1，提交误写 e99 后如何恢复 |
| 来源内嵌指令 | 区分材料中的事实与冒充指令的文字 |

历史库复制自前次 **真实 12B 首次成功发布**，不是手工编造一个容易复制的历史 ID。额外通过原仓库制造一份明确标记的冲突 source head2（版本号 9.99.0），题目要求沿原依赖读 revision1（3.22.0）。冷热库具有相同 owner_id；每例独立复制，避免共享运行时或双写。

草稿和错引修复用两个明确标记的受控 provider 回应触发；它们不是实际推理，不冒称模型自己犯的错，也不计入真实模型请求成本。后续修复才调用真实 12B。

## 3. 程序侧删减对照

测试位于 `tests/test_research_process_fault_review.py`。通过表示测试观察到了预期差异，**不是禁用侧适合上线**。

| 机制 | 原机制 | 关闭或绕过之后 | 证据范围 |
|---|---|---|---|
| 引用解析 | 拒绝未知 e99 | unresolved 正文可把 e99 留成未绑定文字 | 提交边界；未冒称完整发布成功 |
| 批次依赖无环 | 拒绝 k1↔k2 | 规范化接受循环 | 仓库仍有独立防线 |
| 冻结提交校验 | 拒绝事后改正文 | 跳过校验则返回改后正文 | 校验边界 |
| 精确历史读取 | 返回所需 revision1 | 忽略 revision 则换成 head2 | 原 knowledge_read |
| 所有者范围 | 拒绝其他 owner 的对象 | 返回其他 owner 内容 | 隔离测试数据 |
| 原子发布 | 展示写入失败时回滚，0 条残留 | 取消事务后残留 5 个知识版本 | 原 publish_note |
| 提交回执 | 同一 commit 重放返回原结果 | 去回执后重放冲突 | 版本守卫仍阻止重复版本 |
| 已发布正文保护 | 拒绝展示 note 偏离原答案 | note 可与 authoritative answer 分叉 | 原 write_note |
| 完整工具回执 | 恢复完整原始材料 | managed receipt 不可读时恢复失败 | 原内核结算和恢复适配器 |
| 重复止损 | 同一读取 3 次即 no_progress | 继续到 8 次预算 | 原 kernel，脚本 provider |
| 轮数预算 | 3 次停止 | 允许到 6 次 | 有限实验上限，不无限执行 |
| 取消 | 已取消时不 fetch | 屏蔽检查后继续 fetch | 原 source gateway |
| 重定向策略 | 拒绝私网跳转 | 接纳私网跳转 | 未发实际私网请求 |
| 下载体积 | 模拟超额体被跳过 | 提高上限后接纳 | 64 字节模拟体，不是大 PDF 性能实验 |
| 响应关闭 | 退出后关闭 | close 失效则留着打开的响应 | 原下载入口和受控响应 |
| 本轮工具快照 | 拒绝当轮未承诺的新增工具 | 临时重建快照后接纳 | 解析边界，不执行新增工具 |
| 发布后审计投影 | 原 writer 2 次请求、1 次发布 | 关闭后相同 | 脚本内容相同，诊断损失另评 |
| 完成状态 | 正确正文声明 answered，未决问题可关闭 | 同一正文默认 partial，仍有未决问题，完成判定受阻 | 原提交、发布与完成门禁 |

这些结果支持保留相应保障的职责；不能由此推出每层实现都无重复、每个字段都应展示给模型。特别是批次无环和仓库无环、提交校验和发布校验可能分担不同信任边界，若想合并，仍要验证新的单一边界覆盖所有入口。

## 5. 读结果时的限制

每个相关场景只有两个 seed。局部改善是下一轮验证的候选，不是“已证明长期提高正确率”。不使用不同题集的总分替代成对比较，也不将多个删减混成一个原因。

还要看机制是否真的触发：没有省略窗口，不能证明恢复索引可删；没有重复，不能证明重复提醒可删；没有知识修订任务，不能证明修订工具可删；请求历史仍保有草稿，就不能说完整草稿保护真的被移除了。

`no_state_field` 使用保守默认状态，答案即使写完整也可能存成 partial。这能降低协议字段负担，但会改变下游未决问题和完成判定，不能只看正文分数。`no_proof_audit` 位于 writer 结束后，即使可精简，也不会直接减少模型心智负担。

长材料实验中 `omitted_windows` 始终为空，错引修复实验中重复提醒始终未触发。这两项的请求量变化不能算对应删减的收益。`no_source_search` 隐藏了工具，但仍留着提及该工具的通用导航提示，是不彻底的删减；它的失败不能全部归因于工具不可缺少。相同 seed 也不保证逐字复现：数据库、调用身份等仍由原程序生成，微小 token 差别及未触发干预的输出变化不能强作因果解释。

草稿修复实际检查了发送请求：基线的修复请求有一份完整草稿；`no_draft_copy` 的所有真实请求均无完整草稿，assistant 历史也没有隐藏副本。两次删减后都重建了完整答案，但当时完整材料和原任务仍在，不能外推到证据已被裁剪、多轮研究或更长草稿。

来源内嵌指令被明确标为不可信测试伪影，四次都没有照做。这验证了该简单场景，不是对真实、未标注提示注入的安全证明。状态字段、引用工具和材料角色指导也未随语义前缀一起删除。

本批使用冻结来源快照以保证对照；不代表开放互联网的搜索质量和浏览器长期稳定性都得到验证。原文读取、连接器、下载和解析是不同职责，不能用一份 HTML 成绩推断 PDF 工具可以删除。

修订题 `seed75/no_history_hints` 的原日志标为 `error`，原因是第九次推理请求被实验代理的八次预算拒绝，消息为 `Frozen evaluation inference budget exhausted`；这是预设实验边界，不是模型后端中断，也不据此诊断生产的网络故障。

## 7. 从职责出发的判断

研究系统需要保存原任务、取得可核查材料、允许回答缺口、可靠发布及复用。**这些能力有价值，不意味着每一处说明、每一个工具都需要在每次请求里出现。** 本轮最值得继续验证的方向，是减少模型眼前的重复信息和无关工具，而不是让它接管版本、事务和恢复。

| 项目 | 本轮观察 | 审查建议；本轮不改生产 |
|---|---|---|
| 重复的一份研究指导 | 普通 WAL 和 asyncio 共四组成对运行，输入分别减少 5.32%、4.52%；逐项内容没有退化，也没有更完整 | 优先做提示单一来源验证；保留一份权威规则，不能说正确率已提高 |
| 纯历史复用时的修订工具、长历史提示、动作历史显示 | 本题各两次均保留精确 revision1 引用；输入分别减少 57.06%、40.28%、48.55% | 值得扩大纯复用题验证，检查能否按任务展示；不能据此全局删除修订和错误历史 |
| 通用语义指导前缀 | Queue 从 0/2 完整到 2/2；asyncio 一例补上单子任务不连带取消，却丢失取消不受 return_exceptions 影响 | 有减负信号也有条件回退；不是稳定获胜候选，不能整段直接删除 |
| 每轮携带完整原任务 | asyncio 两次都变成英文且只答部分取消问题；长 WAL 两次变成英文概述 | 保证每个实际请求都有完整任务，具体如何避免重复可另测 |
| 自动知识召回 | 冷库只省少量输入；热库去掉后总输入增加 16.52%，请求 7→8 | 按冷热和命中情况衡量，不能用冷启动成绩删除长期复用能力 |
| `knowledge_updates` 首次结构化积累 | 普通题去掉后输入减少 19.61%；明确积累任务则交付 2/2→1/2，请求 4→8，输入增加 69.00%，实际候选 4→0 | 有真实接线收益，但两例原版推论均不合格；保留能力和继续提高知识质量是两件事，不能只按普通题 token 判断 |
| 资料发现与原文读取 | 两个基线都完成；各自关闭后均 0/2 交付 | 保留相应职责；本题不支持删掉它们来减负 |
| 长文导航、回执显示和恢复索引 | 基线和大多数删减均只读开头约 6,000 字，漏掉后文已有答案 | 先解决继续阅读和伪缺口；不能从双方均不合格推导可删。恢复索引未触发，仍待专门对照 |
| 原对象修订 | 六次均未正式交付，实际数据库也未成功精确修订 | 基线不成功，无实机证据证明可删或有效；暴露了编辑合同对 12B 仍难用 |
| 完整草稿保护 | 原版和短提示版各 2/2 保住所有条件，后者输入减少 6.87% | 本题未显收益，也未发现回退；保留此前正文退化证据，不能仅据两次成功撤销保护 |
| 错误详情、重复提醒 | 简单错引各组均恢复；去详情输入减少 19.20%；重复提醒实际未触发 | 错误反馈可更聚焦的候选；重复提醒没有有效删减结论，不能把未触发差别当收益 |
| 状态字段和强制工具选择 | 正文有得有失；去状态会把完整答案存为 partial；required→auto 无稳定成本或正确性收益 | 下游合同也要计入收益，当前不支持直接删除 |
| 发布后审计 | 脚本与实机交付相同；发生在模型结束后 | 可按诊断价值继续审查，删除不会直接提升本轮模型理解能力 |
| 版本、范围、原子事务、回执、取消与预算 | 程序边界对照观察到数据、资源、恢复或执行次数损失 | 保留保障职责；若合并重复校验，需要证明覆盖所有原入口 |

这些是单项、局部结论，不构成可直接叠加的生产方案。尤其不能把多个最省 token 的项一次混删，再把变化归给某一项。前一批 40 次实验题目及历史库条件不同，不与本批混算；前批某些删减曾有负面结果，也应阻止把本批两次成功外推成普遍等效。

首次积累还需要单独看数据库：原版两次的 source/evidence、答案及各两个候选处于同一发布 commit，依赖精确、没有悬空引用。一例候选主张完整，但只根据“只读支持条件”推导出原文另述的 DELETE 建议，前提不够；另一例主张单独缺少三项条件，推论又只是原文事实改标签。故两例的知识语义验收均不通过。删减版一次仅在正文列出 c1/i1 和状态，没有实际新主张、推论，且假设侧车包含于只读媒体就足够，遗漏可读性；另一次连续五次旧提交失败而止损。不能把原版知识通过 0/2、删减版 0/2 解释成二者等效，更不能把原版确实落库的四个候选都称为正确知识。

本轮形成的是“哪些显示值得减、哪些职责删后确有损失、哪些尚未测出来”的清单，**没有证明研究正确率稳定上升，也没有证明所有现有流程都不能删**。42 项已逐项审查，21 种模型侧删减完成 88 次实机，程序侧另有 18 项受控边界对照；未触发机制和可选上游、特殊来源的删减价值仍明确保留待测。
