# Research 操作记录：成功读取少重复，失败恢复保留（2026-11-03）

**最终只保留一个小范围改动：读过原文后又搜索旧知识，程序确认没有新结果时，少列一份重复的成功读取记录。** 刚读完原文、搜到新资料、出错、重复、修订及恢复时用原记录。目标状态共 12 个 seed，累计输入 **−20.14%**、请求 **17→14**；**最后单独一批输入 +13.52%**，所以不能保证每次任务都省。详细失败和未采用范围都保留在下文。

## 先说这次具体改了什么

每次模型继续查资料时，程序会附上两份有重合的信息：

1. 阅读回执：哪次读取、读到了哪些原文、以后怎样取回。
2. 操作历史：又把同一次成功读取的工具、参数、回执编号列一遍。

这次只研究第二份里重复出现的成功读取。原文、阅读回执、资料位置、精确知识版本、裁剪后的恢复入口都保留。搜索记录、读旧主张的记录也保留：它们没有原文阅读回执来替代。**前 72 次测试的是较宽候选；随后收窄成只在知识搜索之后精简。下面的历史实验不能全部当成最终版本的成绩。**

只要已经结算的操作里出现工具失败、相同结果重复出现，或进入修订、写入、回执恢复等操作，就继续使用原来的操作历史展示。后面再成功读取，也不会重新开启精简。

这里“原来的展示”仍是原版最近八条调查记录，以及原版的最新错误、工具反馈和恢复索引。**没有声称模型每轮会看到从开始到现在的全部历史。** 底层已结算记录和持久日志没有删除。

## 实验先怎么做

先做 24 次隔离 A/B，再接入生产做 24 次新 seed 复测；由于全程成本有波动，事先固定再补四个 seed、24 次查询运行。随后收窄范围，另做 12 次 A/B、12 次最终生产复测，合计 96 次。各批分别保存；只有同一版本、同一条件才能合并统计。当前生产的修订工具按需展示、历史说明文字、工具权限、发布检查均保持一致。第一轮生产基线为 `71f6bf3d`。

模型为本机 KoboldCpp 的 Gemma4 12B Q4。第一轮 seed 为 131、132。六种任务每种每组两次，预算相同，交换运行顺序。统计实际后端输入、输出和请求数，包含失败、重试及止损成本。

为保证有些记录真的出现，多数任务先由固定工具选择执行真实工具，例如读旧主张、读其证据、读原 source。随后由实机模型继续完成。固定选择没有调用模型，不计入模型请求；它们产生的记录会进入实际模型输入。这验证的是“已到达该状态后怎样继续”，不能当成模型自主完成所有前序操作的成绩。

每份正文都另行对照原文检查：中文、3.22.0、三个替代条件的 OR 关系、两个文件都已存在且可读／目录可写以创建两文件／immutable，以及实际保存的原始版本引用。不是让被测模型自己打分；检查者知道分组，不属于盲评。

### 最终生产范围：只在确认零结果之后精简

最终代码让搜索工具直接记录一个事实：**本次知识库搜索没有命中，旧笔记搜索也没有命中**。这个事实随正常工具回执保存。上下文读取这一事实决定是否精简，不猜问题意思，也不解析模型生成的文字。

最终必须同时满足：

1. 最近一次已结算操作是成功的知识搜索，程序回执明确标记零结果。
2. 在当前已结算操作历史里，没有工具失败、相同结果重复、写入、准备修订、修订或回执恢复。
3. 被省略的每一行都已有另一份原文阅读回执；搜索本身和旧主张读取等不省略。

之后只要又读取资料、搜到新结果或进入其他分支，就用原展示。旧版本回执没有零结果标记时也用原展示。原文、导航、准确版本、阅读回执和恢复索引始终保留。

### 为什么仍保留这个局部改动

采用依据是用户明确的局部准则，加上目标状态的累计证据，不是把最后一批称为成功省钱。

前四批的零结果任务中，候选实际发生的每个请求都仍处于这个相同状态：已有原文、最近操作为零结果搜索、没有工具失败或重复。逐请求核对后，其模型可见的历史精简与最终规则一致；这些目标任务可以与最后一批合并。**其他状态、其他候选不能一起混成最终成绩。**

| 同一目标状态的全部数据 | 原历史 | 精简 |
|---|---:|---:|
| 不同 seed 数 / 运行数 | 12 / 12 | 12 / 12 |
| 总输入 token（含重试） | 67,600 | 53,982 |
| 总输出 token | 3,612 | 3,020 |
| 实际请求 | 17 | 14 |
| 正式保存 | 12/12 | 12/12 |
| 严格正文与保存检查 | 11/12 | 12/12 |

累计输入减少 **20.14%**；最后一批的成本回退同样留在这个合计内，没有删除失败或挑正收益 seed。证据支持保留这个局部精简；它仍是单一 WAL 材料下的探索结果，不是长期平均节省承诺，更不是整体研究正确率结论。

## 出错时具体留下什么

| 信息 | 本次处理 |
|---|---|
| 做过的工具、当时的准确参数、结果编号、成功或失败 | 按原来的最近八条调查历史展示；进入保留分支后不再精简 |
| 失败工具的具体错误 | 原历史错误片段、最新错误和直接工具反馈都保留原行为，没有缩短 |
| 重复得到了相同结果的次数 | 保留原计数，程序止损也不改 |
| 成功读取的原文、准确来源版本 | 保留 |
| 每次原文读取的回执、可恢复的原文编号 | 全部保留，不跟着最近八条历史截掉 |
| 被裁剪材料的位置和恢复入口 | 保留原 `omitted_windows` 和来源导航 |
| 修订、写入、恢复回执后的历史 | 保留原展示；准备修订工具成功也会停止精简 |
| 磁盘上的执行日志、已结算结果 | 保留；本次没有删除日志文件 |

协议格式错误的修复提示仍由原内核提供，本次没有缩短它。没有对所有错误类型、所有历史库和所有长材料做完整模型实验，也没有改善模型抄错 ID 本身，更没有放宽 ID、版本或引用检查。
