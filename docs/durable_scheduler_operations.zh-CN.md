# Durable 调度器运维说明

Durable 调度器只把 SQLite checkpoint 当作任务事实；线程、唤醒集合和失败摘要
都是可重建的运行时状态。调度器循环错误按连续失败次数限流，默认连续三次失败后
停止本地工作线程，并保留当前调度器所有权。这样可以避免多个进程同时接管同一个
数据库，也允许原来的服务实例恢复。

当外部条件恢复后，调用同一个调度器的 `start()`，或调用等价的 `resume()`。这会
清除连续失败计数、重新请求一次 reconcile，并重新扫描持久化的待处理任务；不会
重新获取已经持有的数据库所有权。正常 reconcile 成功后，后续错误从连续失败的
第一次重新计数。每次重试至少等待配置的 `retry_interval`，关闭操作仍可立即唤醒
线程。

调度回调抛出的异常（包括 `ValueError` 和 `KeyError`）属于该任务的分发失败。任务
会先记录有界失败摘要并释放本次认领，低于上限时保留为可重试的 `PENDING`；达到
上限时只有确认 `fail_task()` 已经提交为持久化 `FAILED` 后才停止重试。提交冲突、
删除竞态或其他提交错误会重新读取 checkpoint；如果没有确认终态，任务继续保持
可恢复状态。

服务 `get_health` 响应包含 `scheduler.enabled`、最近一次 `loop_failure`、有界的
`task_failures` 和 `blocked_tasks`。调度器还会通过模块日志记录结构化的循环错误、
分发错误及失败提交冲突；错误摘要只包含阶段、任务 ID、异常类型、消息和重试次数。
