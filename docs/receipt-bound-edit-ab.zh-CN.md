# 读取回执绑定编辑：实机 A/B 试验

当前原始读取对象试验：`python -m tools.receipt_bound_edit_ab --run-dir .e2e-artifacts/receipt-bound-edit-read-object-20261110 --repeats 1 --timeout 240`。目录须不存在。

## 第三轮：绑定原始读取对象

本轮仍仅修改实验脚本、配套测试与记录。A 使用原有 `tools.edit({path, content, base_result_ref})`；B 在同一个 guest 内将编辑签名替换为：

```typescript
tools.edit(args: {
  read: Awaited<ReturnType<typeof tools.read_file>>;
  content: string;
}): Result<string>;
```

示例：`const r=await tools.read_file({path:inputs.path}); return unwrap(await tools.edit({read:r,content:unwrap(r).text.replace('old','new')}));`。不再传递转换回调。模型保留原始读取对象并计算新正文，程序使用该对象原有的回执编号和读取路径，不重新读取、不选择最近的回执、不自动重试。

测试包装层只在同一次 guest 程序内，以 WeakMap 关联原始读取对象与当次读取参数中的路径；读取结果顶层冻结，凭证仍来自原结果，不另建事实账本。原对象不能用解包值、展开副本或 JSON 克隆替代。编辑最终仍调用原有主机 `edit`，权限、完整读取和版本检查均由生产执行器完成。该便捷对象不支持跨 guest 程序序列化传递，本轮不验收跨进程恢复。

19 项配套测试、Ruff 和脚本 mypy 通过。测试确认：两组都拒绝读取后的外部修改；B 只有一次读取；读取其他文件或同路径的新版本不会替换原对象所绑定的回执；篡改参数或结果凭证不能重定向编辑；克隆、解包、缺失读取、部分读取和正文计算失败不产生成功写入。此前两次读取覆盖外部修改的行为不再是新原型的预期结果，历史证据保留在第二轮记录中。

本轮额外记录首次成功编辑回执出现时的 provider 日志字节位置，只从同一个原始日志计算该前缀的模型调用与 token，命名为 `edit_phase_*`。不会复制日志或双写回执；未成功编辑时该阶段计量未知。由此区分编辑接口开销与后续 done 声明修复开销。任务仍是同样 3 对，顺序 AB/BA/AB，max_turns=8，两组每个单元统一超时 240 秒；生产文件内容摘要用于排除运行期间发生源码变化的配对。

审计版本为 `guest-tools-edit-read-object-v4`，上一轮审计不由本版覆盖。实机结果将记录在 `.e2e-artifacts/receipt-bound-edit-read-object-20261110`。

## 第二轮：统一 tools.edit 入口

仅修改实验脚本与配套测试，不修改生产文件。A 组仍显式读取，传入正文与读取回执。B 组模型只看到一种编辑签名：

```typescript
tools.edit(args: {path: string; transform: (text: string) => string}): Result<string>;
```

声明、任务示例和实际 guest 入口均使用 `tools.edit`，不再提供全局 `update_file`，也不并列展示原始编辑参数。两组均在测试进程内将项目叶子工具收敛到 CodeMode，外层文本合同和原生工具列表不再额外暴露同名编辑操作；冻结的内部工具及执行器保持原样。B 组脚本在现有 guest 内为该属性提供作用域包装：读取路径、执行正文转换、将本次读取回执传给既有主机 `edit`，并返回既有编辑回执。其他工具仍使用原来的代理。转换函数不经过主机 JSON 通道，不新增主机工具、写入执行器或持久化事实。

成功的 guest 程序在测试包装层返回执行计数，脚本单独记录后还原原返回值，模型看不到实验计数。`confirmed_helper_calls`、`confirmed_helper_edits` 是成功程序中确认执行的调用与写入数；失败程序的计数未知，单列 `untraced_failed_programs`，不当成零次采用。词法出现次数只用于辅助审计。版本一致性、完整读取和同路径凭证检查仍由生产编辑执行器完成。

配套 13 项测试覆盖精确绑定、外部修改拒绝覆盖、失败不写入、token 计量、声明唯一性、外层文本与原生合同不暴露第二套编辑入口、冻结合同持久化与恢复、未执行代码不计采用、失败计数未知，以及下述旧正文闭包覆盖的 A/B 对照。Ruff 与脚本 mypy 通过。每个单元前后记录生产文件内容摘要；用户并行修改导致摘要不一致的配对只保留描述性结果，不作为同源码收益证据。运行期间不修改脚本，不创建 worktree，也不进行 HEAD 对照复现。

本轮 `--audit-only` 仅接受 `guest-tools-edit-transform-v3` 记录，防止使用新接口口径覆盖上一轮审计。上一轮原始记录与审计保持不变。

第二轮早期探索位于 `.e2e-artifacts/receipt-bound-edit-unified-20261110`：虽替换了 guest 声明，实际请求还附带外层旧编辑说明与 schema；首个 B 把 transform 当成字符串并失败。发现这一实验缺陷后终止本脚本拥有的进程树，保留记录但不混入正式配对。随后对两组均收窄模型可见外层工具，并新增相应合同测试，重新运行完整矩阵。

中间的 `.e2e-artifacts/receipt-bound-edit-unified-surface-20261110` 在发送模型请求前，被冻结合同持久化校验拒绝：脚本收窄外层工具后未同步内部清单的顺序。已仅在脚本中修正并加入持久化恢复测试；该目录同样不作为模型效果样本。

### 确定性并发风险

正式矩阵前两个 B 实际采用了统一入口，但都先手动读取、计算 `newText`，再调用 `tools.edit({path, transform: text => newText})`。回调忽略内部读取的正文。额外的真实执行器测试确认：若外部修改发生在手动读取之后、内部读取之前，B 会拿新回执写入基于旧正文计算的内容，覆盖外部修改；同场景 A 使用原读取回执，正确拒绝写入。这个对照是确定性测试，不依赖模型采样或实机耗时。

因此，本原型只保证写入凭证属于内部读取，不能保证模型的转换基于该次读取。生产执行器的版本检查没有失效，原型组合方式却为旧正文重新取得了当前版本凭证。即使 token 有下降，也不满足保持原有版本语义的验收要求，不应直接进入生产。后续应研究绑定原读取对象的编辑入口，避免便捷层再次读取并替旧正文换凭证。

## 第一轮：全局便捷函数（历史记录）

本试验只在测试进程内提供 `update_file(path, transform)` 原型。脚本不修改生产代码、用户设置或 Git 工作区版本。两组均使用正式 Headless 入口、本地模型、CodeMode guest、权限、`read_file`、`edit` 和原始回执。每个实验单元使用独立进程、状态目录和项目副本；超时终止该单元拥有的进程树。

A 组使用现有读取和整文件编辑协议，提示明确说明凭证在 `readResult.result_ref`。B 组在模型实际看到的 CodeMode 声明区提供原型函数签名，并在同一个 guest 的程序正文前注入实现：

```javascript
async function update_file(path, transform) {
  const read = await tools.read_file({path});
  const content = transform(unwrap(read).text);
  return unwrap(await tools.edit({path, content, base_result_ref: read.result_ref}));
}
```

该函数不自动重试。完整读取、同路径、同任务和写入版本核验都由既有编辑执行器负责，读取不完整时仍拒绝整文件更新。原型源码哈希参与 B 组运行时合同标识。没有增加主机写入工具或持久化账本；本轮不验收跨进程恢复。

3 个任务分别覆盖普通字段、嵌套数组、Unicode/引号/换行。每组修改同一份初始数据，核对完整 JSON、类型、备份文件及全部变更文件；依次使用 AB、BA、AB 顺序，重复次数可配置。每个任务最多 8 轮，默认进程级上限 180 秒。

记录任务完成率、无失败工具回执的完成率、模型请求次数、输入/输出 token、模型请求耗时、完整任务耗时、读写次数、失败回执和模型程序。请求按回执记录器与 exchange 去重，缺少 usage 时标为未知，不填零。`helper_call_programs` 只表示模型原始代码中出现便捷函数调用的程序数，不能单独证明所有分支均实际执行；须结合源码和原始读写回执审核。

最初探索将函数说明只放在任务文字中，B 组第一例绕过原型，继续手写旧协议。这一记录保留于 `.e2e-artifacts/receipt-bound-edit-ab-20261110`，中断后未作为便捷函数收益样本。随后将声明补进模型实际看到的 CodeMode 声明区，重新运行完整配对试验，记录位于上述 `declared` 目录。不得混合两次试验选择性统计。

这是小规模文件编辑协议试验。提示缓存、运行顺序、模型生成差异及生产收尾开销均会影响耗时；不将本轮结果推广为浏览器、混合模式或所有代码编辑任务的成功率。
