# 原工具内部减负：自动缩进与失败摘录

日期：2026-11-19。直接使用当前工作目录，没有创建或复制 worktree。

## 范围与行为

- 工具名、输入 schema 和调用方式均不变。模型继续使用 `edit(path, replacements)` 的旧代码/新代码，不新增区域名、版本引用或缩进开关。原有整文件更新合同不变。
- 先走原精确匹配及已有行号清理。只有原文无法匹配时，Python 编辑才尝试自动恢复：至少两条非空物理行、正文和相对缩进逐行一致、所有行只有同一个外层空格偏移、全文件只有一个候选，新代码保持相同的基准缩进。
- 程序将同一个偏移用于新代码，不推测内部层级。遗漏语句、改错标识符、相对缩进不同、多个候选、片段末行不完整、涉及多行字符串或 Tab、不合法 Python 均不会用此路径写入。首版只支持空格缩进、可解析的 Python 文件。
- 使用原权限检查、批次原子提交、工作区版本更新与收据保存。自动恢复准备后、写入前再次检查文件版本，外部改动不会被覆盖；批次后续编辑导致 Python 无效时也整批不写。正常精确编辑仍可用于已有的语法修复中间态。
- 真实命令非零退出时，在展示前部摘录原输出中的 pytest 统计、失败测试名及少量错误行；不根据测试名编造业务根因。摘录不参与成功判断，退出码和正式执行事实仍来自原收据。
- 后台首次查询的正式结果附带关键摘录，避免日志尾部的失败列表必须翻页才能看到。有原输出采集时，不再在正式结果字段中重复整段日志；无法提取或无法确认正常退出的诊断保留原展示。完整输出仍由原输出存储保留，查询不会重新运行命令。
- 编辑不匹配时，在原唯一锚点附近展示一处“请求的旧文本／当前文件”的有界差异及原上下文。此比较仅用于诊断，不参与定位授权或修改。能展示具体上下文时省掉重复的长篇操作说明；没有可靠锚点时才建议读取当前文件。

没有实现按函数名编辑、默认自动后台、额外计划清单或第二套运行时。

## 收益与剩余限制

可确认的局部收益有两项：历史同一条整段错位调用从拒绝变为直接成功，新增参数和额外调用均为零；复杂实机的首次后台回执减少约 38%，失败证据提前展示。

两次新实机都没有完成业务修复，也未证明真实模型少用回合或更容易独立完成复杂任务。自动恢复仍要求模型提供正确正文及相对缩进，不处理缺行、额外末尾片段、内部层级错误、歧义目标或遗漏的业务要求。语法检查只用于拒绝无法安全应用的候选，不代表业务逻辑正确。失败摘录当前主要识别 pytest 的结构化文本；其他程序没有可识别格式时保留原诊断。
