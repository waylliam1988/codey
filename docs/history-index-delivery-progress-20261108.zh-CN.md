## 最终实现与边界

- `history_index.py` 提供不可变 AVL 顺序树、原始 entry 定位树和可见任务集合；`sqlite_display.py` 负责事务内落库。`entry_ownership.py` 统一两个后端最终 by_task_id 的计算，原始记录与索引使用同一份结果。
- 每个原始 entry 保存显示版本。隐藏记录不加入顺序树，但保留原始路径成员信息；隐藏 marker 清空显示树及任务集合。跨继承前缀编辑使用 edit bridge，子分支固定继承创建时的版本。
- 顺序树当前使用单条来源区间，没有实现区间合并。分页、问题导航和定位窗口为 O(log N + 页大小)；任务批次最多 200 个，每个在集合中查找。所有保留版本的节点空间为 O(N log N)，并非 O(N)。正文不复制。
- 正常追加不改变 path_generation，旧游标继续固定在原版本；编辑、回退选择和 marker 改写要求刷新。游标签名绑定数据库、聊天、查询种类、generation、固定末尾、revision 与边界，不再接受旧 unsigned 游标。
- 节点按创建聊天归属，不做跨聊天全局去重；只有后代共享祖先节点。已有“有保留子分支的父聊天不可删除”规则保证叶子删除能安全回收自己的节点，其他分支不受影响。
- SQLite 每请求使用独立短快照，只在首次 SELECT 准入时持有 session 写锁。任务状态、正文和产物元数据使用同一个 reader。关闭快照后才返回响应对象，不跨请求保留事务。
- Memory 同样提供隔离语义，但准入时复制不可变对象字典，成本仍随内存库总量增长；有界数据库读取的性能目标针对 SQLite。
- 文件保护以数据库为范围。同进程读者共享一个 OS 租约，普通 SQLite 写入不取这个租约；删除与关闭在 session 写锁外等待读者。应用删除持有保护直到实际文件清理完成，保留 409/503 与重试语义。
- 跨进程采用互斥 OS 租约：另一个进程的历史读取会快速返回 snapshot changed，不承诺多进程历史读者并行；跨进程普通数据库写入可继续，删除必须等待读者。进程退出由 OS 释放租约。
- 前端把未确认的显示事件暂存，按最多 200 个任务分批校验，最多暂存 512 个事件、等待 5 秒，超限或失败重新同步。校验结果受 epoch/generation/revision 与本地 token 约束；流缓冲也受版本约束。排队输入、审批、停止完成等控制状态单独处理。
- 搜索、模型上下文及完整分支列表仍使用各自现有查询；本次不宣称所有查询都变成有界读取。
- 只接受新的严格 cold-start v1 结构。旧形状数据库明确拒绝，保持原文件、身份与提交数据，不迁移、不自动清空。

## 失败根因与修复

- 旧测试依赖 inactive_run_ids、unsigned 游标、全量 entries 调用，已按新协议更新；没有增加兼容旧协议的生产分支。
- 旧测试在同一个读取线程内同步删除聊天，违反新生命周期；改为独立删除线程，并验证它必须等待快照。
- 浏览器 renderer fixture 使用未持久化的模拟任务；显式提供模拟任务的权威校验结果，不放松生产端任务成员校验。
- 新浏览器测试最初从只保存元数据的 UiState 读取 messages，已改为读取实际 session 投影。
- 修复真实流顺序问题：terminal 生命周期改变前 flush 已确认的流帧。
- 修复真实页面残留问题：异步校验从模型移除旧 run/pause 后，通知挂载视图更新；否则 Continue 按钮和旧回答会残留。回归同时检查模型和真实浏览器。
- 分支 durable commit 可没有 entry_ids；通过 generation 识别路径改写并强制刷新导航与历史。隐藏 marker 截空后清除旧内容，连续改写不会恢复过期响应。
- 架构检查发现 sqlite.py 超过 1000 行；抽取两个后端重复的 entry 归属逻辑，未提高长度上限或豁免检查。
- 无 Any 前端门禁改为遍历 TypeScript AST，避免把 AbortSignal.any 方法名误判为类型。新增后端模块加入零 Any contract 门禁；没有宣称已有全仓历史 Any 全部消除。
