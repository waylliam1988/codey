# Research 简化审查：保留权威链，减少模型必须操作的协议

审查基线为 `ac753681`，并读取了工作区新增的正反材料 runner、fixture、rubric，以及正在修改的 `completion_guidance.py`。工作区在持续变化；本文不是后续修改的验收。本轮没有修改生产源码、没有调用模型。

## 结论

可以在原 kernel 内把 Codey 的模型工作方式收敛到接近 OpenScience 的“读材料 → 形成答案 → 明确提交”。不需要另建研究执行器、答案数据库或发布通道。

当前修改方向成立：单一 compact plan、固定 inline、复用实际已读窗口，分别减少计划对应、保存采用和切题恢复的操作。它们仍没有消除逐题控制、两种答案形状和主/附 passage 的区别。继续增加修复提示，不等于继续减少这些决定。

OpenScience 的已归档综合对照支持这种简化方向：同一固定 12B 下，它有 5/6 有效交付、4/6 必要事实与关系齐全且未发现错误附加结论；当时 Codey 为 0/6。这个对照使用旧 `c346b9e2`，不能代替对当前代码的重新验收。

## 当前修改的具体审查结果

### 1. 需要修正：共享上下文的字符重叠污染逐题归属

位置：`codey/research/plan_contract.py:107`～`113`。

当前逻辑把当前题 spans 和全部 `other_task_context` 合并，再用任意字符区间重叠计算每题 rN。编号、前导空格和换行同样进入共享 context；旧 rN 又经常包含这些字符，于是共享空格即可让另一个问题的实质 rN 被分配给当前题。

本轮直接运行现有函数复现：

```python
compact_plan(None, "1. 为什么 A？\n2. 为什么 B？")
```

得到：

```text
q1: 为什么 A？ → r1,r2,r3,r4
q2: 为什么 B？ → r1,r2,r3,r4
```

其中 r2 是 A，r4 是 B。英文和不带问号的中文编号题也复现了同样结果。

影响是逐题出处、覆盖及缺口归属不准确；这不是“已经证明能直接发布错误事实”，因为 q2 仍需自己的提交。但它削弱了原 accounting 的诊断价值。

建议在原 task layout 中明确区分：编号/空白等结构字符、实质题目 spans、真正的全局绑定上下文。按内容区间计算实质题目的归属，结构字符不能让其他题的 rN 进入当前题。真正的全局约束仍须完整绑定，不能为了修复交叉归属而丢弃它们。

这仍然是结构归属，不引入语义分类器。不确定的非编号正文继续保留为原任务上下文；不要声称“留在 context 中”就等于它已被回答。

补测至少应验证：q1 不包含 q2 的实质 rN；q2 留缺口时 B 没有被标成 q1 的回答出处；A/B 都有正确归属；全局禁用项、语言及格式约束保留。现有测试只验证全部 rN 的并集被覆盖，不能发现错误交叉归属。

### 2. 实验记录需要加强：根目录指纹不能约束整个活动矩阵

位置：新增 `tests/manual/research_reduction_local.py:124`～`132`。

runner 只在启动整个矩阵时记录一次 implementation_id，之后每次启动新 worker 都从正在变化的工作区导入生产代码。若测试中继续修改源码，一个 matrix 就可能包含多个实现版本，而根 manifest 只有初始版本。

建议每个 worker 在任何模型请求前重新计算实现身份，与该矩阵冻结的身份比较；不一致就把该次记为“版本变化，未准入”，停止矩阵或开新实验目录。记录本次实际身份。不要在一个矩阵里静默接受源码变化，也不要重用父进程已缓存的 implementation_id 充当新检查。

这是实验有效性问题，不是要求为生产增加另一份状态。源码未变化时，这个风险不会触发。

### 3. 诊断缺项：正反 runner 目前只有 kernel 入口

新增 fixture 的正反题、独立 rubric、材料经来源工具读取、标签不进入问题，这些方向正确。

但当前 runner 仅调用原 strict research，尚没有“只给相同问题和完整材料，不要求工具”的直接回答对照。因此它能评当前流程，不能单独判断失败来自模型还是合同负担。

如要回答能力边界问题，补一个仅用于诊断的直接入口；复用同一 fixture 和采样配置，保持 rubric 不进入请求。不是新增生产研究阶段。

另外，正反两例实际使用同一官方 URL，但各映射不同冻结选段。这适合作封闭材料诊断；必须保留“当前选段不足”的评分，不把无法读到被排除的段落当成真实网页检索失败。

### 4. 当前正在改的背景提示：可实验，尚未证明有效

`completion_guidance.py` 把“只陈述所问关系”放宽为允许必要且受支持的背景，有助于避免把解释截得不完整，但不改变结构负担，也可能增加主动扩写。

应作为单独的提示实验，不与新提交合同一起改后将收益归因。继续按完整条件、错误附加和正例拒答评分，不按回答更长判好。

## 怎样收敛得更接近 OpenScience

### 第一层：保留当前逐题链，先简化最难填的动作

保留已经一次成功的 `research_plan {}`；没有必要为了省这一个调用，立刻再设计一套自动语义规划。

新默认提交合同优先把模型输入统一为“状态、正文、一份证据引用列表”，减少以下选择：

- 主 passage 与 additional passage：一份去重引用列表即可，程序按固定规则适配原保存函数。
- 新 finding 与已有 findings 的相近名字：默认指导只呈现本任务需要的答案形式；历史采用能力沿原准确版本引用保留，不能让模型猜字段装对象还是装字符串。
- 选择 submission_mode：应用按冻结合同决定，模型不再选择。
- qN、unit、task_refs 的机械对应：程序派生。

证据列表必须由模型明确选择，且来自本轮实际呈现的冻结集合。程序只能规范化、去重或按明确合同拒绝，不能自行挑一段“看起来相关”的证据补上，更不能自动推断完整支持。

这些属于新冻结合同的适配，旧冻结请求保留旧解码；不能改变旧请求字段含义。不要再为普通新任务并行维护两个调度流程。

### 第二层：若要达到整体交付体验，取消强制逐题完成的调度

真正接近 OpenScience 的目标是：

```text
原任务及完整约束
  → 在原 kernel 中阅读/检索
  → 当前请求呈现有预算的、原版本的已读材料
  → 模型一次明确提交多个问题的答案与缺口
  → 原保存、选择与报告编译链
  → 唯一冻结报告
```

这不是在已保存答案之后再让模型整篇自由重写。模型提交的这份正文就是准备保存和采用的内容；报告从最终选中的精确知识版本编译，正文不另写一份。

可沿现有提交工具演进出一个版本明确的多题提交合同，模型只提供每题的身份、状态、正文及证据。应用派生 rN accounting、fN、原调查记录和最终出处编号。具体字段应以实际可表达、可验证的 schema 为准，不要先引入多个等价选择形状。

多题提交必须有自己真实冻结的多题范围，不能偷偷放宽原单题 scope。它仍进入原 kernel 的 normalize、执行与 effect 结算；不是另一个 Python while 循环，也不是通过直接调用内部写入绕过原准入。

这样减少的是“模型必须按程序顺序切题和逐题结算”的成本。模型仍需负责证据充分性、语义关系、条件完整性和明确缺口。较大回答也可能增加遗漏，所以需要对照，不能把一次提交全部题当成必然更准。

### 权威链不变

| 内容 | 权威来源 |
| --- | --- |
| 原任务与计划 | 原任务及原计划回执；其他结构单向派生 |
| 实际已读证据 | 原来源版本与原阅读回执 |
| 答案正文 | 原 KnowledgeStore 的精确版本 |
| 明确采用与缺口状态 | 原提交 effect 的规范回执 |
| 正式报告 | 原编译及发布边界生成的唯一冻结快照 |

恢复只读原冻结请求及已结算效果，保留当前实现身份检查。多答案一批写入后，原 staging、幂等身份与效果结算必须覆盖中途退出；不能因为单 finding 的测试通过，就假定多 finding 的部分写入也安全。

### 可以直接省掉与必须保留的内容

可以省掉默认的更细 work_units、模型填写平行计划数组、独立保存后再次采用、模型重填全局 coverage、为“证据不足”保存一条占位 fact、以及最后的整篇重写。

必须保留实际阅读与版本身份、模型明确声明的答案状态、证据与主张的对应、原效果结算、报告范围/格式检查和唯一发布。只有引用存在并不能保证语义正确，报告不能宣称得到了独立语义认证。

## 如何验证这次收敛值得保留

1. 先修正逐题归属，增加不会把 B 分配给 A 的回归。
2. 补齐新正反材料的直接入口，先知道当前模型在最小条件下能做多少。
3. 第一层字段简化与第二层多题提交分开比较，材料、采样和评分不同时修改。
4. 用原 WAL/asyncio 两题 × 三 seed 验收实际交付，并增加新正反题防止只适配已知问题。每次保留真实失败。
5. 单独检查多答案中途写入、效果结算、接纳和发布边界；拒绝或中断不能留下被误当成正式报告的半份交付，恢复不得重复写入/发布。

成功不是“出现一份长报告”或 CLI 返回 completed，而是有材料时完整且无错误附加，缺材料时明确留缺口，引用范围准确，并通过原唯一交付链。
