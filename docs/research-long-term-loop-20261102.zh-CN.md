# Research 长期知识闭环修复与回测

日期：2026-11-02。源码基线：`de3edcb1`。保留整篇提交、共享 kernel 与唯一回答发布事务。

## 核对结果与修复

四条问题均有对应的生产实现缺口。当前用户环境是冷启动，因此没有做历史数据迁移；跨会话材料全部由临时测试库中的首次研究产生。本轮没有调用本地模型。

### 1. 研究归档的作用域

普通整篇研究的 source、evidence、answer 统一采用：有项目时为 `project`，无项目时为 `personal`，个人所有者使用 KnowledgeStore 已持久化的 `owner_id`。会话 ID 继续记录来源，但不再自动成为长期研究的所有者。

| 作用域 | 含义与边界 |
| --- | --- |
| global | 明确公开的既有知识，按原权限读取；不把无项目研究自动公开 |
| personal | 同一知识空间所有者的长期知识，可以跨会话召回 |
| project | 原项目知识，换会话可复用，其他项目不可读取 |
| session | 显式临时材料，只允许原会话使用 |

选中受限历史材料时，发布继承其作用域。不同受限作用域混合仍会明确拒绝，沿用仓库的关系权限约束。本次未放宽 KnowledgeAccess，也没有批量提升历史数据的可见范围。

### 2. 历史材料进入同一阅读与引用通道

整篇合同开放 `knowledge_search`、`knowledge_read`。搜索和自动背景仍只是定位信息；原回答和候选主张不能代替原始材料。

`knowledge_read` 对 source/evidence 读取固定的对象版本。来源可以按 `offset/limit` 分窗读取；证据沿其 `from_source` 引用读取固定来源版本。读取结果通过现有 `research_observation`、`read_passages`、工具回执和恢复投影进入 `eN` 通道。发布时再次检查权限、固定版本、来源全文与摘录，并直接引用已存对象，不重抓网络，也不把旧回答升级为证据。

存量对象版本参与 passage 身份，避免同一正文的两个知识修订把既有 `eN` 重绑到后读版本。引用来源索引按 `(id, revision)` 区分，允许同一回答同时引用同一来源的两个固定版本。网页阅读的既有 passage 身份算法保持兼容。

可选的 `knowledge_commit` 复用现有执行效果与知识事务，支持明确提交和修订候选主张、条件、推论、问题、实体和观察。整篇合同的 schema 和执行器均拒绝用它另写 source/evidence/answer。主张和推论继续保持未经语义审查；没有从自由回答自动提取事实。首次普通发布仍默认只产生 source/evidence/answer；需要结构化积累时，显式提交已经存储的证据版本及关系。

### 3. 协议纠错

原修复提示保留字段校验错误，并增加上一失败响应的摘要和摘要哈希。原响应继续保留在既有 provider artifact，提示不整份重放超长正文。native 调用 ID 不参与错误内容身份。

修复 schema 的 JSON 渲染固定键顺序，保证冷恢复前后相同合同的诊断一致。若一次针对性修复后仍得到相同失败响应和相同诊断，kernel 从原请求指向的既有 RetryDecision 判断重复，明确以 `protocol` 停止。原次数上限、输出截断处理、恢复机制继续生效；未新增纠错运行时或重试数据库。

### 4. 长材料导航

从实际阅读回执合并已读区间，列出未读区间与首个未读区间。`next_offset` 改为首个未读位置，避免把“读到最远处”误当成“此前全部读过”。

整篇上下文不再静默裁掉第 12 个之后的定位或第 8 个之前的回执。所有被正文预算省略的窗口均有紧凑索引：稳定标签、来源哈希、范围、固定知识版本（如有）和完整 `read_tool_result` 恢复动作。隐藏正文仍不可直接引用；恢复原回执后才重新进入引用准入集合。以上均为回执派生视图，没有新增阅读进度权威。

### 原 3 项失败的归因

`test_simple_finding_and_generated_report_use_the_real_shared_driver` 的文本/native 两例属于旧 finding/report 合同验收。脚本提交旧版字符串问题数组，却让当前入口生成 compact 注册合同，注册失败后脚本继续消费空的阅读结果。测试现在明确冻结它本来要验证的 v1 合同，继续沿真实共享 kernel 完成检索、阅读、finding 与报告；当前默认整篇入口仍由整篇测试单独验收。

`test_manual_knowledge_refs_are_rejected_by_the_frozen_report_contract` 原先在未注册问题时测试 `done` 字段错误，生产正确地先拒绝了当前不可用的工具。测试现在先建立旧合同的问题注册前置条件，再核验额外 `knowledge_refs` 字段被拒绝；新增当前整篇合同测试，核验只开放 `submit_research_answer`、关闭全局 `done`，且同样拒绝手填 `knowledge_refs`。

这 3 项均为测试落后于生产合同，并非生产应该重新允许旧脚本绕过当前合同。没有为这些测试放宽生产工具准入。

### 类型与边界修复

原有类型错误主要来自整篇入口已经支持两种 scope/report，但恢复、完成闸门与发布投影仍只标注旧类型。现用真实联合类型表达现有运行语义，恢复后对本地修复对象作明确类型校验。没有通过增加 ignore 或降低检查等级消除错误。

同时使用文档写入事务直接返回的 revision，避免对可能为空的二次查询直接取下标；发布结果读取先验证回执中的 revision 为正整数；固定合同版本和序列化结果也显式表达其数据类型。原有冷重启与投影验收覆盖这些修改。

没有运行全量 pytest。上述测试验证执行、存储、权限、固定版本与恢复闭环；不代表本地模型一定会主动形成好的跨问题关联，也不代表已验证回答的语义正确性。后续提示和本地模型实验应把长期积累与跨会话复用作为主线验收，而非只优化单份报告。
