# Research：减少草稿和报错的重复内容

> 后续“已读资料持续可见、取消手工找回才能引用”已接入生产；本页仍保留报错去重阶段的原始结果，不把两项改动混为一项。新实现、生产回测及修复见[生产报告](research-visible-evidence-production-20261103.zh-CN.md)，此前 24 次 A/B 见[实验报告](research-visible-evidence-ab-20261103.zh-CN.md)。

**已接入生产。先做 24 次实机 A/B，再换 seed 做 24 次生产对照。采用的是报错去重，完整草稿继续保留。**

能确认的收益很小：**查旧资料、遇到一次读取错误后恢复，两轮都正确完成；输入分别减少 0.95%、0.90%，请求数相同。** 没有证明复杂恢复更可靠，也没有依据继续截短草稿或长报错。

**一、到底改了什么**

原来，同一次读取失败的错误文字可能出现在三个地方：刚收到的工具结果、操作历史、最新错误栏。模型反复看到同样的话，没有获得更多信息。

现在保留最新错误栏里的原话，另外两处复用它。失败操作的目标、参数、状态、重复次数和原始记录编号仍保留。不同操作的错误不会因为文字相同而一起删除。

| 内容 | 处理 |
|---|---|
| 模型写好了、还没正式提交的完整草稿 | 实际请求里本来只有一份完整回传，继续保留。没有再截掉正文。 |
| 最新一次错误的原话 | 保留原有最新错误栏，显示上限不变。 |
| 操作历史里同一次错误的重复文字 | 不再抄一遍；这条操作记录及其准确目标仍在。 |
| 本轮工具结果里同一次错误的重复文字及通用回执说明 | 只有当整段错误已完整放进最新错误栏时，改成简短状态、原记录编号和指向最新错误栏的说明。 |
| 较早发生的错误 | 保留原历史和原工具结果显示，便于区分先后操作。 |
| 超过最新错误栏容量的错误 | 仍完整发送原工具结果，不能拿截出的开头冒充全文。 |
| 底层原始记录、引用检查、保存、重启恢复、止损 | 保留原有行为。 |

程序复用已有的最新错误和原始回执，加一处“错误全文是否已在当前输入中”的判断；没有新状态、新工具或额外模型操作步骤。此前长文导航精简、零结果搜索时的操作记录精简、直接展示完整修订工具及已读旧主张原话均保留。

对应生产改动仅在 `answer_context.py` 和 `task_guidance.py`：最新失败操作的重复 `error` 字段从 `latest_error` 复用；最新失败结果的 `model_text` 不超过 1,600 字符时，工具结果显示改为简短回执。更长错误仍走原完整显示。原始 `ToolResult` 没有改写。

**二、实机结果**

后台为 KoboldCpp / Gemma4 12B Q4。A/B 使用 seed 501、502；生产复测使用新 seed 521、522。每轮六类任务，每类每组两次，共 24 次。

这里的“正确完成”同时检查正文、任务要求、实际保存和准确证据引用，不能只看有没有生成答案。

| 场景 | A/B 正确完成：旧版 → 精简版 | 生产正确完成：旧版 → 新版 | A/B 输入变化 | 生产输入变化 |
|---|---|---|---:|---:|
| 查旧资料，先遇到一次读取错误 | 2/2 → 2/2 | 2/2 → 2/2 | −0.95% | −0.90% |
| 普通回答并保存新候选知识 | 2/2 → 2/2 | 2/2 → 2/2 | +0.05% | +0.01% |
| 简单完整草稿未提交，补做正式提交和保存 | 2/2 → 2/2 | 2/2 → 2/2 | 0.00% | −0.01% |
| 多份长材料被裁剪后，恢复复杂草稿的引用 | 0/2 → 1/2 | 0/2 → 0/2 | −17.75% | −6.86% |
| 错误引用加长材料裁剪后的恢复 | 0/2 → 0/2 | 0/2 → 0/2 | −0.54% | −17.04% |
| 连续两次读取错误后恢复 | 0/2 → 0/2 | 0/2 → 0/2 | +23.26% | −30.15% |

**真正稳定观察到的小收益是第一行。** A/B 输入为 26,935 → 26,678 token；生产为 26,929 → 26,686 token。每组都为 6 次请求，版本、文件可读、目录可写以便创建文件、`immutable` 及三项“或”关系均正确。读取的是历史证据的准确版本，没有抓新网页或换成来源的新版头。实际第一轮请求中的同一次错误由三份文字变为一份。

普通保存和简单草稿题，两轮各组均实际保存了指定候选 claim，引用真实归档证据，与答案处于同一次发布事务。草稿题首次请求仍有一份完整草稿。它们输入基本不变，不算本次去重的收益。

**三、失败和代价不能藏起来**

复杂题仍会提交隐藏的或无效的引用，或者恢复了第一份材料就提前回答。原版也存在这些失败。生产 seed 522 的新版虽然保存了答案，却把第二份材料里的 C2 写者额度、tag 和 checkpoint 规则说成没有提供，故判为不合格。配对原版没有交付；这不能算研究正确率提高。

A/B 的复杂草稿精简版有一份通过，但“remote 不继承 local 的许可”措辞不够精确，原文说的是 allowance；数字和其余核心条件正确，逐例记录保留这个问题。新 seed 没有复现复杂题正确完成的改善，不能宣称已经修好。

连续两次读取错误的任务，两版都继续对错误目标读取或搜索，最终止损。A/B 新版请求反而为 8 → 10 次，输入增加 23.26%；生产新 seed 则为 11 → 8 次。**两边都失败时，少花输入不能算成功恢复收益；这类路径也不保证每次更省。**

全部任务合计如下，包含失败和重试，不只统计第一轮：

| 指标 | A/B：旧版 → 精简版 | 生产：旧版 → 新版 |
|---|---|---|
| 总输入 token | 318,685 → 303,072（−4.90%） | 338,120 → 295,809（−12.51%） |
| 模型请求数 | 55 → 54 | 59 → 52 |
| 正式保存答案 | 6/12 → 7/12 | 6/12 → 7/12 |
| 正文及全部任务要求通过 | 6/12 → 7/12 | 6/12 → 6/12 |

整体输入下降很大一部分来自失败路径变化，**不把这两个整体百分比当作成功研究的节省承诺**。采用依据是第一行成功恢复的局部收益、其余已正确完成配对没有新增失败，以及完整诊断和恢复边界仍保留。

**四、验证范围**

这是每类每轮两个 seed 的探索性验证，使用固定官方原文和合成材料。为确保真正触发草稿修复、错误及裁剪，相应任务有受控的前置工具调用或草稿；工具真实执行，后续选择、模型请求、正式提交和数据库保存均是真实流程。受控回应不计为模型请求或 token。普通保存题没有这种前置错误。不能把结果外推成全面研究能力结论。

生产复测的旧版只恢复冻结的原显示函数；新版走实际生产函数，没有套实验精简补丁。每轮 12 个配对的首次实际请求均核对过，差异符合本次显示改动，工具定义相同；只排除随机请求键和回执编号的干扰，不替换知识 ID、版本或正文。生产复测期间 578 个生产 Python 文件的摘要保持不变，与 A/B 快照相比仅上述两个生产文件变化。

较长报错没有做新的实机截短实验。本次选择保留它们的完整工具结果，程序回归覆盖 1,599、1,600、1,601 和 4,000 字符边界，检查具体错误及原始回执不丢失。

针对性回归 **76 项通过**；扩大回归覆盖 **205 个文件，2,660 项及 21 个子测试通过**；另做重启续作组 **22 项通过**。包含 native/text 实际请求、完整草稿修复、进程中断后恢复和防重复发布。针对性与扩大回归有重叠，不相加冒充更多独立测试，没有留下失败。

Ruff 全库通过。Mypy、Pyrefly、ty 检查整个生产目录，Python 3.11、3.12、3.13 目标均通过。Pyrefly 为零错误，仍报告既有警告；目标版本静态检查不等于分别用三个解释器跑完测试。
