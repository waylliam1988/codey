# 冷启动内核收敛复查

日期：2026-09-30。对照提交：`3ca86a1`。
范围：本次未暂存改动、生产调用者、授权、结果恢复、完成判断及对应测试。

## 结论

主链在收敛：编程、Research、混合任务和只读审计顾问复用共同模型工具循环，
本轮授权与工具定义绑定同一份快照，项目检查与任务要求组合成一份最终证明。
运行日志继续保存持久事实，TaskSession 提供任务内的事实视图。

这不意味着总代码量减少，也不构成整个仓库没有任何 bug 或死代码的证明。
本轮清理针对审查范围内的重复执行入口、独立顾问循环、失效测试与静默回退；
历史实验、真实网页模型输出质量以及未来工具扩展没有被有限回归穷尽。

最终全量：**5952 passed、29 skipped、1471 subtests passed，363.89s**。
parity：**682 场景、566 一致、116 明确差异、0 未分类失败**。
首轮全量失败和修复过程保留在 `TEST_REPORT.md`。

## 调用链与职责

```text
用户入口 → TaskPolicy
    → project_adapter / research_iteration / task_entry / project_audit_advisor
    → TaskSession
    → run_task_kernel
        → build_turn_snapshot
        → provider adapter 发送
        → normalize_turn
        → execute_turn
            → effect intent
            → 具体项目／来源／知识执行适配器
            → 原结果 settlement
        → completion_gate.evaluate
    → 同一份最终证明的 UI／运行记录投影
```

ResearchPipeline 和 PlanExecutor 仍负责研究策略及确定性来源读取；这些内部
策略操作有父任务授权检查。它们不是另一套模型工具循环，不能把它们的存在
误写成“每一个内部操作都已由 execute_turn 执行”。项目 Engine 保留验证关联、
改动完整性和修复策略，最终证明由共同 gate 组合。

## 本轮修正的关键边界

| 函数／模块 | 修正后的职责 |
| --- | --- |
| `TaskPolicy.from_payload` | 拒绝未知版本、畸形授权／拒绝字段和错误布尔类型，不静默丢掉约束 |
| `apply_auto_plan`、规划和补证据策略 | 在父策略上收窄，保留显式拒绝与完成要求 |
| `build_turn_snapshot`、`normalize_turn`、`execute_turn` | 深冻 schema、授权、执行器和 replay class；产生 effect 前再次检查快照 |
| `result_receipt_fields`、`restore_result_receipt` | 保存并校验原文本、身份、结构化元数据和摘要；长结果外置到现有受管存储 |
| `KernelEffectSink`、恢复适配器 | 结算必须携带原结果；恢复交付原收据，不重跑已结算命令或写入 |
| `completion_gate`、项目 enforcement | 组合一份证明；确认当前文件版本；拒绝畸形内部证明 |
| `project_adapter` | 先检查授权和持久身份，再创建项目／会话；回执投影已有证明，不再次运行完成检查 |
| `ProviderAdapter` 及具体包装器 | 两种协议共用发送包装，保留真实 provider hook、剩余超时和实际交换记账 |
| `provider_uses_native` | 穿透明确的包装器识别实际 provider，不把动态 mock 属性当原生能力 |
| `shell_approval`、shell redelivery | 原生 call id 不裁剪、不去空格；错误类型不能被转换成成功 |

### 恢复的含义

完整收据和网页正文／命令原始输出是不同产物。恢复给模型的内容仍是当时看到
的窗口，并保留原截断标记，不用完整正文替换窗口来假装当时已读过全部证据。
原始产物和收据的摘要都需要匹配；文件缺失或被改动时明确失败。

恢复的验证结果可以原样交付，但只有与当前工作区版本匹配时才能证明当前
文件已验证。旧日志仍可按已有记录格式读取；缺少完整收据不再被解释为完整
成功结果，也不会因此自动重跑已结算动作。

### 完成的含义

模型的 done 是候选。搜索摘要不能代替打开来源，普通联网任务不自动承担
严格 Research 的笔记与报告要求；修改后的验证不能借用旧版本的通过记录。
没有改动的正常 done 任务记录一份 N/A 检查证明；停止的任务不记录完成证明。

## 测试卫生

- 删除 12 个 pytest 不会收集的 `_obsolete_test...` 方法及死夹具，避免保留
  看似覆盖行为、实际从未运行的测试。
- Research 测试适配器不再吞掉任意参数；实际发送和实际工具快照参与断言。
- 恢复测试通过真实 kernel 执行并保存计数文件，重新打开日志后确认计数不变。
- 混合任务测试读取真实文件、打开来源、实际编辑、验证内容并检查版本证明。
- 重复结算、字符串形式的失败标记、越权和取消等负向断言继续保留。
- 原始 parity oracle 不改写；新会话失败的变化使用一个精确 before/after
  差异记录，不用宽泛例外覆盖新失败。

## 代码量和性能

相对 `3ca86a1`，生产代码新增 1847 个已跟踪行及四个新模块的 468 行，删除
1289 行，净增 **1026 行**。这里包含用户提交前的改动，不能全部归因于本轮复查。

重复模型循环和旧执行入口减少了；完整收据、授权闭合、恢复证明及生命周期
观察补上了此前缺少的行为。这些新增行应靠行为回归证明必要性，不能仅因为
“统一”就认定增加都是合理的，也不能只看总行数判断是否收敛。

已确认减少的重复工作包括修复轮次重复创建来源资源，以及完成回执再次
扫描工作区。没有进行在线模型、真实浏览器、CPU、内存或延迟基准，所以不
宣称量化性能提升或真实用户体验已全部验证。

## 后续保持收敛的规则

1. 新工具注册 schema、授权、效果与执行器；新任务注册所需检查，不复制循环。
2. 授权从入口取得，子任务只能收窄；模型提示、路由、恢复内容都不能扩大授权。
3. 为 bug 先复现可观察失败，再修实现；测试不只检查新函数返回某个字段。
4. 恢复测试检查真实副作用次数、原结果和版本身份，不能用预置成功收据替代执行。
5. 完成证明只有一个最终入口；显示层读取证明，不另行推算完成。
6. 删除旧入口时同步更新调用者与行为测试，不留下可运行的第二套生产内核。

29 个跳过项来自 Windows／符号链接权限／POSIX 合约限制和一个未启用的真实
浏览器测试。本轮未 release、未打 tag、未修改版本号。
