# 搜索、索引与 CodeMode 收敛及 12B 实机比较

本文保留此前轮次的历史结果。后续 Codey 的输入前缀、任务变更归属、原生修复回执和
12B 复测见[请求输入收敛报告](codey_input_convergence_12b.zh-CN.md)；本轮没有重新运行参考项目。

本轮保留上下文搜索、glob、持久元数据索引和 CodeMode 恢复，调整它们的事实归属与生产接线。
参考项目没有修改；比较使用各项目原 CLI 和任务循环，没有重写参考代理。

## 实现与事实归属

| 内容 | 现在的唯一所有者 |
| --- | --- |
| 文件内容 | 文件系统；索引不保存正文 |
| 发现范围与遗漏 | 不可变索引快照的 coverage；冷、暖、重新打开共用投影 |
| 搜索匹配、分页、上下文 | 原 `rg_search` 生产编排；删除未接入生产的 RootPlan 路径 |
| 工具参数与结果定义 | 原 ToolDefinition / ToolSpec / result schema |
| 子调用请求与结果 | 原 durable effect intent 与完整收据；父调用只持有子效果引用 |
| 程序状态 | 原 task checkpoint；恢复元数据只引用其 revision |
| 执行与恢复 | 原 execute_turn、mutation line 与同一个 Node worker |
| 是否完成 | 原完成门；不根据展示字符串另建成功判断 |

索引资源通过 `build_project_tool_fns` 创建，默认执行委托、项目托管工具、任务入口和安全信息工具恢复共用工厂。
没有模块全局索引或另选默认目录。缺失、过期重建；损坏、读写失败报错，不换一种搜索方式继续。
发现预算与正文预算分开，glob 在正文预算准入之前应用。筛选只重访候选文件的直接父目录，深度固定为 1。
这是文件候选集上的原生 glob：目录及后代使用 `src/vendor/**`，不把目录名字当作根遍历的祖先剪枝规则。
目录条目发现不完整时拒绝 glob 请求并要求缩小范围，不再无界遍历求交集。

CodeMode 的已提交父收据直接恢复。部分子调用已提交时，重建控制流，子调用继续进入原 execute_turn，复用原收据。
缺少子收据、身份/参数不一致、历史不确定时阻断；脚本 catch 不能把这类恢复错误转成父调用成功。
没有 `__execution__` 结果副本、第二份子请求账本、独立子 delivery batch 或另一套 JS 执行器。
原 checkpoint 仅新增程序/工具目录摘要、能力、范围、固定时间/随机种子，以及状态操作的 revision 引用。
读工具实际执行仍可并行，结果按发出顺序交付；写操作等待此前回调完成。这是恢复约束，不能据此宣称强 JS 安全隔离。

协议解析改为明确的词法与容器语法，字符串之外识别布尔值/null，字符串内容不做全文替换。
坏输入返回原任务循环重发，不猜测反转义、不自动剥引号、不依次尝试多种修复解析器。

## 实机比较方法

- 模型：`koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`，同一个本地 KoboldCpp 服务。
- 每次仅一个代理使用模型；上下文配置 32768、输出上限 2048、每任务最多转发 24 个生成请求、墙钟上限 240 秒。
- Codey 走原 headless 入口，kernel 上限 16 轮；各参考 CLI 保留自身循环与工具设计，外部共用请求/时间上限。
- Codey、Pi、OpenCode 请求设置 temperature=0、seed=41；DSH 原配置路由没有暴露等效控制，实际请求省略这两个字段。该差异限制因果比较。
- 每个任务/代理使用独立临时 Git 仓库，提交相同初始夹具，状态目录独立；不修改本项目提交或参考源码。
- 四项任务：含引号完整行读取、限定范围/扩展名/排除目录的字面量搜索、第二处命中后的两行、修改两个模块并执行测试。
- 只读任务分别判断结果内容和裸 JSON 格式。评分器只为内容评分识别一层 Markdown JSON fence；生产协议没有此容错。
- 跨文件任务同时要求独立 oracle 通过、代理自己观察到验证通过、未改动夹具测试和其他文件、进程正常结束。
- 只读交互的自动代理指标是至少两次生成请求；原始工具事件另行保留，不能把这个计数称为执行证明。
- 计时包含 CLI 启动、提示、模型、工具、反馈和结算；不是纯 rg 性能测试。流式 token usage 不完整，不比较 token 效率。

| 项目 | 本地参考版本 |
| --- | --- |
| Codey | 工作区源码 manifest 与 archive；HEAD `1984309f` 不能代表未提交修改 |
| Pi | 1.4.0，`38ff99177fba21e9c57a670f4e95adcf407c99c7` |
| OpenCode | package 2.1.4，源码运行显示 local，`6ac6549a0aed2c69cc31eff17abdc1d690a585a6` |
| DeepSeek Harness | 0.2.1-rc.3，`22ddee3792402c3e70ec5f86a63c3e3e895a2f60` |

Pi 使用 source resolver，OpenCode 使用原 Bun preload 与私有 standalone server，DSH 使用原 headless profile 和 tsconfig。
这些是源码 CLI 的启动配置；没有修改工具参数、修补回答或替换原任务循环。

源码迭代中的早期 Codey 行与最终交付源码通过各行 manifest 区分；最终源码另跑契约矩阵，不能把所有历史轮次合并算成功率。

## 从原始轨迹能解释什么

Codey 的集中工具声明降低了小模型猜命名空间的负担，结构化搜索结果保留命中与上下文身份。
这次 OpenCode 简单任务的轨迹反复出现 `tools.read` 等未知名称，错误已提示通过 search 查找工具，模型仍重复。
这是该版本默认惰性工具发现与这个模型的适配问题，不能推广成 OpenCode 缺少读取或编码能力。

Pi 在简单读取中的端到端耗时较低。glob 失败轨迹实际选用 bash + grep + sed，得到正确命中后又重复同一命令，最终耗尽请求。
因此该失败不能用来证明 Pi 内置 rg 工具的匹配能力较差，也不能用来证明 Codey 的 rg 引擎更快。
Pi 的跨文件任务也明显更快。该任务首请求中，Codey messages/tools JSON 字符数为 6412/10164，Pi 为 3179/2956；
Codey 17 次请求的 messages 总字符数为 244213，Pi 19 次为 172819。较重的契约和上下文是潜在预填充成本，
同时 Codey 轨迹有精确替换失败后的返修。字符数不是 token 数，不能把全部耗时差精确归因于这些因素。

DSH 的 glob 轨迹先返回包含 vendor 的文本结果，模型多轮后才整理出要求的集合。其采样控制与其他代理不同，不能单独归因于工具 schema。
跨文件轨迹中，pwsh 验证反复返回 `NO TESTS RAN` / 无法导入 `test_app`；原会话元数据记录的 cwd 是正确的夹具目录。
随后用原 DSH CLI 做独立只读诊断：模型忠实执行要求的 `Get-Location` 和 Python `os.getcwd()`，
两者都返回 `C:\Program Files\PowerShell\7`，因此无法打开夹具中的 `probe.txt`。
这复现了当前 Windows shell 执行目录异常；尚未定位到其底层具体代码行，没有修改参考项目。
不能把该验证失败归为模型不会修改代码；外部 oracle 实际通过。
DSH 的只读 LSP 能力仍是 Codey 可借鉴的范围；本轮没有给 Codey 增加语义导航，也未在这四个任务中测试 LSP。

Codey 仍会多包代码块、写出错误的精确替换片段、在文本模式中重发坏外层 JSON。
完成门保证显式约束和已记录事实，不保证任意自然语言答案都正确；普通比较任务没有额外注入标准答案要求。
严格授权、完整回执、验证及结算会增加耗时，复杂任务的模型轮数也可能被这些反馈消耗。

## 已发现的边界与实验批次

定向主回归通过 420 项测试、484 个子测试；最终接线修改后另通过 142 项测试、420 个子测试，
协议/重放类型调整后另通过 77 项、79 个子测试。选择互有重叠，不相加。Ruff、526 个生产源文件的 mypy、
git diff --check 通过，没有运行全量 pytest。最终源码 native/text 各 9 个实机场景全部通过，共 18/18；
包括读、写、Stop、字面量/引号/正则/空搜索、非对称上下文和搜索 Stop，并验证原收据恢复及重复恢复稳定性。
528 个 Python/MJS 源文件与保存的源码 manifest/archive 哈希一致。
文本含引号场景仍需一次错误请求后的纠正；这说明边界能拒绝并反馈错误，不能宣称模型不再生成错误 JSON。
最后用最终源码的原 headless 入口重跑 glob：内容通过、4 次请求、20.0 秒；
原状态目录实际生成 `search_index/*.json`，确认托管入口的持久接线已生效。答案仍有代码块，格式项继续记失败。

第一轮公共 glob 任务暴露了 Codey 的生命周期错误：无进展关闭原生调用时，收到的确认生成尚未通过原 generation boundary 结算，外层就结算 writer。
本轮已在原边界修复无进展及预算关闭路径，并用真实 durable sink 补回归；没有扩大状态机合法迁移来放行。

另一项原有边界仍存在：仓库没有初始提交、文件全部预先未跟踪时，Codey 能读对并输出答案，外层却把原有 Git 变更归为本任务改动，追加验证阻断。
定位到 `project_writer_phase` 的全工作区变更覆盖任务变更判断；本轮没有扩展到重做任务变更归属协议。
该失败完整保留，不计入干净仓库主比较，也不宣称脏工作区已经解决。
