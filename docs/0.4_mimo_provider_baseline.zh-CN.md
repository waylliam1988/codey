# Codey 0.4 MiMo Provider Baseline

## 定位

这是 0.4 stabilization 的第三 provider baseline，也是 post-0.4.21
stabilization 阶段的 MiMo full cross-check。它整理的是 MiMo 在真实网页模型上
跑完 coding / research / ghost live A/B 后的结果。

这不是统计 benchmark，也不是 provider 排名。它只回答四个问题：

```text
MiMo 作为第三个网页 provider，0.4 的 coding / research / ghost 闭环是否能走通？
DeepSeek + Qwen 的 0.4 结论是否能被第三 provider 交叉确认？
MiMo 暴露的问题是生产 bug、harness bug，还是 provider/model 行为？
进入 0.5 前是否还需要 GLM/MiMo/Qwen 继续重跑？
```

结论：

```text
MiMo 第三 provider full baseline 可以作为 0.4 stabilization evidence 使用。
MiMo coding / research / ghost 全量 live pass 没有暴露新的生产 Codey bug。
0.4 闭环已经不再只是 DeepSeek + Qwen 两个 provider 的初步结论。
不建议为了 0.4 继续重跑 MiMo 全套；GLM 只作为可选额外交叉确认。
```

## 证据范围

本地证据目录：

```text
tests/manual/results/0.4-stabilization/mimo/
```

这些目录被 `.gitignore` 忽略，保留在本机用于复盘 result JSON / journal /
transcript / trace，不作为仓库源码提交。公开仓库只提交 harness、deterministic
test 和结论文档。

执行纪律：

```text
provider: mimo
一个 suite
一个 arm
一个 case
固定 output
completion/source/ghost research continuity 优先 archive transcript
跑完立即分析 result / journal / transcript
```

MiMo 的网页回复时间明显长于 coding smoke。Research 和 Ghost research continuity
样本多次需要 3 到 8 分钟才自然收口，因此这轮不把长时间无 stdout 当作失败，只以
harness 退出和 result JSON 为准。

| Probe | MiMo 结果 | Interpretation |
| --- | --- | --- |
| `ghost_research_continuity` | 5 cases x baseline/continuity；10/10 exact；journal hash chain 全部正常；没有 seeded claim/open question leak。 | continuity 仍是 bounded stale/recheck hint，没有变成 evidence。 |

无效样本说明：

```text
ghost_continuity / chat_recent_focus 第一次用 --isolated 启动。MiMo 的登录态在
isolated context 下不可用，baseline row 是 response_missing，continuity row 是
authentication_required。该样本归类为 invalid provider setup，不计入 counted evidence。
同 case 已用非 isolated context 重跑并通过。
```

生产决策：

```text
Ghost 继续只作为 bounded continuity / work queue hint。
旧 claim 和 open question 不能成为 evidence 或 citation。
当前用户请求优先于 continuity。
work queue 不在 plain chat 下自动触发 Research。
当前没有新的生产 Ghost bug。
```

## 已证明与未证明

初步证明：

```text
MiMo 可以跑通 0.4 的 coding / research / ghost 全量 live A/B 路径。
Completion scorer/report gate 能抓住 MiMo 的 fixture mutation false completion。
MiMo 在 verification_review/current 中能利用 Verification Map 找到更多真实 review 问题。
impact_guard 没有引入 missed caller 或 wrong extra edit regression。
search coverage 在 MiMo 上保持安全，并在部分 omission case 降低 turns/tool calls。
Ghost continuity 没有污染 evidence，也没有覆盖当前用户意图。
```

没有证明：

```text
MiMo Research strict proof quality 的稳定 clean success。
bounded planner / scoped_task_plan 有跨 provider 稳定净收益。
source_connector_done batch/checklist 值得推广。
GLM / StepFun 也同样通过 full 0.4 pass。
```

## 后续规则

不建议继续重跑 MiMo 全套。只有下列情况才重新跑 MiMo 对应 arm：

```text
修复了该 arm 暴露的明确 Codey bug
改了该 arm 的模型可见 prompt / tool schema / harness schema
第四 provider 暴露的问题需要回到 MiMo 做交叉确认
需要确认 MiMo provider/browser 登录态或 teardown 噪声是否恢复
```

如果后续继续 MiMo：

```text
给 Research / Ghost research continuity 足够长等待时间
不要使用 --isolated，除非先确认 provider 登录态可用
继续 one case / one arm / fixed output
row 已写入后的 EPIPE / TargetClosedError 归为 teardown noise
scoped_task_plan 低分先检查 expected path 是否跟上冷迁移后的真实包路径
```

0.4 final stabilization report 已更新：

```text
docs/0.4_final_stabilization_report.zh-CN.md
```

下一步建议直接开启 0.5。GLM full pass 可以作为可选额外 confidence run，但不再是
0.4 进入 0.5 的阻塞项。
