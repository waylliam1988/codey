## Windows Shell 的两个超时

GitHub 运行 `43143241389` 的 Ubuntu、macOS Shell 作业成功，Windows 作业失败。现有日志显示第二次审批已允许、执行已结算、续跑已启动，但任务没有在 10 秒内完成；另一个用例在等待真实工作线程到达完成边界时触发 5 秒断言。

这些日志能确认测试等待超时，不能单独证明生产死锁，也不足以完全排除调度问题。本次不更改生产调度、授权和 Shell 执行逻辑。完成等待上限改为 60 秒，竞态屏障改为 20 秒，低于 HTTP 客户端的 30 秒期限；屏障顺序、任务必须完成、原始结果和请求次数断言全部保留。超时后打印所有线程栈，供下一次 CI 区分缓慢执行与真实阻塞。这两项仍需 CI 运行验证，不能视为已经证实根因并消除。
