# 长期研究与知识复用

Research 继续使用现有任务入口、driver、工具、effect 和恢复机制。新增的长期
知识能力也供 coding、混合任务和普通问答使用；没有独立的研究 worker 或执行账本。

## 如何使用

重启 Codey 后，在原来的 Research 入口提出问题即可。可以直接说明：

> 调查这个问题，比较支持与反对的材料，把值得复用的结论、成立条件、原始出处
> 和尚未解决的问题保存下来。

之后新建会话，用不同措辞提问，例如：

> 结合以前的研究，找出这个新问题可能共享的机制。说明召回依据，检查类比的
> 条件；新的联系先作为候选推论保存，不要把机制类比当作已验证结论。

普通问答和 coding 也可以召回已有知识；深入调查仍选择 Research。模型可以
继续调用知识搜索和读取工具，并按机制、约束等词补查，而非只靠第一次自动召回。
实际保存和引用的质量仍取决于模型是否正确执行工具、理解来源和保留限制。

私人观察可以明确要求保存到个人范围，并保留陈述时间与尚未核实的身份。个人范围
在同一个知识空间中跨会话有效；session 范围仅在当前会话可用，project 范围受项目限制。
个人空间是单一所有者设计，不是多用户权限系统。引用受限前提的研究报告继承其范围；
无法表示的混合受限范围会明确拒绝保存，不能自动发布成公共知识。

## 已实现的行为

- 来源正文及版本、精确证据片段、主张、观察、实体与别名、候选推论、问题和研究回答。
- 条件可标为已报告、来源未报告、尚未提取或不适用；空条件不代表普遍成立。
- 证据在关系上支持、反驳或限制主张；旧回答不能作为新的独立支持证据。
- 以名称、别名、全文和有限关系扩展召回；结果附版本、原因、路径和限制。
- 显式身份、乐观版本检查与幂等提交；相似文字不会自动合并对象。
- 依赖固定版本；前提变化或撤回时，下游结论提示复查，历史内容不被悄悄覆盖。
- 研究报告与证据图引用同一知识版本；图上可检查条件、出处和候选身份。
- 组合软件、实验、因果、医学、历史、商业、数学等研究方法提示，不限定论文研究。
- 研究续查的外部动作通过共享内核执行，沿原 operation 恢复；预算不会因恢复重置。

关联路径、出现频次、Ghost 偏好和模型给出的置信数字都不会增加证据强度。
引用检查证明对象和版本存在，不证明模型已经正确解释材料。

## 数据与 Markdown

当前知识空间下的 `.codey/knowledge.db` 是权威存储。首次打开会事务导入旧笔记，
保留原 Markdown 和旧索引供核对；历史笔记不会凭空补出缺失的结构化证据。
索引重建从数据库进行。备份知识空间时应包含数据库；不要只备份导出的 Markdown。

Markdown 是显式交换格式：`KnowledgeStore.export_note(id)` 导出；
`import_markdown(text, expected_revision=...)` 校验版本后导入。
外部编辑导出文件不会自动写回数据库；导出失败不撤销已成功的知识事务。

修订保留历史，撤回保留原因；隐私清除则删除知识正文、相关依赖、笔记历史、索引和
受管理的笔记导出，并阻止原提交重放复活。执行回执、获取材料的受管理输出和外部备份
各有自己的保留周期，知识清除接口不声称清理这些独立副本。

## 验证与实际限制

定向测试覆盖存储、协议、授权、版本图谱、真实任务入口，以及子进程中断恢复。
模型实测脚本是 `tests/manual/persistent_research_local.py`，经过正式 headless 入口，
分进程执行研究、召回与修订；使用固定的 SQLite 官方文档，隔离搜索排名的变化。
它不是全网检索质量或医学判断的评测。

完整结果与已知失败记录在 [实施进度](research-knowledge-progress.md)。系统目前使用
SQLite 的名称/全文检索和有界关系遍历；没有加入向量服务、自动语义合并、持续自主研究
调度或完整学科本体。新联系的提出和证据解释由当前模型完成。
