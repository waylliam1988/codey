# Codey 0.4 A/B Stabilization / Release Evidence Baseline

## 定位

0.4.13 已经把 0.4.x 的核心闭环接起来：

```text
Context Boundary
  -> Evidence / Research
  -> CompletionProof
  -> Repair Context
  -> Verification
```

从 0.4.14 开始，0.4 不再继续堆大能力。主线改成
**A/B stabilization / release evidence baseline**：用真实网页模型把 coding、
research 和 Ghost 的实际使用闭环磨稳定。

目标不是证明所有 provider 都赢，也不是追求 prompt 一次完美，而是证明：

```text
能完成 coding
能诚实停止
能记录证据
能分析失败
能从失败修复
能避免 Research / Ghost 污染 evidence
```

核心成功标准是：

```text
失败可归因
修复可验证
收益可复盘
网页额度不乱烧
```

## 冻结规则

0.4.14 之后的 0.4 stabilization commit 必须小而可解释：

```text
一个问题
一个根因
一个 deterministic test
一个小 commit
```

允许：

```text
修 A/B 发现的真实 bug
补 deterministic test
修 journal / transcript / result schema
修 provider stall 分类
小范围 prompt clarification
```

禁止：

```text
新目录迁移
新 Manager / Scheduler / 大型抽象
大 prompt 重写
大规模行为重构
同时修多个不相关问题
```

如果必须违反这些冻结规则，先单独写设计说明和风险，不把它混进 A/B 修复 commit。

## 结果目录

所有 live arm 必须写入固定目录，避免临时文件成为不可复盘证据：

```text
tests/manual/results/0.4.14/
  deepseek/
    coding_completion_core/
      control_done/
      proof_only_block/
      repair_context/
      repair_context_minimal/
    coding_completion_extended/
    research/
    ghost/
  glm/
  mimo/
  qwen/
  stepfun/
```

后续 0.4.x patch 可以继续使用同一 evidence baseline 目录，除非 schema 发生明确
breaking change；breaking change 必须单独记录。

## Arm Manifest

每个 arm 必须有一个 manifest。最小字段：

```json
{
  "provider": "deepseek",
  "arm": "repair_context",
  "suite": "coding_completion_core",
  "cases": ["case_001", "case_002"],
  "git_commit": "0ead2c8",
  "dirty_state": "clean",
  "output_json": "tests/manual/results/0.4.14/deepseek/coding_completion_core/repair_context/result.json",
  "journal_dir": "tests/manual/results/0.4.14/deepseek/coding_completion_core/repair_context/journal",
  "transcript_mode": "archive",
  "transcript_dir": "tests/manual/results/0.4.14/deepseek/coding_completion_core/repair_context/journal/transcripts",
  "started_at": "2026-08-26T00:00:00Z",
  "finished_at": "2026-08-26T00:10:00Z",
  "stop_reason": "completed",
  "provider_error_class": null,
  "codey_failure_class": null
}
```

要求：

```text
git_commit 必须是真实 HEAD
dirty_state 必须记录 clean / dirty
output_json 必须逐 row 落盘
journal_dir 必须能还原 send/reply 边界
archive transcript 只属于 manual 层，不能进入生产 RunTrace / EvidenceLedger
```

## 失败分类

每次异常先归因，再决定是否继续消耗网页模型额度：

```text
provider_send_error
provider_no_reply
native_search_stall
webpage_ui_changed
prompt_confusion
harness_bug
codey_runtime_bug
product_behavior_regression
```

处理规则：

```text
provider_send_error          先记录，不立刻改 Codey
provider_no_reply            先记录，不立刻改 Codey
native_search_stall          记 provider/native-search，不算 planner 失败
webpage_ui_changed           修 driver / selector，补 provider test
prompt_confusion             小范围改 prompt，必须用 transcript 证明
harness_bug                  修 harness，补 deterministic test
codey_runtime_bug            修 runtime，补 deterministic test
product_behavior_regression  修产品行为，补 regression test
```

不要把 provider 限流、native search 卡住或网页 UI 变化误判成 Codey 能力失败。

## Provider 顺序

第一轮只跑一个 provider，先用它验证 harness 和 Codey 自身：

```text
DeepSeek -> GLM -> Mimo -> Qwen -> Stepfun
```

DeepSeek 先跑。Qwen 放后面，因为 native search / 网页状态更容易卡住，必须有单独
stall 归因，不能污染 planner 或 Research 结论。

## 执行纪律

每次只跑一个网页模型、一个 suite、一个 arm。

每个 arm 的流程：

```text
1. 确认 git status / HEAD / dirty_state
2. 运行单 arm live A/B
3. 写 result JSON
4. 写 journal
5. 写 transcript / digest
6. 立刻分析 result JSON
7. 立刻看 journal
8. 立刻看 transcript
9. 写 arm verdict
10. 决定是否继续下一个 arm
```

建议第一轮 transcript 用 `archive`，方便 prompt-lab；稳定后 routine smoke 可以降为
`digest-only`。

## Coding / Completion 阶段

先跑 0.4.13 的核心闭环：

```text
control_done
proof_only_block
repair_context
repair_context_minimal
```

核心 arm 稳定后，再跑扩展：

```text
read_before_edit
scoped_task_plan
verification_review
impact_guard
```

每个 arm 记录：

```text
completion_correct
false_completion_count
honest_block_count
repair_attempt_count
repair_success_count
unnecessary_repair_count
provider_stall_count
tool_call_count
turn_count
evidence_quality
journal_replayable
transcript_replayable
```

重点判断：

```text
假完成是否下降
是否能诚实 block
是否正确区分环境失败和代码失败
repair context 是否帮助模型
是否出现过度 repair
tool call 数是否合理
最终 patch 是否更小、更准
transcript 里模型是否理解 Codey 的约束
```

## Research 阶段

Coding / Completion 核心稳定后再跑 Research：

```text
bounded_research_planner_ab.py
longitudinal_research_harness_ab.py
research_comparison_benchmark_ab.py
deep_research_core_ab.py
source_connector_ab.py
source_connector_done_ab.py
search_coverage_ab.py
```

通过标准不是“回答最好看”，而是：

```text
证据链完整
引用和 claim 对得上
失败路径诚实
不会编造缺失证据
stale claim 被识别
unsupported claim 被隔离
native-search stall 被正确归因
journal 能解释为什么得出结论
```

没有真实 OpenScience head-to-head artifact 时，只能说
`OpenScience-style regression passed`，不能说 surpass。

## Ghost 阶段

Research 稳定后再跑 Ghost：

```text
ghost_continuity_ab.py
ghost_research_continuity_ab.py
ghost_router_ab.py
ghost_signal_extractor_ab.py
ghost_work_queue_production_ab.py
```

硬边界：

```text
Ghost 不能自动触发 Research
memory 不能当 evidence
旧事实不能直接变成 citation
continuity 只能作为 planning hint / continuity hint
continuity 不能污染当前任务结论
work queue 不能误触发 Research
```

如果 transcript 显示模型把 Ghost hint 当成事实，先停跑，修 prompt/context wording，
补 deterministic test，再重跑对应 arm。

## 停跑规则

遇到任一情况，当前 provider 停跑：

```text
连续 2 次 provider_no_reply
任何 webpage_ui_changed
任何 harness_bug
任何 codey_runtime_bug
任何 product_behavior_regression
journal 缺关键事件
transcript 没有落盘
result JSON schema 不完整
```

停跑后流程：

```text
1. 锁定失败 arm
2. 读取 result JSON / journal / transcript
3. 归类失败
4. 如果能 replay，就先 transcript replay / local scorer
5. 写最小修复
6. 补 deterministic test
7. 跑 ruff + targeted pytest
8. 必要时只重跑失败 arm
9. 再继续 provider 后续 arm
```

省网页额度的规则：

```text
能用已落盘 transcript 判断的，不立刻重跑网页
能用 local scorer/replay 验证的，先本地验证
只有需要确认真实 provider 行为时，才重跑 live arm
```

## Verdict

每个 arm 给四档人工 verdict：

```text
pass
pass_with_provider_noise
fail_codey_bug
fail_harness_or_provider
```

`pass_with_provider_noise` 必须写清楚噪声类型，例如 provider 限流、native search stall、
网页 UI 瞬时异常或非稳定 no-reply。

## 修改策略

Coding 问题优先修：

```text
假完成
没有读文件就编辑
把测试失败误判成完成
repair context 太吵
verification policy 判断过松
```

Research 问题优先修：

```text
unsupported claim 没隔离
stale claim 没标注
引用和 claim 对不上
搜索失败被写成事实
native search stall 没归因
```

Ghost 问题优先修：

```text
memory 被当 evidence
旧事实进入 citation
Ghost 自动扩大任务范围
continuity hint 影响最终事实判断
work queue 误触发 Research
```

任何修复都必须补 deterministic test；live A/B 只证明真实网页路径没有坏，不能替代
回归测试。

## 0.4 完成门槛

满足下面条件后，才认为 0.4 打磨完整，可以进入 0.5：

```text
DeepSeek 全套通过
至少一个第二 provider 通过 coding + research 核心套件
Qwen stall 有明确分类和降级策略
Ghost 不污染 evidence
所有 Codey bug 都有 deterministic test
所有修复都有小 commit
每个 arm 都能从 JSON + journal + transcript 复盘
```

0.5 之后才适合做更大的能力路线，例如 provider scheduling、cross-provider consensus、
research benchmark 强化、长期记忆策略升级和 protocol/dialect 学习。0.4 的收尾只做一件事：

```text
把真实使用闭环打稳。
```
