# 整篇研究交付：实施与验证记录

起点：`ca29a4ff`。目标是让固定本地 Gemma4 12B 在原 kernel 中直接读取材料、提交带引用和缺口的整篇回答；原发布事务是唯一答案知识写入。没有第二套研究循环，不增加可写正文缓存。模型声明、执行交付和内容验收分别记录。

## 第一批：冻结合同与证据归档准备

- 新增整个任务的冻结 scope、`markdown + state` 提交合同、由原阅读回执稳定派生的 eN 短引用。
- 引用只允许本轮实际呈现的整窗；未呈现窗口不可引用。重复读取不重编号，同一 URL 的新版本不覆盖旧引用。代码示例中的引用不自动采用。
- 跨来源提交准备原 KnowledgeStore 的 source/evidence 变更，不拆分或制造 claim；答案留在原发布事务写入。本批准备函数不执行知识写入。
- 冻结报告保留正文引用位置、原 passage、来源及证据版本。失败调查可以形成真实 unresolved 报告，不制造来源。
- 本批尚未接通生产默认入口，也未发起模型请求。

验证：新增合同/归档测试及原 finding 相关测试 **20 passed, 2 deselected**；Ruff、`git diff --check` 通过。原 finding 文件的两项 shared-driver 测试在未修改的 `ca29a4ff` 独立 worktree 中同样失败（旧脚本提交字符串计划，随后 StopIteration），故单独记录，后续随新入口测试更新；没有把它们算作通过。未运行全量 pytest。

## 第二批：接通普通研究默认入口

- 新建的普通 strict research 使用完整任务与 `markdown + state`，取消强制计划、逐题、finding/采用手续。历史冻结合同仍按原 required_checks 与 scope 版本解码。
- 原 kernel 冻结材料标签与工具 schema，原 effect 记录提交；完成检查验证明确引用与原始阅读回执。正文不通过另一模型改写。
- 原发布事务原子保存所选 source/evidence 与唯一 answer；synthesis note 是原事务中的展示投影，不增加另一套提交/发布循环。不自动生成 claim。
- 发布证明绑定已结算 answer 的精确版本和报告摘要。普通缺口报告可交付；open_question 在 partial/unresolved 时仍保持未解决。
- 本批实现首次发布，未新增一般答案编辑接口。后续修改仍须通过原知识版本机制，不能编辑冻结提交或展示投影来改变正文权威。

验证：相关合同、读取复用、完成、队列和真实进程恢复测试 **145 passed**。其中新入口覆盖 JSON/native、错误引用修复、缺口交付，以及请求冻结、响应冻结、工具执行、kernel 结算、发布准入、知识提交、发布回执七个中断点；恢复不重复模型请求或知识写入。架构检查 **99 passed, 3 failed, 460 subtests passed**；三项失败均在未修改的 `ca29a4ff` 独立 worktree 复现（工具名单基线、已有超长文件、report_sections 非 stdlib 依赖），未放宽检查。本批仍未请求实机模型，离线通过不等于内容质量通过。
