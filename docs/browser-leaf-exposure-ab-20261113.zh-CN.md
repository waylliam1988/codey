**四个浏览器叶工具直接显露：源码检查、授权测试与自主实机 A/B**

结论：直接入口改善了本轮模型的操作采用和完成率，但没有减少总请求或输入 token，尚不据此默认开放四个工具。正式矩阵为 4 个页面任务、每个任务两种问法、每对各运行一次，共 16 个自主实机单元。任务完成 A 为 2/8，B 为 6/8；需要交互的 6 个单元中，操作与更新正文读回 A 为 0/6，B 为 6/6。B 有两次操作成功后仍在最终提交阶段失败。

**已有输入绑定实现的检查。** 核对了 `2159b41c` 和 `2d94a0e7` 中与本轮有关的绑定、规范化、恢复与失败交付代码。模型输入由冻结的 `ModelInputBinding.model_spec` 提供；上传和复制在 `normalize_turn` 中验证、转换，然后进入原执行合同；恢复会核对合同、能力和复制观察；`CopyTurn.data_json` 保存不可变观察，读取时返回脱离原对象的视图；固定模板失败交付使用模型合同，已提交子动作继续由原回执承载。未发现阻塞本实验的问题，相关 60 项已有回归通过。这不是对两个提交全部改动的全面审计。

现有兼容性限制需要保留说明：`restore_snapshot` 只接受 v6，v1–v5 会明确拒绝恢复，要求建立新请求。这是当前实现可观测的行为变化，不能将其描述为完整保留旧版本在途请求的恢复兼容性。本次未修改该策略，也未修改任何 `codey/` 文件。

**实验如何接入。** [脚本](../tools/browser_leaf_exposure_ab.py) 仅在实验进程中包装 `build_turn_snapshot`。A 原样使用生产快照；B 向模型可见工具增加 `browser_snapshot`、`browser_fill`、`browser_click`、`browser_read`。原 CodeMode 入口和全部嵌套能力保留。

四个入口复用快照中的原 `ToolSpec` 和执行器，工具定义按名称仍只有一份；文本合同和原生声明从原冻结定义生成。每次构建均核对 B 与其生产基线的授权、controller 限制、嵌套能力、定义和执行器未变，并通过生产快照保存与恢复往返。显露尊重显式 `model_tool_names`，也不会绕开上传、网页复制等简化输入绑定。没有注册新工具，没有替换解析器或执行器，没有重写模型回复，没有增加等待、自动读回或完成判定。

两臂通过生产 `run_headless`、Chromium、kernel 和 durable receipts 运行。共同预取的正式 `open_url` 回执先于模型请求，16 项均确认首次模型请求前已有绑定页面。页面只使用同步更新。校验器在工具事件后、页面关闭前旁路读取实际字段值与有效点击计数；这些测量值不进入模型请求，也不成为模型证据。

任务不包含 CodeMode、unwrap、工具名、引用编号或预期业务答案。交互场景的验收值未出现在首次模型 HTTP 请求中；双引号和换行的备注原文属于用户要求输入的内容。正式版之前的探索采样仅用于检查夹具和验收，不计入以下结果。

B 的四个填写单元均在填写后尝试旧按钮引用，生产在点击前拒绝，模型随后刷新观察并恢复。有效点击每个交互单元恰好一次，合计 6 次；4 次旧引用调用均未造成实际点击。直接工具仍然需要模型理解引用失效，不能宣称已消除这种负担。

**证据与收益的解释边界。** Chat 按生产指导引用 `[sN]`，验收通过原回执的 `canonical.source_id` 核对来源，并另查包含请求事实的完整正式正文。B 六个交互单元都读到了更新正文并引用了该来源。`sN` 是来源级引用，单靠它不能证明模型绑定了某个精确正文版本；本轮没有精确 passage 引用，不能将来源引用等同于版本级引用验证。

两臂的 JavaScript 提案和解包错误都是零：A 多数没有开始操作，B 采用直接工具。因此本轮证据支持“工具直接显露使模型更容易选择并执行操作”，尚未测到“原本会生成的 JavaScript 变少”或“解包错误率下降”。多行输入在 B 正确落入实际 textarea，但没有成功的 A 编程操作可用于比较编码错误。

每种问法每臂仅一次，覆盖 4 个受控页面、1 个本地模型。不能外推到任意网站、异步页面、原生工具协议或其他模型。四个工具成组显露，也不能据此判定其中某一个工具的独立收益。

**默认开放判断。** 本次保留实验，不修改生产默认。直接入口有继续验证的依据，但整组开放仍伴随更高调用成本、旧引用恢复和下游交付失败。下一步适合独立比较入口组合，例如先开放观察与读取，再加入填写与点击；网页来源与知识对象引用混用也应作为独立问题处理，不能混进本轮候选后宣称是工具显露收益。
