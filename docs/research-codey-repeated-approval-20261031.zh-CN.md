# Codey 审批续接重复问题排查与验证（2026-10-31）

Codey 存在两处已确认的代码缺陷：审批续接时运行任务描述被控制指令占位文本替换，以及同一次命令执行被显示成两条记录。修复后，当前 Qwen/KoboldCpp 的原连接和重新连接两种实测均只执行一次命令，然后读取结果并结束。

- 运行：`run_10cd49ec73ab4afdb33cc4a7ffd9c913`。

## 已修复的代码问题

### 审批控制输入污染运行任务描述

`TaskSubmission.from_input(ResolveShellApproval(...))` 使用 `Resolve the shell approval` 作为占位任务。调度器虽然读取了持久化的原始任务，但重新构造 submission 后，运行 session 和观察信息仍使用了这个占位文本。

原始任务并未从整个模型历史中消失，但续接请求出现了互相不一致的任务描述。现在通过审批与原运行的身份校验后，从原任务 checkpoint 恢复任务文本，并同步请求和任务开始事件。缺失原始任务时拒绝继续。

### 同一次执行出现审批卡和普通工具行

审批执行发布 `shell_result`，内核随后发布同一次执行的普通 `tool` 记录。原实现按审批 ID 和工具调用 ID 分别渲染，缺少关联。

现在执行开始、完成、过期事件均携带原 `call_id`，公开事件流和前端保留该身份。前端按运行 ID 与调用 ID 合并为一张命令卡，兼容事件逆序、重放和迟到的开始通知。不同调用或不同运行中的相同命令仍分别显示。
