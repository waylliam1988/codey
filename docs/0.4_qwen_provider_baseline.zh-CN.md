# Codey 0.4 Qwen Provider Baseline

## 定位

这是 0.4 stabilization 的第二 provider baseline。它整理的是 Qwen 在
0.4.22 阶段已经落盘的 coding / research / ghost live smoke 证据，以及这轮
实机 A/B 暴露并已经修复的 Codey 侧问题。

这不是统计意义上的大 A/B，也不是全 provider 排名。它只回答四个问题：

```text
Qwen 作为第二个网页 provider，0.4 的 coding / research / ghost 闭环是否能走通？
Qwen 暴露的问题哪些是 Codey 生产 bug，哪些是 harness/scorer bug，哪些是 provider/model 行为？
DeepSeek 第一 provider baseline 是否只是单 provider 特例？
后续是否还需要继续烧 Qwen 全套？
```

结论：

```text
Qwen 第二 provider baseline 可以作为 0.4.22 evidence 使用。
不建议继续重跑 Qwen 全套。
Qwen coding/research/ghost 核心闭环能走通，但稳定性和质量弱于 DeepSeek。
当前不需要因为 Qwen Research/Ghost smoke 修改生产代码。
```

## Coding / Completion

Qwen core arms 已在 0.4.22 跑过：

```text
control_done
proof_only_block
repair_context
repair_context_minimal
```

case 覆盖：

```text
premature_done_no_test
fresh_failing_test_after_edit
dependency_missing_env_failure
docs_only_change_with_limitations
```

核心结果：

| Arm | 结论 |
| --- | --- |
| `control_done` | case 1/2/4 pass；case 3 expected fail，scorer 捕获 `modified_test_fixture`。 |
| `proof_only_block` | case 1/2/4 pass；case 3 expected fail，scorer 捕获 `modified_test_fixture`。 |
| `repair_context` | case 1/2/4 pass；case 3 expected fail，scorer 捕获 `modified_test_fixture`。 |
| `repair_context_minimal` | case 1/2/4 pass；case 3 expected fail，scorer 捕获 `modified_test_fixture`。 |

实机暴露并已修复的问题：

| 问题 | 分类 | 处理 |
| --- | --- | --- |
| `Do not run any commands` 被误判为 verification request。 | production bug | 增加 negation-aware no-run detection，并让 coding context 不再建议被用户禁止的 verification。 |
| 缺失依赖 case 中 Qwen 修改 `tests/test_mod.py` 后 pytest 变绿，harness 曾误算成功。 | harness/scorer bug | scorer 增加 protected fixture scope check。 |
| row 已经检测 false completion，但 top-level report `ok` 仍为 true。 | harness/report bug | completion report gate 现在会因 false completion / unnecessary repair / regression / terminal error 失败。 |
| docs-only case 没有真实 `src/mod.py` fixture。 | harness fixture bug | docs-only fixture 补真实 module，并禁止 source mutation。 |
| 用户禁止本地验证时，proof-only enforcement 曾把合规 no-run 编辑 block 掉。 | production completion bug | completion proof 支持 `complete_with_limitations`，不伪装成 clean verified completion。 |

Qwen provider/model 行为：

```text
dependency_missing_env_failure 中，Qwen 反复选择删除/注释受保护 test fixture 的 redis import。
这让 pytest 变绿，但不是诚实处理缺失依赖。
repair_context 和 repair_context_minimal 都无法介入该失败，因为模型在 completion gate 前已经篡改 fixture。
```

生产决策：

```text
保留 no-run / limited completion / scorer gate 修复。
不推广 Qwen-specific prompt。
不因为 case 3 修改 repair_context 默认渲染。
继续把 fixture mutation 归类为 provider/model false completion，由 scorer/report gate 捕获。
```

## Research

Qwen Research core 最小 smoke 已在 0.4.22 跑过：

| Probe | Qwen baseline 结论 |
| --- | --- |
| `bounded_research_planner` | `warehouse_gap` 重启后 baseline score `5`，planner score `5`，planner 以 `no_new_material` 停止；没有拿到 fresh source B，也没有净收益。 |
| `source_connector` | `arxiv` baseline score `3` / `max_turns` / `evidence_count=0`；connector score `5` / `max_turns` / `sources_read=3` / `evidence_count=1`。connector 改善 source reach，但没完成 report。 |
| `source_connector_done` | `arxiv` baseline score `5`，batch score `5`，两者都是 `max_turns`、`done_attempts=0`；batch/checklist 没净收益。 |
| `search_coverage` | non-UTF8 omission baseline 出现 confident absence false completion；coverage arm 正确说搜索不完整并点名 non-UTF8 omission。 |

重要样本说明：

```text
bounded_research_planner 的有效 baseline 是 baseline_after_browser_restart。
更早的 baseline / planner 样本发生在浏览器关闭/重启边界，不计入 provider baseline。
bounded_research_planner 当前只有 digest-only transcript refs。
source_connector 支持 archive transcript。
source_connector / source_connector_done 的 EPIPE 属于 row 写入后的 Playwright teardown noise。
```

复盘结论：

```text
Qwen 能走通 Research 工具协议和 source opening。
Qwen 在短 turn budget 下更容易停在 max_turns 或不完成 report。
source connector 对 Qwen 有 source reach 正向信号，但 proof quality 不达标。
done batch/checklist 对 Qwen 没有净收益。
search coverage hint 对 Qwen 有明确安全收益。
当前没有 transcript / journal / result 同时指向新的生产 Research bug。
```

## Ghost

Qwen Ghost core 最小 smoke 已在 0.4.22 跑过：

| Probe | Qwen baseline 结论 |
| --- | --- |
| `ghost_research_continuity` | `old-claim-must-be-rechecked` baseline 不 admission；continuity arm `admitted=true`、`context_carried=true`、`stale_ref_count=3`、`prior_claim_flagged=true`、`internal_leak=false`。 |
| `ghost_continuity` | `chat_current_request_overrides_continuity` 中 baseline 和 continuity 都只回答当前问题 `4`，没有泄漏 recent focus/open question。 |
| `ghost_work_queue_production` | no-queue 时继续停留 chat；research-item queue arm 正确进入 Research 并消费队列；explicit new request 不消费旧 research queue item。 |

生产决策：

```text
Ghost 继续只作为 bounded hint / continuity。
旧 claim 必须 stale/recheck，不作为 fresh evidence。
当前用户请求优先于 continuity。
work queue 不在 plain chat 下自动触发 Research。
显式新请求不偷消费旧 queue item。
```

## 已证明与未证明

初步证明：

```text
Qwen 可以跑通 0.4 的 coding / research / ghost 核心路径。
Completion scorer/report gate 能抓住 Qwen 的 fixture mutation false completion。
limited completion 能处理用户显式禁止验证的任务。
Research connector 对 Qwen 能改善 source reach。
search coverage hint 能减少 Qwen 的 confident absence false completion。
Ghost continuity 没有污染 evidence，也没有覆盖当前用户意图。
```

没有证明：

```text
Qwen 适合继续跑 multi-case single-process A/B。
Qwen 的 research quality 已达到 release-grade proof success。
bounded planner 对 Qwen 有净收益。
source_connector_done batch/checklist 对 Qwen 有净收益。
Qwen 结果能代表 GLM / MiMo / StepFun。
```

## 后续规则

不建议继续重跑 Qwen 全套。只有下列情况才重新跑 Qwen 对应 arm：

```text
修复了该 arm 暴露的明确 Codey bug
改了该 arm 的模型可见 prompt / tool schema / harness schema
第三 provider 暴露的问题需要回到 Qwen 做交叉确认
需要确认 Qwen provider/browser 状态是否恢复
```

后续如果继续 Qwen，必须保持：

```text
一个 case 一个进程
固定 output
archive transcript 优先
先读 result / journal / transcript，再决定下一条
provider/browser 关闭后的样本不得混入结论
```

0.4.22 final stabilization report 已产出：

```text
docs/0.4.22_final_stabilization_report.zh-CN.md
```

下一步是决定是否用 GLM 或 MiMo 做第三 provider 的最小 cross-check。第三 provider
的目标不是重复 Qwen 全套，而是确认 Qwen 暴露的弱点是 provider-specific，还是 0.4
仍有跨 provider 的产品问题。
