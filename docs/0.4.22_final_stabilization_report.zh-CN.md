# Codey 0.4.22 Final Stabilization Report

## 定位

这是 0.4 stabilization 的最终收口报告。它合并 DeepSeek 第一 provider baseline
和 Qwen 第二 provider baseline，用来判断 0.4 是否已经完成“实际使用闭环打磨”，
以及进入 0.5 前还需要补哪些最小确认。

这不是统计 benchmark，也不是 provider 排名。它只回答：

```text
0.4 的 coding / research / ghost 闭环是否能在真实网页模型上跑通？
A/B 暴露的 Codey bug 是否都已修复并有 deterministic test？
哪些 treatment 可以进入生产默认，哪些只能保留实验结论？
进入 0.5 前是否还需要第三 provider cross-check？
```

总判断：

```text
0.4 的核心闭环已经成立。
DeepSeek 第一 provider baseline 已冻结。
Qwen 第二 provider baseline 已形成，能证明 0.4 闭环不是 DeepSeek 单 provider 特例。
当前没有未归因的生产 Codey bug 要阻塞 0.4.22。
进入 0.5 前可以选择补 GLM 或 MiMo 的最小 cross-check，但不需要继续烧 Qwen 全套。
```

## DeepSeek Summary

DeepSeek 是第一 provider baseline，用于确认 0.4 的 coding / research / ghost
闭环能在真实网页模型上端到端跑通。

| Domain | 结论 |
| --- | --- |
| Coding / Completion core | `control_done` 暴露 false completion baseline；`proof_only_block` / `repair_context` / `repair_context_minimal` 能把环境失败转成诚实 block。requested-verification 低层循环已修复。 |
| Coding extended | `verification_review`、`read_before_edit`、`scoped_task_plan`、`impact_guard` 都有可复盘 smoke；只保留正向信号，不扩大默认 prompt。 |
| Research | bounded planner 有正向 smoke；source connector archive rerun 可走通并完成；source_connector_done batch/checklist 没净收益。 |
| Ghost | continuity 能作为 bounded context admission，旧 claim stale/recheck，不污染 evidence；当前请求能覆盖 continuity；work queue 没误触发 Research。 |

DeepSeek 决策：

```text
DeepSeek baseline 冻结。
不再重跑 DeepSeek 全套。
只有修对应 bug、改模型可见面、或第三 provider 需要交叉确认时，才重跑对应 arm。
```

## Qwen Summary

Qwen 是第二 provider baseline，用于确认 0.4 闭环不是 DeepSeek 特例，并暴露
provider-specific 的不稳定点。

| Domain | 结论 |
| --- | --- |
| Coding / Completion core | 四个 core arms 已逐 case 跑完。case 1/2/4 通过；缺失依赖 case 反复出现 `modified_test_fixture` false completion，scorer/report gate 能捕获。 |
| Research | bounded planner 无净收益；source connector 改善 source reach 但没有完成 report；source_connector_done batch/checklist 无净收益；search coverage hint 有明确安全收益。 |
| Ghost | continuity 被正确限制为 stale/recheck hint；当前请求覆盖 continuity；work queue 只在合适的 queue arm 消费任务，显式新请求不消费旧队列。 |

Qwen 决策：

```text
Qwen baseline 可作为第二 provider release evidence。
不继续重跑 Qwen 全套。
不推广 Qwen-specific prompt。
Qwen research 弱样本归为 quality / turn-budget / provider-behavior observation，不是生产 Research bug。
```

## Treatment Decisions

可以进入或保留在当前生产路径的结论：

```text
CompletionProof / repair enforcement 继续作为 coding done gate。
用户禁止本地验证时允许 complete_with_limitations，不伪装 clean verification。
completion A/B scorer/report gate 必须保留 protected fixture / false completion 检查。
Research search coverage hint 有明确安全收益，保留当前方向。
Ghost continuity 继续只作为 bounded local hint。
```

不推广的结论：

```text
不推广 Qwen-specific prompt。
不推广 source_connector_done batch/checklist。
不因为单样本扩大 scoped_task_plan / impact_guard 默认 prompt。
不把 source connector 写成已证明优于 baseline。
不把 bounded planner 写成跨 provider 稳定净收益。
```

## Risk Register

## Recommendation

推荐 0.4.22 作为 0.4 final stabilization baseline。

下一步有两个可选路径：

```text
Path A: 直接开启 0.5
  条件：接受 DeepSeek + Qwen 已足够证明 0.4 闭环，不再为 0.4 烧第三 provider。

Path B: 先补第三 provider 最小 cross-check
  建议 provider：GLM 或 MiMo
  范围：coding core 只跑 repair_context_minimal case 1/2/3/4；Research 只跑 search_coverage baseline/coverage；Ghost 只跑 current_request_overrides + no-queue/research-item。
  目的：确认 Qwen 的弱点是否 provider-specific，不追求重新证明全部 0.4。
```

我的建议是 Path B，但范围必须小。它不会阻塞 0.4.22 report，只作为进入 0.5
前的额外交叉确认。若第三 provider 也没有新的生产 Codey bug，就可以开启 0.5：

```text
verified completion
  -> durable operation state
  -> effect intent / settlement
  -> replay policy
  -> provider / protocol / project habit learning
  -> bounded context admission
  -> quieter but more reliable runs
```
