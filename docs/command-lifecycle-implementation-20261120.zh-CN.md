# 命令生命周期改进与验证（2026-11-20）

本轮覆盖生产 `run`，包括 CodeMode 中的 `tools.run`。

默认调用先等待 10 秒：完成就返回结果；仍在运行就返回同一次执行的 `task_ref`。完成后的状态和有界输出由程序在下一次模型请求中递送。模型提前提交 `done` 时，程序等待已有任务结束并递送正式结果，不要求模型轮询。

显式 `run_in_background=true` 继续立即返回引用；`false` 继续同步等待。超时、取消和不完整输出沿用原有执行器及其收据。

## 实现与事实归属

- 复用已有 durable 子任务、调度器、取消和恢复机制。自动等待时，将原调用的 pending 效果与子任务创建放在同一事务中；交还控制权不重新执行命令。
- 原调用只记录结果摘要和子任务／执行收据引用。退出码作为兼容显示字段投影；完整执行事实和验证事实来自子任务唯一正式收据，避免一次执行重复记验证。
- 自动通知复用 `task_output` 的结果投影。明确区分成功、失败、超时、取消、输出不完整、执行状态未知；总通知正文不超过 12,000 字符，包含 JSON 转义后的预算。
- 通知引用写入现有冻结模型请求。已收到并保存的正式模型回复、已结清发送、可能发出的请求都参与去重；确定未发出的请求不消耗通知。没有新增独立递送队列或执行运行时。
- 恢复原调用时，沿原效果标识寻找已有子任务，不重新启动进程。无法确认的外部执行仍按未知处理，不能自动重放。
- 读取旧版子任务输入时恢复其原有显式后台选项，新版保存原始调用参数。拒绝旧合同不允许的执行选项。
- 本轮修改文件清理了原有隐式 Any，并通过按文件启用的 `disallow_any_explicit/expr/unimported` 检查；未添加 cast、忽略指令或检查豁免。

参考思路来自 Codex 的默认有限等待、OpenCode 的完成结果递送，以及 DeepSeek Harness 的长命令转任务机制。实现接在 Codey 原有任务和收据上，未引入参考项目的另一套运行时。

## 剩余限制

- 自动通知在安全的下一次模型请求边界加入；不会打断正在生成的模型回复，也不会自行恢复等待用户输入的会话。
- 显式同步仍由 `false` 控制；模型可能自行选择这个选项，或主动查询中间输出。程序不修改模型参数来制造“自动化成功”。
- 原执行或发送结果无法确认时，保留未知状态，避免重复执行／递送；这不保证模型一定已理解结果。
- 输出只递送有界摘要，详细内容仍通过现有任务输出读取。进程结束而输出未完整收取时报告不完整。
- 实机为单一本地模型的有限样本，不代表所有模型都会遵循默认参数或停止轮询；确定性协议和恢复行为由回归测试验证。
