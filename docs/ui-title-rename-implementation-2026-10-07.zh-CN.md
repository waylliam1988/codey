# 顶部标题原位重命名：实现及验收记录

单击顶部聊天名称即可编辑；Tab 聚焦标题后，Enter 或 Space 也可进入。顶部菜单移除了 `Rename chat`，左侧各聊天菜单的 `Rename` 保留，可重命名其他聊天而无需先切换。

按最后的视觉反馈，顶部编辑框改为透明、无边框、无轮廓、无阴影，并关闭原生控件外观。文字与原标题对齐，标题栏高度保持不变；编辑状态由光标和原生文本选区体现。真实 WebView2 截图中，原先右侧括弧状的线段已消失。侧栏重命名继续使用原有灰色输入框。

## 行为约定

- 进入编辑时选中原名称；Enter 保存，Escape 取消，点击外部或切换聊天保存到最初编辑的聊天。键盘确认或取消后，焦点回到标题。
- 保存后，顶部、侧栏、搜索和持久化记录共同更新。输入为空或只有空格时保留原名称；沿用 80 字符限制。
- 只允许编辑聊天名称，项目面包屑和标题栏空白处不会触发重命名。窄窗口和侧栏收起时仍可使用。
- 回复或元数据刷新保留同一个输入框、未提交文字及选区。修改名称保留聊天草稿、正文 DOM、阅读位置和任务状态。
- 输入法组合期间的 Enter、Escape 和 229 键码不结束编辑；鼠标按下到松开之间完成组合时，不会吞掉切换聊天的点击。旧输入框的迟到事件不能提交或取消新聊天的编辑。
- 手动改名复用现有保存逻辑；可选 `titleRenamed: true` 标记通过前端规范化和后端存储保留，防止明确命名为 `New chat` 的聊天再次被自动标题覆盖。旧记录无需迁移。

交互和视觉约定同步到 DESIGN.md 的 §5.4。
