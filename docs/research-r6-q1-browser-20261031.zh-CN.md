# r6 格式登记、q1 答偏与浏览器退出收敛（2026-10-31）

本轮将明确的独立报告格式要求移出逐题 `task_refs`，没有删除原要求；冻结实际问题数量，
避免补登记时增加重复 q1；为已知的“数量限制被答成一般并发”增加有限拒绝检查。
浏览器密集路由退出反例在修改前出现 288 条未取回 future，修改后同样 12 轮为 0。
**完整 Research 内容仍未验收通过。最终检查的模型纠错实机复跑在首请求超时，
尚无最终纠错循环成功的实机证据。**

## r6：保留原文，让报告层承担格式要求

原始完整 WAL 任务的 r6 仍为 `给出约 800 字的中文研究结论，`，原文位置为
`start=123, end=140`。`task_requirements()` 的编号、原文和位置没有改变。
新投影将完整匹配的独立输出句放入 `report_requirements_checked_by_application`，
其余要求继续进入 `coverage_task_refs`。两个投影都来自原始任务，不从模型计划推断，
不另存一套任务或报告。原任务仍由现有 durable 输入和发布上下文保留。

本次保守支持独立中文输出句式，包括上述“约 N 字的中文研究结论”以及“请用中文回答”。
未识别句式和混合实质内容的句子继续要求显式覆盖，例如“给出约800字的中文研究结论并说明
版本边界”，不会被当成纯格式免除覆盖。没有自动填补任何实质 rN。

格式在统一逐题提案形成规范结论后、渲染和发布前检查：

- 范围是**结论正文整体**，不是每个答案，也不是重复呈现后的整份报告。
- 计数为非空白字符，移除引用标记；标题、来源表、证据及覆盖章节不加入计数。
- 产品约定“约 N 字”为包含两端的 ±20%；约 800 字对应 640–960，约 100 字对应 80–120。
- 中文采用有限文字检查：汉字数须大于拉丁字母数且至少一个汉字，不验证翻译或内容语义。
- 不满足时修改已有答案，不创建格式问题，不补造覆盖记录。

旧已接受报告不重建；`FindingReport` 的持久化字段及摘要格式未改变。
旧记录若已包含 r6，验证兼容它且不改写原 payload；当前冻结契约只让模型选择仍需覆盖的编号。
仅有已识别格式要求时，`task_refs=[]` 合法，但格式仍检查。

## 补 rN 不再增加覆盖记录

登记 N 个问题后，JSON 与 native 的同一冻结 schema 都要求覆盖数组恰好 N 行，
question_ref 仍只能选择实际登记的 qN，示例也生成同样的 N 行。
额外追加 q1 在契约层被拒绝；数量相同但编号重复，仍由原唯一性检查拒绝。
新增诊断指出重复记录的原位置，要求修改其 `task_refs`，不合并或接受重复记录。

漏 rN 的反馈现在显示缺失原文，要求修改已有问题行，避免只给编号让模型猜测。
**这不能保证模型一定遵守反馈。** 第一轮实机依然重复提交漏登 r1/r10/r11 的提案，
没有为了成功自动归属这些要求，也没有放宽无进展停止条件。

## q1：拦截已知答偏，不构成蕴含证明

当前逐题提案增加小范围负检查：对于明确使用单个/至多等数量边界措辞的问题，
如果答案只给一般并发描述，或者答案给出限制而所选支持 excerpt 只有并发描述、
缺少直接数量边界线索，则拒绝发布并指出原问题、现有引用及调查/修改路径。
只有相关观察时可以保留 `partial`，但须交代未解限制。
普通读写共存问题仍可用共存证据回答，不要求它证明排他数量限制。

历史 `research-q8-gap-20261031/live-03` 的原错误答案与完整知识证据版本被复制到临时库，
在不调用模型、不改写历史库的条件下执行新焦点检查，得到 `count_limit_not_addressed`。
这验证旧反例被拒绝，**不是完整历史任务实机重跑**。

本轮定点实机还暴露初版检查没有识别“单写者限制”措辞：其概述 excerpt 没有单写者保证，
却被用来支持正确但无选中证据依据的单写者答案。该反例已补为最终回归，包括答案只说
“存在单写者限制”时的漏检。最终实机复跑未拿到模型回复，不能声称模型已稳定修对。

检查只识别部分措辞下缺少必要线索的错误，不识别所有语言变体，不证明主体、条件、
数字或版本关系正确。含有“only one file”的证据也不因此证明“only one writer”。
测试明确保留“原文 one、答案 two”仍未经语义认证的边界；解释依旧 `unreviewed`。
不能继续扩张关键词后宣称建立了通用内容验收器，也没有恢复同模型正面自评通行证。

## 浏览器：先结束自有 context，再断开协议连接

原有 `unroute_all(behavior="wait")` 保留。新反例在真实隔离浏览器页面上产生 100 个被
生产网络守卫拦截的本地无效资源请求后立即退出；无模型调用，不向这些资源地址发出连接。
旧关闭顺序的 12 轮产生 **288 条**未取回 future，asyncio debug 创建栈指向 Playwright
协议 callback。等待路由处理器不足以让所有待回复协议请求在 `pw.stop()` 前结束。

`Session.close()` 现在仅在持有自有浏览器进程时，先关闭其 context，再停止 Playwright，
最后终止进程。共享浏览器的 context 和既有标签不关闭；fresh tab 仍遵循原规则。
一个 context 已关闭或报错时继续其余清理。没有安装异常过滤器、修改 Playwright、
吞掉日志或用固定 sleep 等待。

相同的 12 轮反例修改后为 0。已提交的手工回归入口可复现当前检查：

```powershell
python -X utf8 -u -m tests.manual.research_browser_teardown_local --directory .e2e-artifacts/browser-teardown-new --cycles 12
```

它保留原始 asyncio debug 日志，并在出现 TargetClosedError、未取回 future、遗留 pending
task、少退出一轮或子进程失败时返回失败。最终正式运行 12/12 退出，三类异常均为 0。
本轮三次真正建立浏览器的 Research 退出也均为 0。这修复了当前已定位竞态，
不承诺所有未来浏览器退出异常都不可能出现。
