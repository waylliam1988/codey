# Open Code Review 对 Codey 12B 自我审核的实验

日期：2026-10-11。结论：本轮直接借鉴组合没有提升质量，不建议合入生产。它有值得单独验证的设计，但不能据此说整个 Open Code Review 项目不如 Codey。

## 测试了什么

Codey 基线为 `4f0237e59ae505592ec479a92a5db42f43a2f68a`；参考项目为本地 `open-code-review`，提交 `a758d9cbfb689937c7857ad64b2dd66adb58c0c2`，Apache-2.0。

KoboldCpp 1.117.1，模型为 `koboldcpp/Gemma4-12B-QAT-Uncensored-HauhauCS-Balanced-Q4_K_M`。仅使用 loopback Local 连接，没有调用 Zen 或网页模型。

两个比较臂：

- **Codey**：当前生产审核提示、输出解析、审核适用性检查、修复、重新验证及完成流程。
- **参考借鉴版**：仅在实验子进程中替换审核 provider，读取参考项目真实主审核提示、Python 规则及工具定义，提供冻结工作区的有界 `file_read`、`code_search`，收集 `code_comment` / `task_done`。其后仍使用 Codey 原有修复与完成流程。

本机没有现成 Go/ocr 可执行程序，因此没有运行原生 OCR CLI。文件分组、计划、反思轮次、独立意见过滤、评论定位没有纳入这次比较。这里评价的是这个可复用组合，不是整个项目。

## 控制与验收

在模型调用前固定任务、种子 51/52、候选、预算和顺序。每个配对使用相同候选源码身份，交替先运行哪个比较臂；连接、会话、项目和工作区分别隔离，每个臂开始前等待后台空闲。

采样温度 0.2，输出上限 1536 tokens，有效窗口 32768，最多 14 Writer 轮次，每臂最多 20 次生成，300 秒墙钟上限。参考审核每次最多 4 次生成，读工具不允许写入、执行命令或访问冻结范围之外的文件。相同种子不意味着完全确定性。

固定候选共三类：包含端点的筛选、按键稳定去重、嵌套独立复制。每类都有错误候选和正确对照，可见测试对两者均通过，隐藏检查能区分它们。两个种子合计 12 个配对。

另有整数精确向上取整任务：12B 真实生产 Writer 在关闭实际审核调用的实验阶段生成候选，随后把同一份候选冻结回放给两种审核，两个种子合计 2 个配对。候选生成是否通过隐藏检查不作为准入条件。两次生成均留下负数分支错误，并有真实、当前的可见测试通过记录。

候选生成阶段关闭审核调用可能被现有完成门阻塞；这没有被伪装成生成任务完成。冻结准入接受“只有被关闭的审核阻塞交付、但源码与可见验证仍有效”的候选，拒绝取消、过期验证等结果。

这两组是同一个 12B 生成和审核代码，审核为独立上下文；为了配对，首次 Writer 的工具前缀是明确标注的固定回放，共用提交总结。它不是自然 Writer 会话的完整随机复现，不能外推到所有自我审核任务。

隐藏检查只在 agent 停止后由外部执行，未提供给 Writer、Reviewer 或修复提示。外部通过不能代替生产验证、审核及完成证明。

区分以下结果：

1. **可用缺陷反馈**：真实审核返回完整的 `changes_requested`，手工核对其确实指出目标缺陷。
2. **合格候选**：可见与隐藏检查通过、没有越出修改范围、agent 有当前源码的真实通过验证。
3. **完整交付**：在合格候选基础上正常结束，并有可信完成证明。
4. **误完成**：终端声称完成，但实际代码、范围或验证不合格。审核不可用单独记录，不当作审核批准。

## 结果

最终有 14 个有效配对、28 个比较臂；两次候选生成单独保留。

| 指标 | 当前 Codey | 参考借鉴版 |
|---|---:|---:|
| 固定错误候选的可用缺陷反馈 | 5/6 | 4/6 |
| 固定错误候选修复并完整交付 | 3/6 | 2/6 |
| 正确对照完整交付 | 6/6 | 6/6 |
| 正确对照首次阻断误拒绝 | 0/6 | 0/6 |
| 固定候选完整交付合计 | 9/12 | 8/12 |
| 自产候选的可用缺陷反馈 | 2/2 | 1/2 |
| 自产候选最终合格 | 2/2 | 0/2 |
| 自产候选完整交付 | 0/2 | 0/2 |
| 有效比较臂误完成 | 1 | 3 |
| 有效比较臂首次审核不可用 | 1 | 1 |

“可用缺陷反馈”是这组错误候选的判别结果，不是通用 finding-level precision/recall。

| 场景：完整交付 | 当前 Codey | 参考借鉴版 |
|---|---:|---:|
| 端点缺陷 | 2/2 | 2/2 |
| 端点正确对照 | 2/2 | 2/2 |
| 按键去重缺陷 | 1/2 | 0/2 |
| 按键去重正确对照 | 2/2 | 2/2 |
| 浅复制缺陷 | 0/2 | 0/2 |
| 深复制正确对照 | 2/2 | 2/2 |
| 12B 自产取整候选 | 0/2 | 0/2 |

有效比较臂的服务端累计输入与输出为：Codey **211,676 tokens**，借鉴版 **297,077 tokens**，增加 **40.3%**。使用统计完整；包括后续修复和再次审核，不含候选生成、无效试跑及脚本工具前缀。

正确对照六个臂合计为 8,855 与 59,886 tokens，借鉴版约为 **6.76 倍**。所有有效臂运行时间合计约 425.2 与 542.7 秒。输入计数可能包含服务端复用前缀，这不是付费账单或实时上下文占用。

两组有效比较中，参考版 `file_read` / `code_search` 调用均为 **0**。因此本轮没有验证“按需读取调用者”带来的收益。

## 失败分别来自哪里

### 模型判断与输出

**按键去重：**参考版两个种子均把整条字典比较当作性能问题，提出用 set 优化，而没有报告“同 id、不同 payload 被重复保留”的需求违反。建议代码还试图把字典放入 set，若直接采用会有不可哈希问题；该建议作为非阻断意见记录，没有应用。这是本轮可见的语义遗漏与建议质量问题。

Codey seed 51 指出按 id 去重的缺陷并修复。seed 52 的审核文字也识别出了缺陷，但在 JSON 字符串中输出了未转义换行；一次格式修复后仍失败，两个原始回复都能独立复现 `JSONDecodeError: Invalid control character`。这是“发现了问题，但反馈未能被消费”，不能记为有效反馈。

**复制：**两边均识别浅复制并修好了实现，但修复阶段修改了禁止修改的测试文件。最终分别因范围/审核适用性或轮次限制未完成。这说明审核发现率不能代替完整流程质量。

**真实自我审核：**Codey 两次识别自身生成候选中负数使用 floor 而非 ceiling 的错误，最终源码、范围和当前可见验证均合格。随后模型请求执行新的 `python -c` 探测命令，进入 shell 审批，headless 默认拒绝；两次均停止，未取得最终审核与完成证明。

参考版 seed 51 的首次工具意见耗尽输出长度，格式修复后仍无可用审核，原错误候选被完成；seed 52 正确指出缺陷，但修复前就请求额外探测并进入审批，候选未修好。这是审核协议、模型后续操作和生产命令策略共同影响的结果，不是单看 Reviewer 判断可以解决的问题。

### Codey 生产策略与确定性误判

当前首次审核不可用时可以继续部分正常完成路径。因此本轮 Codey 的去重 seed 52，以及参考版审核不可用的取整 seed 51，均出现可见测试通过、隐藏语义失败的完成。它没有把“不可用”变成 `approved`，但可见测试不足时，允许完成的策略仍无法保证语义正确。

新 shell 命令默认拒绝是现有权限策略，实验未绕过、放宽或自动批准。它造成部分正确补丁无法交付，但不能把停止补算成成功。

另外，原复制题的“Mutations in either copy must not change the other”被 [入口权限关键词规则](../codey/task/entry_auth.py:63)误判为全局禁止项目写入，候选没有安装，审核没有调用。这是可静态复现的生产权限逻辑缺口，和模型审核能力无关。此次只修改实验题表述为语义相同的正向表达，并在模型调用前检查题目确实授权候选编辑；生产权限规则未修改。

### 实验脚本问题及排除

- 试跑把非阻断建议也转成了阻断意见。测试先复现，再修正实验分类；整个试跑不用于质量结论。
- 原复制表述触发权限误判，八个比较臂没有真实审核。固定回放仍发出 done 所得的失败不代表模型审核失误；全部从审核统计排除，诊断保留。
- 初版适配器把格式修复消息包装成空 diff 的新审核。测试先复现，再改为保留原审核上下文并原样转发控制消息；受影响的两个自我审核配对整体排除，双方以原冻结候选各重新运行一次。

没有重跑有效的去重失败，没有改任务 oracle，没有换种子，没有反复采样到赢。排除原因与原始结果都在合并记录中。

## 哪些设计值得借鉴

**最值得单独测的是有界只读上下文工具。**Codey 已把原始任务与 Writer 总结分开，并提供验证证据、Project Map、Verification Map、Review Impact Map。OCR 可以进一步读取相关调用者和完整代码，适合摘要不足的跨文件问题；本轮调用次数为零，所以只能列为结构上有价值、尚未证明质量收益的能力。

**分类与结构化反馈值得保留，但要测试格式边界。**非阻断建议不能进入修复完成门；原始缺陷意见、截断状态、格式修复需要属于同一次审核。本轮适配器错误就是这条边界的反例。结构化工具可以减少自由 JSON 格式错误，但在本次预算下仍有截断和无效反馈，不能宣称已解决。

**规则适合短小聚焦，不宜直接复制整份 Python 检查清单。**这次组合的规则和工具模式显著增加输入，模型还多次输出不必要的性能建议。观察到注意力偏向性能检查，但不能仅靠捆绑 A/B 证明是哪一条规则造成遗漏；需要拆开变量验证。

**原项目的意见过滤没有作为收益计入。**它只删除被 diff 明确证伪的意见，默认保留不确定意见；并不负责剔除所有低价值建议。不能把它误用为“再让同一模型投票，所有猜测就变可靠”。

建议下一轮只比较“现有 Codey 审核”与“原提示保持不变，加有界读取和一种结构化提交”，加入确实需要读取调用者才能判断的缺陷与正确对照。先固定样本、指标、种子与预算。当前没有证据支持合入完整规则包、过滤链或另一套审核框架。

```powershell
python -m tests.manual.open_code_review_self_review_ab --run-dir artifacts/ocr-self-review-new-run
```

运行目录必须不存在。目录内先写预登记，再逐臂保存原请求/响应、源码、工具记录、审核结果、验证事实和完成证明。整个运行只支持 loopback。

验证：新增契约 **26 passed**；含相关审核与 observer 回归合计 **80 passed**。Ruff 通过，mypy 生产范围 **404 source files** 通过，Pyrefly 生产范围 **0 errors**；diff 与新增文件空白检查通过。未跑全量 pytest。

本轮未修改生产代码，未修改参考项目，未提交、未推送、未发布。实验脚本和本报告待提交。小样本、单模型、单机及有限任务族不能证明普遍泛化收益，也不能证明项目整体排名。
