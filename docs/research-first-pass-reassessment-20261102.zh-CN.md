# 首次知识积累：重启后的 WAL 补测与保留判断

日期：2026-11-02。基线 `020c302b`，新版 `d081266c`。结论是保留冷启动积累修复：在要求积累知识的 WAL 任务中，交付与可追溯候选事实的保存有明确收益；完整知识语义验收仍未通过，不能据此宣称研究推理能力提高。

本轮补齐此前因后端故障缺失的 WAL 对照。用户重启 KoboldCpp 后，八例均取得完整请求结果，没有 HTTP 卡死。旧版的两例积累任务是实际的 `no_progress`，不再是基础设施故障；此前两次后端故障仍保留原始分类。

使用同一个 Gemma4 12B 模型与 KoboldCpp 1.117.1、原 headless 入口、native tools、seed 74/75、temperature 0.3、top_p 0.9、最多 4096 输出 token、关闭 thinking，每例最多六次请求。两个版本使用逐字相同的固定官方选段、用户问题、阅读模式和预算，每例从空知识仓库启动。没有预读材料、预填计划、向模型提供标准答案或替换生产运行时。

基线在隔离工作树运行；两版分别冻结源码、驱动和材料指纹，最后一次推理后均复核通过。矩阵期间没有修改生产源码或提交。实测顺序为 A 积累 75、B 积累 75、B 积累 74、A 积累 74，然后分别运行 A、B 的两例普通对照。未把旧 Queue 成绩或此前失败的 WAL 请求混入本轮八例。

基线两例均读取到了正确原文，随后反复尝试通过 `knowledge_commit` 引用当前 `e1` 或尚不存在的 claim 身份。新材料此时没有数据库对象可供引用，修复后仍失败，六次请求结束时没有知识对象或正式答案。这证明这里存在任务交付的实际阻碍；没有最终答案不能计为模型所有事实都答错。

新版每例只读取一次、提交一次。重新打开仓库核对，每例各有一版 source、evidence、claim、inference、answer，属于同一发布事务；claim 指向精确 evidence，inference 指向 claim 与原始 evidence，跨会话按原措辞可以召回。保存的版本及 OR 条件有原文支持，正文保留 3.22.0、已有且可读的 shm/wal、可写目录以创建文件、immutable 三种替代条件。积累任务请求减少约 67%、输入 token 减少约 61%，两版完成程度不同，这些数值不代表同等成功任务的纯性能比较。

**知识语义存在独立缺陷。** 新版两条 inference 都主要复述原文的三项只读条件，更适合归为 claim，不能作为“已正确区分事实与推论”的证据。两条 claim 与两条 inference 的结构化 `conditions` 均为空，条件只保留在文本和依赖上下文中。本轮条件文本完整是 2/2，事实与推论的类型区分是 0/2；这两个指标不能合并成“知识正确率 2/2”。它们全部保持 candidate、unreviewed，没有自动升级为已验证结论。

此前某个 WAL 推论遗漏“可读”的失败记录也没有被本轮覆盖或删除。原先预登记的“四例知识内容全部合格”仍未达到；本轮没有宣称通过原完整语义验收。按原措辞召回也不能证明长期跨主题研究质量提升。

普通对照的答案和请求数没有退化，但新版输入 token 增加约 23%。因此，本次保留判断依据是具体积累任务从反复修复、无法交付，变为能交付答案并保存有据可查的候选事实。新增合同有持续成本，也没有表现出更强的独立推理能力。不能以程序能存储、能回滚、能召回替代知识内容审查。
