# Research：读过的资料保留，取消反复手工找回

**已接入生产。核心变化是：资料放得下，就继续给模型看；本任务真正读过、准确快照仍在的资料，可以引用，不再要求先手工找回。**

最终一批 24 次生产对照中，复杂题严格合格 **0/4 → 4/4**，请求 **18 → 4**；全部任务严格合格 **7/12 → 12/12**，总输入减少 **53.22%**。

程序仍拒绝编造的编号和没读过的证据。保存成功与正文正确分开记录。

## 1. 改了什么

原来的复杂路线：

> 读资料 → 原文被固定字符额度挤走 → 草稿带着旧引用 → 拒绝 → 模型抄编号找回 → 可能又挤走另一份 → 再提交。

现在的路线：

> 读资料 → 放得下的原文持续可见 → 直接回答 → 程序核对本任务的阅读记录和准确快照 → 保存。

具体处理如下：

| 部分 | 现在怎么处理 |
|---|---|
| 原文显示额度 | 取消原来的 18,000 字符上限，接入现有 provider 的 token 计数，原文工作区最多使用已确认窗口的一半，并受输入额度限制。整次请求仍经过完整预算检查。 |
| 放得下的资料 | 全部显示，包括背景，不再只留最近读的资料。 |
| 确实超过原文工作区额度 | 按完整阅读窗口移出较早的全文，保留稳定引用、已读范围和准确快照目录 `previously_read_snapshots`。移出显示不取消本任务的真实阅读资格。 |
| 整篇回答的手工回执找回 | 不再提供 `read_tool_result`，也不再要求先抄回执编号才能引用。普通网页继续用来源读取工具；固定知识版本继续用 `knowledge_read`。 |
| 过时的 `read_receipt_index` | 生产目录已没有这个名称。仍真实使用回执恢复的旧局部路径改用 `read_receipts`，其能力没有误删。旧对照和历史报告保留原名称以便核查。 |
| 没读过的材料、伪造引用、错误版本 | 仍拒绝。网页完整快照已存在，不等于模型读过尚未打开的尾部。 |
| 草稿、继续阅读、准确归档、原子保存和重启恢复 | 保留。不是把所有失败处理一起删除。 |

这没有增加一套新的模型操作流程。引用直接依据已经存在的真实阅读记录，不再让模型通过反复搬运来证明“刚才读过”。

## 2. 生产复测结果

这次新增两轮生产对照，共 **48 次 Gemma4 12B 实机运行**。下面只统计最后一批、最终代码的 **24 次**：六类任务，每类两个 seed（621、622），两版分别运行。第一轮单独保留在第 3 节及机器报告中，没有把成功样本挑出来合并。

“严格合格”要求整份正文、任务步骤和引用都正确；要求保存新候选的题，还实际核对数据库。对于“不继承额度”被说成“不继承许可”或范围更宽的“限制”，两版都记为严格不合格，不靠模糊措辞抬高分数。

| 场景 | 原版严格合格 | 最终版严格合格 | 请求：原版 → 最终版 | 总输入变化 |
|---|---:|---:|---:|---:|
| 多份长资料、已有完整草稿 | 0/2 | 2/2 | 6 → 2 | −62.91% |
| 多份长资料、先提交过错误引用 | 0/2 | 2/2 | 12 → 2 | −81.78% |
| 查旧资料、先遇到读取错误 | 2/2 | 2/2 | 6 → 6 | −4.24% |
| 普通研究并新增候选知识 | 2/2 | 2/2 | 4 → 4 | −4.34% |
| 简单草稿正式提交并新增候选知识 | 2/2 | 2/2 | 2 → 2 | −4.25% |
| 连续两次读错编号后恢复 | 1/2 | 2/2 | 7 → 4 | −44.65% |

**四次最终版复杂题都一次提交成功，正文也都严格合格，没有再手工找回原文。** 核对了两个版本的数字、ACTIVE 前提、只读支持、精确 tag、父子取消与 collect_errors、checkpoint 的停止/保存/恢复，以及回绕的 AND 条件。C1 的“不继承 local 额度”未再扩大成“与 license 无关”。

复杂题总输入 **120,486 → 29,569 token（−75.46%）**。原版保存两份，其中一份遗漏整份 C1 材料，另一份仍有“local 许可”的措辞问题，因此均未算严格合格；另两次触发止损。

| 全部任务指标 | 原版 | 最终版 |
|---|---:|---:|
| 正式保存答案 | 9/12 | 12/12 |
| 整份任务严格合格 | 7/12 | 12/12 |
| 模型生成请求 | 37 | 20 |
| 总输入 token | 196,868 | 92,092（−53.22%） |

实际请求检查确认，四个复杂题的首次实机输入都完整包含三份原文。原文工作区 **4,728～4,729 token**，小于半窗口上限 **16,384**；全部真实生成请求的最大输入是 **7,484 token**。完整用户问题保留，首次工具 schema 的差异仅为移除手工回执恢复工具。

所有正式保存的答案均核对了数据库正文、准确来源与证据版本、摘录和事务绑定；所有要求新增知识的成功运行都实际保存指定候选，未自动升格为已验证。最终版整条实际请求中也没有再出现过时目录或不可用恢复工具的指路。

第一轮与最终一轮复用了相同两个 seed 来检查修正，并非新增了四个独立 seed；同 seed 的原版运行也有波动。不能把最后这批全通过解释成长期正确率必为 100%。

## 3. 回测中发现的问题，也做了修正

第一轮生产对照共 24 次，证据保留在 `research-visible-evidence-production-20261103`。复杂题请求从 26 次降为 5 次，严格正文合格从 0/4 变为 3/4；但“连续读错编号、尚未读到原文”的两个新版运行都失败了。这个退步没有从统计中删掉。

检查真实输入后，查到两处提示不准确：

1. **实际上还没读过任何原文，提示却说“已读快照在下面”。** 现在明确说明尚未读取，并区分网页 URL 应用 `open_url`，知识 ID 才用 `knowledge_read`。
2. **完整工具结果中还夹着已不可用的找回工具说明。** 现在整篇回答不再追加这些说明，完整搜索结果、错误正文、来源 URL、命中位置仍照常提供。旧局部路径继续使用自己的有效恢复工具。

修正后，同两个 seed 都变为打开给定网页后直接提交，各两次请求；正文的版本与三个 OR 条件正确，指定候选知识也实际保存。随后完成最终代码的完整对照，而不是只保留两个成功样本。

两处一起调整，不能据此把所有失败都归因于某一句话；可以确认的是原提示与实际状态不符，修正后的这两个故障状态恢复了。第一轮的失败记录完整保留。

## 4. 程序检查

扩大回归覆盖 **234 个测试文件、2,933 项测试**，另有 **52 个 subtest** 通过。大批执行时是 **2,932 项通过、1 项失败**；唯一失败来自导航测试仍把当前提示与旧实验渲染器逐字比较，要求未读状态也说“已读快照在下面”。

该断言已修正为独立检查实际行为：未读状态准确、提供网页读取方向、已读原文完整、阅读位置不丢。没有修改生产代码或跳过测试；失败项与相邻导航、引用、内核、工具结果检查 **53 项复测全部通过**。这 53 项不重复加进 2,933 项，原失败日志保留。

静态检查全部通过：

- **全仓 Ruff**。
- **Mypy、Pyrefly、ty**，各自按 **Python 3.11、3.12、3.13** 目标检查完整 `codey`，共九项门禁通过。
- 本次 pytest 在当前 Windows 解释器执行；类型目标不冒充其他解释器或操作系统的实跑。

正式最终实机期间和最后测试修正后，**578 个生产 Python 文件的摘要均与冻结版本一致**。测试断言修正不改变已经跑过的生产版本；最终实机已逐例绑定正文摘要，并核对真实请求和数据库。

重点核对：

- 原文不再显示时，引用仍编译为当时真正读过的准确摘录；之后同 URL 内容变化也不替换旧证据。
- 失败读取、伪造编号、未读尾部不能获得新的引用资格；篡改原文或证据绑定仍拒绝。
- native/text 两种工具通道都能保存；恢复同一运行不重复发布。
- 请求准备、内核结算、发布提交三个位置中断进程后，重新启动仍只发布一次。
- 没读过原文时不暗示“已经读过”；整篇实际请求不再推荐不可用的恢复工具。
- 删除恢复说明后，网页搜索的结果编号、原文搜索的命中位置仍在；旧局部恢复仍可用。
- token 计数复用现有 provider 能力，本批实际使用后端 tokenizer；若该能力返回未知计数，这里会拒绝，不另加静默估计。没有该能力的原有适配器仍采用原文工作区的保守估计。

## 5. 这次没有证明什么

**没有证明模型再也不会写错条件，也没有证明每题都更省。** 前一轮 A/B 那份明确把“不继承 local 额度”说成“与 license 无关”的答案仍是不合格，记录没有修改。

本轮每类只有两个 seed，采用固定官方摘录和合成规则。复杂草稿、错误题先固定执行真实工具操作，再由实机模型接手；这些固定前缀不算模型请求。费用包含所有真实生成、失败和重试。

所有正式实机里的已读原文都能放进半窗口。真正超预算后不重贴全文的分支已做程序验证，本轮没有证明该压力下的模型理解同样可靠。这里采用的是具体局部收益，不宣称全部 Research 能力已经解决。
